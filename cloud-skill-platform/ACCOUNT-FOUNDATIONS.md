# 账号、会员积分与 Skill 广场基础版

更新：2026-09-28。仅完成本地开发和隔离验收，本轮不部署、不发布、不连接真实收款、不调用平台总 API。

后续邮箱登录接入：见 EMAIL-LOGIN.md。新增验证码登录及旧账号验证绑定；发件配置为神思 / shensiforge@qq.com，全站默认每日 1,000 次发信尝试硬上限。真实发信需服务器秘密配置与收件验收。

## 已实现

- 复用现有账号注册、登录、会话与密码哈希存储；用户可编辑笔名和头像。头像在客户端裁为 160×160 PNG，服务端限制格式、尺寸和大小。
- 桌面账户页从服务器读取会员状态、可用积分与任务预留积分。网络异常保留登录凭据，只有明确 401 才清除；缓存显示不作为授权依据。
- 云端 Skill 上传保留安全扫描和人工审核；作者不能审核自己的上传；同一 Skill ID 归属不可被其他用户冒用，相同版本不可覆盖。
- 登录并下载后的用户可以评分、评价；作者不能自评，每用户每 Skill 仅一条记录，修改后重新审核。仅公开评价参与总分，服务端决定作者身份。
- 后台可查看 Skill 原文、扫描证据、审核和下架；原文以纯文本展示，不执行其中指令。可审核评价、暂停用户、管理会员和积分、查看账本及审计日志。
- 审核员与会员管理员分权；会员变更有版本冲突检查，人工积分调账有幂等标识，调账与审计在同一事务内。
- 修复后台 /admin 缺少尾斜杠时脚本、样式加载路径错误；后台令牌仅保留在标签页会话中。

## 平台 API 额度边界

平台生成模块位于 lib/membership-core.mjs，默认没有模型、价格或执行适配器，因此始终关闭。支付配置也始终返回 paymentEnabled=false。

将来启用时，调用路径为：认证当前用户 → 校验会员和自身额度 → 原子预留 → 可信服务端适配器调用 → 校验用量回执 → 结算并退还未使用部分。

- 客户端不能指定 userId、价格、API key、端点、扣费金额或实际用量；旧客户端 reserve / settle / refund 入口明确拒绝。
- 请求幂等键按用户隔离，同键不同内容拒绝，同键同内容不会重复调用。每个用户只允许一个执行中或待核账的任务。
- 明确未计费失败才退款；超时、未知结果或异常用量保留预留额度进入 reconciliation_required，不自动重试。
- 不保存提示词原文，保存请求摘要及必要的任务结果。生产保留期和加密策略待制定。
- 账本 amount 表示可用余额变化；settle.amount=0，实际消费使用 settle.usedUnits，避免与 reserve/refund 重复计数。
- 人工会员 units 是累计授予的额度基数，调整只发放差额，不是月度发放、充值订单或自动续费。

## 数据和部署边界

- 密码沿用加盐 scrypt 哈希；管理员不能查看原密码。账号资料、会员、评价、账本由独立云端服务存储，不存入作品或供应商配置。
- 开发测试使用隔离 JSON 文件，写入失败保留旧状态；Windows 文件占用仅对原子替换作有上限重试。
- 现有 PostgreSQL 适配器仍是整份状态 JSONB 单行事务，不等于已完成生产级独立财务账本、分页和高并发验收。已补请求刷新与事务失败后的队列恢复。
- 没有改动即梦凭证锁、配置隔离、图片/视频提交轮询下载、对话生成与落盘、WorkBuddy、H3 或聚合 API。自带供应商配置不会被云端会员状态限制。
- 云端新接口未部署时，旧服务会提示暂不可用；不以此误判其他厂商账号失效。
