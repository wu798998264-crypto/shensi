## 实际修复

- 即梦冷启动先读取持久核验结果，不再因为界面缓存为空先弹核验窗口。
- 恢复旧认证失败任务时，对比其失败时间与后续核验时间，过时警告不再重复弹出。凭据确实缺失、明确失效、账号不匹配和重复绑定仍拦截。
- 账号面板读取按请求去重；短期重复打开设置复用观察结果；设置页缺失的 panel 引用已修正。
- 原生托盘菜单由 setContextMenu 处理，取消重复 right-click 弹出；不在无响应回调中同步重建 Windows Jump List。诊断日志改为异步写入。
- 产品内关闭按钮继续隐藏到托盘，原有退出入口保留；退出等待渲染器和后台结束都有截止时间。
- 修正上一轮单条待渲染记录覆盖其他卡片更新的问题，同帧多个卡片全部处理；需要结构刷新时合并一次重绘。
- 视口变化复用规范化节点和资产；节点内容、连线标记缓存复用。绘制期间保持已解码图片，减少缩放切换细节级别的白卡闪烁。
- 平移中接近预加载边界才更新可见卡片，不必等鼠标松开；封面队列不会被反复重绘无限重置。
- 图片卡片使用本地 640px 显示缓存，最多两项并发转换；原文件、生成引用、双击预览和图片编辑保留完整尺寸。缓存达到一定写入批次后清理旧缓存至约 512MB，不清理原始文件。
- 平移和缩放的撤销只保存视口参数，不再复制整板历史资产；撤销视图不会回退操作期间新生成的内容。
- 连续滚轮和拖拽期间后台 UI 准备主动让出；配置列表内容没变时保留 DOM；恢复输入焦点不抢走用户新选控件的焦点。
- 工作区已有更新缓存时不再等待较早预取，较早预取也不覆盖新缓存。磁盘冲突验证及正式保存仍保留。

## 冻结与退出

在独立 Electron 验收窗口中通过 Windows UI 点击产品内关闭按钮，观察到 visible=false 且后台仍在运行。随后在该窗口渲染器执行死循环，测试夹具调用已绑定的原生托盘菜单，收到 menu-will-show；现有退出回调在渲染器无法确认时仍完成退出，server 子进程正常退出且无残留。

这里确认的是实际原生菜单与退出路径在渲染器冻结时可运行；系统通知区图标没有暴露为可操作的独立窗口，因此没有声称完成 Windows 通知区物理右键坐标的端到端自动验收。退出不是新增功能，原有托盘菜单条目未增加。
