# 白板图片生成黄金基线二线（v2）

## 基线身份

- 基线名称：白板图片生成黄金基线二线
- 基线版本：v2
- 对应应用版本：神思 6.4.4
- Git 标签：`whiteboard-image-golden-baseline-v2`
- 真实验收日期：2026-09-20
- 验收入口：神思桌面端白板，不使用网页副本或绕过神思配置的供应商直连

本基线与《跨配置串行生图（受保护能力）》并列存在，不替代、削弱或删除原有严格全序列基线。原有基线继续保护完整的聚合 API 与即梦账号切换顺序；本基线专门保护用户在白板中实际点击生成时能看到、能判断、能恢复且最终能取得图片的完整交互链。

## 受保护的运行规则

1. 聚合 API 不是即梦凭证锁的一部分，可以与一个即梦配置同时生成；不得被即梦锁错误阻塞。
2. 不同即梦配置共用唯一凭证锁，必须严格串行。上一配置完成厂商任务、下载、图片校验和卡片回写后，才允许切换下一配置。
3. 同一即梦配置的任务按供应商真实能力提交；不得把本地持久化误显示为“本地排队，尚未提交厂商”。
4. 其他即梦配置占锁时立即提示真实占用配置，不创建本地排队任务。
5. 从用户点击生成开始，卡片左上角必须持续显示当前状态。允许的连续阶段包括“正在连接生成服务”“正在提交”“厂商排队中”“正在生成”“下载生成结果”“正在回写卡片”和“生成成功”。
6. 正在生成的真实任务不得因为旧任务恢复、取消记录、重复轮询或卡片重绘而隐藏状态。
7. 生成成功后状态继续保留，只有用户点击对应卡片才自动隐藏；程序不得在完成回写时自行清除成功状态。
8. 任何失败都必须在原卡片显示中文原因、收费风险和可执行入口，不得静默停止或只进入待处理区。
9. 明确失败、成功、中断完成以及确认未创建厂商任务的安全终态必须释放即梦锁。
10. 待处理区只收录确实阻碍后续生成、持续占锁或需要人工核对收费风险的异常任务；正常进行、成功和明确失败任务不得进入。
11. 结果只有在文件下载完成、格式与尺寸有效、文件大小和 SHA-256 回读一致、卡片回写复核通过后才算完成。
12. 不得修改、迁移、覆盖或输出用户现有供应商配置、端点、模型、API Key、Token 或即梦凭据。

## 2026-09-20 桌面端真实验收证据

同一白板内完成四个真实付费任务：

| 配置 | 模型/通道 | 结果 | 用时 | 产物验收 |
|---|---|---:|---:|---|
| 聚合api | GPT Image 2.5 | 成功 | 32 秒 | 1254×1254；PNG；大小与 SHA-256 回读一致；卡片回写通过 |
| 小鱼姐 | 即梦图片 5.0 | 成功 | 2 分 01 秒 | 2048×2048；PNG；大小与 SHA-256 回读一致；卡片回写通过 |
| 陈安 | 即梦图片 5.0 | 成功 | 2 分 30 秒 | 2048×2048；PNG；大小与 SHA-256 回读一致；卡片回写通过 |
| 她说剧有梗 | 即梦图片 5.0 | 成功 | 3 分 08 秒 | 2048×2048；PNG；大小与 SHA-256 回读一致；卡片回写通过 |

验收过程中聚合 API 与即梦任务可以并行；三个即梦配置严格按“小鱼姐 → 陈安 → 她说剧有梗”串行。每个即梦任务都取得真实厂商任务号，卡片状态从提交前准备持续显示到完成回写。四张成功卡片在验收结束时仍显示“生成成功”，即梦锁占用接口返回空列表。

“短剧最前线”继续按原受保护规则排除。未参与本次二线实测的配置不能借用本表结果宣称已经真实通过；其能力仍由原全序列基线和后续单独实测判定。
