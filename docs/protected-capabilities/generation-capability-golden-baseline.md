## A. 白板卡片生成

一次任务必须保持以下顺序：

```text
用户点击生成
→ 原卡片立即出现任务状态
→ 连接/提交/真实排队/生成/下载
→ 文件完整性校验
→ 正式保存
→ 磁盘与卡片回读复核
→ 任务完成
```

不可变规则：

1. 任务状态必须挂在发起任务的原卡片上，不能串到相邻卡片。
2. 有效结果一旦收到并完成落盘校验，不得被后续旧轮询、超时或旧状态降级为失败。
3. 回填阶段必须区分“正在保存”“正在回读”和“回填失败”；已经回读成功时只能显示完成。
4. 成功状态在用户点击对应卡片前保留；用户点击后才隐藏完成计时或状态。
5. 失败必须给出真实中文原因和可操作入口，不能静默结束。
6. 原任务恢复、取消、重新回填继续使用原任务身份与幂等键；用户明确要求新一轮生成时使用新的任务身份和幂等键，禁止盲目重复提交。

## B. 即梦凭证锁

1. 不同即梦配置共用唯一物理凭证槽，必须串行；聚合 API 不属于该锁。
2. 任务提交前不能把“本地已保存”误报为“厂商已受理”。
3. 锁冲突必须立即显示占用配置和任务，并可打开待处理列表。
4. 待处理列表必须显示真实卡片名称、任务状态、厂商任务号（若有）和强制解除入口。
5. 强制解除只能终止已验证的神思本机任务进程；只有锁探针确认释放后才能把本机锁标记为空闲。
6. 生成阶段的厂商会话异常不得伪装成“需要重新核验”；已经存在厂商任务号时必须保留原任务并进入可找回/可停止状态。
7. 已经持久化的有效账号身份、账号 ID、凭据指纹和成功生成证据不能因为一次启动探测失败、更新后缓存为空或短暂控制面失败而被清成未核验。

## C. 对话区生成

1. 用户指令提交后先出现任务卡，再进入后台准备；首阶段提示为“正在路由”。
2. 对话输出只显示面向用户的纯文本或正式结果，不显示 CLI JSON、Schema、工具参数、内部思考或失败协议。
3. 运行器、模型和媒体配置选择必须按任务身份绑定；切换配置时不能沿用上一个任务的上下文或结果。
4. 对话、文档和白板任务必须使用独立任务身份；一个任务失败不能把后续消息永久置为失败。
5. 用户选择问题或确认操作后，确认按钮必须一次生效；旧任务状态不能阻断新对话。
6. 对话消息、任务卡和正式落盘使用耐久提交；断电、重启、升级后不能丢失已提交对话。

## 变更门禁

任何修改只要触及以下范围，必须先取得用户明确授权，并在发布前重新跑本基线：

- 白板生成提交、轮询、下载、完整性校验、卡片回填或结果状态；
- 即梦凭证锁、账号隔离、配置切换、锁释放、任务恢复；
- 对话任务队列、任务卡、输出过滤、配置选择或耐久提交；
- 任何会改变 `src/server/dreamina-*`、媒体 worker/driver、对话 Agent 网关或上述对应 UI 状态机的修改。

只做渲染层性能优化时，也必须证明任务状态和生成操作栏没有被延迟、隐藏或重新归属。
