# Agent 运行模式改造完成记录

## 结论

本轮改造已经把普通对话收敛为统一 Agent 执行面。用户原始文字先完整进入 Agent，由 Agent 阅读任务路由文档、判断阶段、按需选择 Skill、读取实际需要的文档，再通过结构化工具执行选择、候选、媒体或正式文档操作。普通作品对话不再先经过关键词任务分类、固定文档预读或旧 Chat 编排。

旧 `/api/chat` 只为白板既有生成能力保留；任何非白板请求都会在进入旧编排前返回 `410 LEGACY_CONVERSATION_RUNTIME_RETIRED`。这是对白板受保护边界的兼容，不是仍可选择的 Chat 模式。

## 最终运行架构

### 1. 单一普通对话入口

- 输入框提交只调用 `sendMessage -> executeConversationAgentMessage -> /api/conversation-agent/start`。
- 原指令原样写入对话记录并交给 Agent，不先用媒体、创作、续写、覆盖等词做任务类型绑定。
- 历史恢复、长篇生成等仍调用旧名称 `requestModelReply` 的内部入口，但所有非白板调用会在函数开头转交统一 Agent。
- 同一对话保持有序队列；不同对话使用独立运行通道，可同时执行。
- 运行记录持久化；重启后未完成任务标为已中断，不会盲目重提生成。

### 2. 神思默认运行器

- 默认配置名称为“限免agent配置”，模型显示为“限免模型”。
- 内置运行器使用随安装包提供的 Codex `0.146.0`，以隔离工作目录运行。
- 模型只能调用神思暴露的动态工具；shell、任意文件系统和网络能力默认关闭。
- OpenCode、DeepSeek Agent、Claude Code 等外置运行器一旦被选择，会获得完整任务、任务路由文档和隔离的神思 MCP 工具入口，不回退 Chat，也不绕过神思作品事务。
- DeepSeek Agent 配置已去重并去掉无意义尾缀；旧独立“神思运行器”配置迁移为默认限免 Agent 配置，不再保留重复配置项。

### 3. 路由、资料和 Skill

- Agent 每轮都收到任务路由文档，由模型依据完整语义判断任务与阶段。
- Skill 目录只提供名称、说明和能力；Agent 决定需要时才读取具体 Skill。
- 创作引导阶段明确只使用对应创作指导 Skill；其他阶段按实际需要加载。
- 不调用文档工具时，不读取记忆、大纲、设定或其他空文档；“缺失”和“空白”不会自动成为无关任务的门禁。
- 经验板块和记忆检查板块完整保留，但不再作为每轮任务的强制前置手续。

### 4. 正式文档读写与历史

- Agent 通过 `documents.write` 明确传入 `create / replace / append / patch / rename`，工具不再根据用户措辞重新分类操作。
- 覆盖、续写/追加、局部替换的原有语义和写入规则保持不变。
- 对已有文档写入前必须先读取并绑定当前 revision；冲突时拒绝覆盖。
- 覆盖、续写/追加、局部替换正式生效前，事务层先保存目标文档修改前的完整版本；历史保存失败则正式写入失败。
- 新建、正式写入、候选采用、幂等恢复、作品隔离和白板禁止旁路均由可信事务层执行。
- 源码自修复 Agent 的文件权限也改为只认用户确认后的结构化任务合同；“继续执行已确认方案”不再因缺少“修改/保存”关键词而被降为只读，裸关键词也不能取得权限。

### 5. 动态选择与多候选

- 选择框只由 Agent 的 `interaction.ask` 结构化事件创建，不解析助手回复中的列表或关键词。
- 用户消息先落盘并显示，Agent 问题随后写入对话，最后才在输入区上方显示选择框。
- 支持单选、多选和自由输入；下方固定提示用户可直接发送其他想法。
- 多候选、候选分支、候选对比和“选用后安全写入”保留。
- 固定的“单主笔/多主笔/选谁主笔/每位几份”向导和状态机已经删除；数量和差异由用户自然语言描述，信息确实不足时由 Agent 动态提问。

### 6. 图片、视频和资产

- 对话 Agent 通过现有媒体任务服务生成图片或视频，不新建旁路供应商实现。
- 未指定配置时使用当前对应列表第一项；图片默认 `2K`，模型不支持时使用高清；视频默认 `720p`。
- 视频指令已含时长则直接执行，未含时长时只确认时长。
- 生成结果必须完成下载和验收后才自动写入“全部资产”。归档失败只重试归档，保留原厂商任务，不盲目重提付费请求。
- “聚合 API → 排除短剧最前线的即梦配置逐号串行生图 → 切回柏物语”受保护流程、凭证锁、账号隔离和切换顺序未改动。

### 7. 发布与隐私边界

- 安装包采用运行文件允许清单，测试、fixture、原始资料、备份、回收站、作品、笔记、缓存、日志、密钥、证书、数据库和打包产物一律拒绝。
- 打包后再次检查应用初始状态，阻止开发者作品、测试对话、候选、历史、资产、工作区路径或凭据随默认状态进入安装包。
- 生产能力包按审查过的 manifest 精确重建，reference-only 文件不会被自动接纳。

## 旧框架与关键词审计

审计结果如下：

- 普通对话可达路径不导入 `request-routing.js`、`agent-task-policy.js` 或旧媒体关键词路由。
- `sendMessage` 的普通分支只启动统一 Conversation Agent，不调用旧正文编排。
- Conversation Agent service、gateway、tools 和 bundled runtime 不依据用户文字关键词决定是否读写。
- 文档写入权来自 Agent 工具调用中的明确 `operation`、当前 revision、幂等 ID 和事务授权。
- 源码 Agent 的读写权来自结构化 route contract，不再扫描“修改、保存、读取”等词。
- `/api/chat` 对非白板请求返回 410；白板继续使用原有隔离执行面。
- 代码中仍保留白板所需的旧编排实现、历史数据迁移别名和少量旧字段名。它们不构成普通任务的可选运行模式；删除它们会改变本轮明确要求保留的白板或历史兼容能力。

因此，普通作品任务已经彻底舍弃旧运行框架和关键词读写判断；唯一保留的旧编排运行边界是明确受保护的白板生成。

## 效果与边界

相较旧版本，本轮的质变不是增加更多关键词，而是把“软件先猜任务并设置门禁”改成“Agent 理解完整任务并主动选择受控工具”。这使自然语言任务、连续补充、按需资料读取、动态 Skill、动态选项、多候选和跨运行器执行成为同一套机制，新增任务类型通常不再需要增加一组前端正则和固定流程。

仍需保留的确定性规则包括：作品隔离、revision 冲突、完整历史、幂等写入、付费媒体任务防重提、受保护跨账号串行生图、白板隔离和发布隐私允许清单。这些是数据与付费安全边界，不是语义理解门禁。

神思运行器现在具备接近 Codex 的自主规划、按需读取、工具循环和追问能力，但最终智能上限仍受所选模型能力、上下文窗口、模型服务稳定性和动态工具协议支持影响。限免模型可直接使用内置运行器，不要求用户另装本地 Agent；外置 Agent 则仍依赖对应 CLI 与有效配置。
