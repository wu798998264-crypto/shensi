# 小说原型设计

## 定位

本 skill 是原型主笔辅助入口，用于快速把一个脑洞扩展为人物、设定、大纲、标题、样章和写作计划。适合 10-50 章的中短篇或正式长篇立项前的原型验证。

## 适用场景

- 新项目、新脑洞、新世界观、新人物和新力量体系的初版设定。
- 第一章、样章、多方向试写和故事原型验证。
- 轻量大纲、人物档案、标题和章节计划。
- 正式长篇立项前，用于判断故事是否能跑起来。

## 自包含主流程

本 Skill 的执行合同已经固化在应用能力包中，不读取外部原始资料、脚本或用户目录。

1. 初始化：确认最终产物、预计体量、目标读者、题材边界、叙事视角、基调和用户不可改要求。
2. 核心定位：用一句话锁定“谁因为什么必须做什么，否则失去什么”，再给出主卖点、核心矛盾和差异化限制。
3. 候选竞争：至少提出两条不同的故事发动路径，比较人物压力、冲突续航、升级空间、情绪回报和完本难度，只保留最能持续制造选择代价的一条。
4. 人物与世界：先定义欲望、恐惧、误判、能力代价和关系张力，再补充只会影响剧情选择的世界规则；设定不能脱离事件单独堆砌。
5. 结构规划：建立开局承诺、阶段目标、中段不可逆变化、高潮选择和结局兑现；10—50 章原型至少标出每个阶段的状态变化、信息台阶和追读问题。
6. 标题与简介：标题体现题材、冲突或独特机制，简介交代人物困境、差异化变量和最大悬念，不用空泛形容词替代故事。
7. 样章试写：实际读取并执行 [[神思-开场钩子与时间叙述控制规则]]；根据人物问题选一个主钩，必要时最多一个辅钩，章节必须有具体目标、阻力、变化与章尾余波。对白服务人物立场和关系变化，不用解释设定或时间流水账代替冲突。
8. 原型校验：检查卖点是否进入事件、主角是否主动选择、对手是否持续施压、规则是否产生代价、阶段是否可升级、结局是否能够回收开局承诺。

## 固定输出

- 核心故事句与读者承诺。
- 主角、主要关系、对手压力和关键世界规则。
- 候选方案比较与选定理由。
- 阶段大纲或章纲；规模由用户目标决定。
- 样章目标、场景链、钩子和风险清单。
- 进入正式项目时需要确认、入库或继续验证的事项。

## 边界

- 本 skill 负责原型草案，不直接接管正式长篇 canon。
- 一旦作品进入正式结构化管理，事实源以作品文件夹中的 `02_正史设定/`、`01_剧情控制/`、`03_状态快照/`、`04_正文/` 和 `09_索引/` 为准。
- 原型设定进入正式作品前，由 Agent 结合 [[神思-记忆检查规则]] 区分已确认、待确认与草案，并按 [[神思-大纲与章纲规则]] 判断接入方式；需要正式入库时调用 [[小说结构化文档管理]]。
