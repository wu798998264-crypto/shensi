# 神思使用者说明书

状态：正式说明，双核版。

定位：说明使用者如何驾驭 [[神思]]、[[创作引导]]、创作核与记忆核。本文不是任务路由、正文规则或 canon 来源。

## 一句话定位

使用者负责方向、审美、边界和最终取舍；创作引导负责理解并沉淀这些判断；创作核负责把效果做到上限；记忆核负责让长篇不崩。

固定优先级：

```text
作品效果 > 长篇稳定 > 批量产能
```

## 双核协作关系

```text
你提出想法、反馈或命令
-> 创作引导整理创作意图状态
-> 记忆核编译动态创作胶囊
-> 创作核模拟人物、比较方案并生成
-> 创作核检查效果
-> 记忆核检查硬冲突并提取增量
-> 交付或回写
```

双核是两个后台执行核心。[[创作引导]] 仍然保留，而且是你日常最主要的入口。

## 你可以怎样使用创作引导

你可以直接说：

```text
用创作引导模式和我聊聊。
我现在一点头绪都没有。
我有几段零散想法，你帮我理顺。
这一章不对味，但我说不清哪里不对。
给我三个差异明显的方向，我用数字选。
```

创作引导保留逐轮提问和数字选项，但不会每次从头问题材、主角和目标。它会复用已经确认的：

- 想要的读者反应。
- 不想滑向的套路。
- 认可的节奏、场面和语言。
- 明确讨厌的表达与处理方式。
- 什么算通过、小修或打回。

普通细节由双核自动推进。只有重大 canon、主角命运、重要角色生死、核心真相、结局、重大关系转向或明确禁区出现分叉时，创作引导才暂停询问。

## 创作意图状态

创作引导会在后台维护：

```text
已确认方向
已确认边界
验收标准
已确认取舍
正例
反例
临时倾向
仍待确认的重大分叉
```

它属于协作偏好，不属于故事 canon。系统不会因为你某次随口说“可以”就永久改写作品方向，也不会把审美意见写进世界观正史。

## 创作核强在哪里

创作核不满足于得到一个“能写”的方案。高价值节点会内部构造至少三种差异明显的走法：

1. 最符合人物本能的走法。
2. 情绪、爽感、压迫或悬念最强的走法。
3. 最意外但已有因果能够支撑的走法。

它会先淘汰依赖降智、巧合、强行解释、人物突变和提前泄密的方案，再按人物合理性、目标情绪、场景具体度、新鲜度、长线价值和追读力选出最强方案。

内部推演不会变成冗长报告。你通常只看到最终内容；需要拍板时才看到简短的方案差异和风险。

## 记忆核强在哪里

记忆核在写前只抽取本轮真正需要的资料：

- 当前目标与阶段位置。
- 最近必要正文和未完成后果。
- 相关人物的欲望、恐惧、误判、底线和关系位置。
- 必须遵守的 canon、因果、时间地点和资源限制。
- 读者已知、可疑、误判和必须未知的信息。
- 未兑现承诺、伏笔压力和情绪债。
- 本轮相关的正例、反例和禁区。

写后，它记录人物选择、关系变化、情绪债、伏笔、读者知识和下一章必须承接的内容。多章连续生成时，下一章读取上一章实际形成的记忆增量，而不是只照初始大纲机械前进。

记忆核只阻止硬冲突，不会因为“资料里以前没写过”就封死合理的新细节。

## 你不需要做什么

- 不需要自己调度几十份 skill 和规则。
- 不需要每章填写完整合同。
- 不需要每章重新说明已经确认的口味。
- 不需要人工维护所有人物状态、伏笔和信息差。
- 不需要等待系统展示完整推理过程。
- 不需要因为正式写作而默认启用 webnovel-writer、commit 或 projection。
- 不需要用一堆评分表代替审美判断。

## 你仍需负责什么

| 职责 | 你要判断什么 | 神思负责什么 |
|---|---|---|
| 方向 | 为什么写、写给谁、最想让读者有什么反应。 | 给候选、分析风险、沉淀意图。 |
| 边界 | 哪些不能写、不能提前说、不能滑向什么套路。 | 编译进动态胶囊并持续检查。 |
| 审美 | 哪些场面、语言和节奏真正对味。 | 从正例与反例中提取可执行取向。 |
| canon | 哪些设定、关系和主线事实正式成立。 | 标注状态、检查冲突、按授权入库。 |
| 取舍 | 多个好方案中保留、删除或延后哪个。 | 做候选竞争并给出最小必要差异。 |
| 验收 | 当前版本通过、小修还是打回。 | 定位问题属于方向、方案、正文、记忆还是章纲。 |

## 最小输入

方向已经稳定时，你可以只说：

```text
继续写第N章。
本章最重要的是：
必须承接：
不要写成：
结尾希望读者等什么：
```

甚至只说“继续”，系统也应先从现有创作意图、最近正文和记忆状态自动补齐。只有重大缺口无法判断时才问一个关键问题。

## 单章协作流

```text
读取你的要求和已确认口味
-> 记忆核生成动态创作胶囊
-> 创作核在高价值节点比较方案
-> 写正文
-> 检查人物、情绪、场景变化和章尾
-> 检查 canon、因果、信息权限和关系变化
-> 局部问题定向返修
-> 生成记忆增量
```

普通章节不会额外向你展示胶囊、评分表和回执。你要求查看、出现质量争议或准备入库时，系统再提供简版依据。

## 多章连续生产

一次要求多章正式正文时，神思仍逐章保证连续性，但不要求你逐章点击确认：

```text
第N章完成
-> 生成第N章记忆增量
-> 自动编译第N+1章胶囊
-> 继续生成
```

如果中途出现会改变主角命运、核心真相、结局、重大关系或已确认 canon 的分叉，创作引导会停下来让你拍板。其余问题系统自己解决。

## 三种审稿决策

| 决策 | 适用情况 | 后续动作 |
|---|---|---|
| 通过 | 效果成立，记忆核无硬冲突。 | 定稿并按授权回写。 |
| 小修 | 核心结构成立，局部反应、语言、场面或章尾不足。 | 做最小定向返修，不重跑全流程。 |
| 打回 | 方向、人物驱动、章节功能、因果或信息权限失败。 | 返回创作引导、候选竞争或章纲。 |

## 资料建议

正式长篇可以逐步准备，不要求开篇一次性填满：

| 资料 | 用途 |
|---|---|
| 商业与审美总纲 | 目标读者、核心体验、正例、反例和禁区。 |
| 全集大纲、卷纲和近期章纲 | 控制长期承诺与阶段目标。 |
| 人物和关系状态 | 欲望、底线、误判、知情边界与关系位置。 |
| 信息释放与读者知识 | 控制秘密、显影、误判和揭示。 |
| 章节记忆 | 保存每章实际发生的选择、后果和未兑现内容。 |
| 正文 | 唯一可信的已发生场面来源。 |

具体路径和 canon 状态按 [[神思-结构化管理规则]] 执行。

## 兼容运行时

[[神思-本章创作合同模板]]、[[神思-webnovel-writer运行边界规则]] 和 [[神思-webnovel同步适配规则]] 继续保留，但只在用户明确要求、作品已经依赖或外部运行时真实可用时启用。

未启用时，神思原生双核可以直接完成正式正文；不要求外部 reviewer、chapter-commit 或 projection。

## 最终边界

最佳协作关系是：

```text
你提供方向、标准、边界和取舍。
创作引导理解你。
创作核把效果做到上限。
记忆核让作品持续成立。
结构管理只把已确认事实写入正确位置。
```
