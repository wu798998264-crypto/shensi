# 神思创作引擎

状态：正式生效，唯一总控入口。

## 触发条件

[[神思|神思创作引擎]]，简称“神思”。凡是涉及小说、短剧、剧本、漫剧、人物、设定、大纲、正文、改稿、续写、自检、入库、结构化管理、公众号内容、视频提示词、图片资产、人物站位或其他创作任务，必须先进入本文。

只有用户明确说“不要使用神思”“跳过神思框架”“自由发挥”或“只闲聊，不执行框架”时，才允许跳过。

所有中文规则统一按 UTF-8 读取。默认不读取 `_备份_不参与规则扫描/`、`原始资料/`、`废弃设定/`、乱码隔离文件和未被当前任务命中的理论资料。

## 一句话定位

神思负责把用户的方向、审美和取舍转化为高质量产物，并让长篇状态可以持续承接。默认运行时是 [[神思-双核运行规则]]：[[神思-创作核运行卡]] 负责效果上限，[[神思-记忆核运行卡]] 负责连续性与状态，[[神思-正文质量净增益与防退化规则]] 作为隐藏底层裁决保护内容唯一性和修改净增益，[[创作引导]] 负责用户可见的总编协作。

固定优先级：

```text
作品效果 > 长篇稳定 > 批量产能
```

## 总控硬闸门

1. 无目标和必要上下文，不进入正式生产。
2. 无输出模式，不把产物冒充正式交付。
3. 无 canon 状态，不写入正式事实库。
4. 无对应专项模块，不执行受格式或媒介约束的产物。
5. 记忆核发现未处理硬冲突，不标记正式完成。

普通细节缺失不构成停工理由。系统应先判断用户要求的最终产物，再根据对应专项的最小创作合同决定是否需要引导。小说使用 [[创作引导]]，公众号、剧情短视频、短篇小说和提示词分别使用 [[推文创作引导]]、[[短视频创作引导]]、[[短篇小说创作引导]]、[[提示词创作引导]]；该判断不受作品模式、笔记模式或当前打开文档限制。

“每轮只问一个问题”只限制单轮认知负担，不代表整次引导只能询问一轮。只有专项引导规定的必需决策簇已经由用户确认或明确委托系统、看点增强已经讨论、最终创作合同已经确认时，才算信息充分并进入正式主笔。只有主题、题材、单个风格词、一个画面或一段素材，不得判定为信息充分。每轮回答都必须合并进创作合同状态，已确认内容不得重复询问；用户说“你决定”“按你的推荐”时，将该项记录为授权委托，并由系统给出明确取舍，不能把缺口静默留空。

用户明确说“直接写”“直接生成”“不要追问”“全自动”“按现有信息写”时，立即停止用户可见追问，以当前信息建立临时创作合同并执行；该指令只跳过询问，不跳过专项主笔、效果检查、格式门禁、连续性检查或事务边界。

## 默认双核链路

```text
神思裁决任务、输出模式与 canon 状态
-> 对应专项引导读取已有创作意图；仅在关键缺口存在时补齐
-> 记忆核编译动态创作胶囊
-> 创作核进行候选竞争并生成
-> 创作核效果复核
-> 内容唯一性与质量守恒检查
-> 记忆核硬冲突检查与记忆增量
-> 必要时一次定向返修
-> 交付或按授权入库
```

候选竞争、人物心智模拟和读者效果推演优先消耗强模型算力。完整评分表、语言病灶库、商业理论、结构化执行手册和兼容运行时 artifact 默认留在写后或专项触发阶段。

## 极简读取组织

日常运行最多分三层：

1. 总控层：读取 [[神思]] 与 [[神思-双核运行规则]]。
2. 双核层：记忆核编译胶囊，创作核执行当前任务；质量净增益规则以轻量任务卡隐式裁决，不向起草上下文灌入完整检查表。
3. 专项层：只读取当前最终交付物命中的一个主模块；出现明确专项风险时再追加一份对应规则。

硬规则：文件可以多，运行路径必须短。不得扫描式加载所有活动规则，不得为了“保险”把完整自检清单塞进起草上下文。

复杂度按 [[神思-分级闭环与规则包规则]] 分层：轻链处理低风险试写和局部修改，标准链处理正式承接产物，强闭环只用于多章/多集、满血终稿、顶级目标、重大 canon 或跨媒介生产链。不得把强闭环变成所有创作任务的默认负担。

## 输出模式

| 输出模式 | 适用场景 | 完成标准 |
|---|---|---|
| 正式交付 | 正式正文、剧本、大纲、设定、提示词或视觉资产。 | 创作核效果复核、内容唯一性和质量守恒通过，记忆核无未处理硬冲突；需要入库时 canon 与路径明确。 |
| 压缩初稿 | 用户明确要求章节草稿、剧情草稿、批量试作。 | 信息与因果完整，不冒充可发布终稿。 |
| 结构草案 | 新项目、脑洞、设定或大纲试作。 | 标注草案或待确认，不覆盖正式 canon。 |
| 诊断审查 | 框架、质量、命名、格式、结构或文本问题分析。 | 输出证据、判断和最小可执行建议，不强制回写。 |

用户一次要求多章正式正文时，不因数量自动降级。双核按章节顺序循环，每章生成后先提取记忆增量，再编译下一章胶囊；普通章节无需等待用户逐章确认。

## 执行强度

| 强度 | 默认场景 | 运行方式 |
|---|---|---|
| 快速试写 | 找感觉、验证脑洞、试片段。 | 最小胶囊、直接生成、基础效果与硬冲突检查，不入正式 canon。 |
| 标准正式 | 正式正文、章纲、设定、剧本和后续要承接的产物。 | 双核完整短链、必要专项规则、记忆增量或结构化更新包。 |
| 满血终稿 | 用户明确要求终稿、投稿前、发布前、全量验收或重大质量争议。 | 标准正式链后再加载对应完整自检、商业或语言质量矩阵。 |

标准正式是默认。满血终稿不得反向成为普通起草的默认负担。

## canon 状态

| 状态 | 允许位置 | 规则 |
|---|---|---|
| 已确认 canon | `01_剧情控制/`、`02_正史设定/`、`03_状态快照/`、正式正文及其后台连续性增量 | 只能来自用户确认、已确认正文或明确授权。 |
| 待确认 canon | 对应作品的待确认事项、待确认更新或临时更新包。 | 可供参考，不得覆盖正式设定。 |
| 草案 canon | 候选稿、临时草案包、待确认事项，或按需创建的 `08_资料库/备选方案/` | 新项目试作和 AI 首轮生成默认不落盘；仅在用户明确要求长期保留多套并行方案时创建备选方案。 |
| 废弃/冲突 | `08_资料库/废弃设定/` 或待确认事项。 | 保留来源和处理原因。 |
| 不涉及 canon | 诊断、格式、任务分工和纯工具产物。 | 不写入正史。 |

创作意图状态不是 canon。用户的风格偏好、正例、反例和验收标准由 [[创作引导]] 维护，只约束协作与审美。

## 姓名去污染

涉及原创人物命名、新项目主角卡或正文中新登场且尚未命名的人物时，按需读取 [[神思-命名去污染规则]]。已有资料、正文或正式 canon 明确的姓名必须承接，不得擅自改名。

| 公众号长文、推文、类型化创作、正文配图和去 AI 味 | [[公众号模块]]；先由 [[公众号文章创作理论]] 识别内容方向，再按需加载细分理论；明确要求正文配图时，在成稿后加载 [[skill/神思/公众号文章创作理论/ian-xiaohei-illustrations/SKILL|Ian 小黑正文配图 Skill]] |

开放 Skill 的替换单位、可信内核、自检协议、能力缺失补位和失败回退统一服从 [[神思-Skill开放平台规则]]。用户 Skill 只能进入被授权的创作能力槽，不得通过 `@Skill` 覆盖任务路由、上下文编译、权威连续性与格式门禁、记忆、结构化落盘、版本或安全。

## 兼容适配

[[神思-webnovel-writer运行边界规则]]、[[神思-webnovel同步适配规则]] 和 [[神思-本章创作合同模板]] 继续保留，但只在用户明确要求、作品已接入或外部运行时真实可用时启用。

未启用时，不要求 reviewer artifact、chapter-commit、projection 或第二套提交链。缺少这些外部产物不影响神思原生双核完成判定。

## 结构链接

具体作品中复用的 `伏笔总表`、`信息释放表`、`读者当前知识库`、`更新日志`、`待确认事项`、`术语表` 和 `世界观` 等同名文档，必须使用完整路径加显示别名的 wikilink。人物、地点、章节和作品内唯一实体可以使用短 wikilink。

## 执行回执

正式生产内部只保留短回执：

```text
神思双核回执
- 任务与输出模式：
- 创作意图来源：
- 动态创作胶囊：已编译 / 临时编译
- 创作核结果：通过 / 定向返修 / 打回方向
- 质量守恒：通过 / 已回退退化修改 / 需人工裁决
- 记忆核结果：无硬冲突 / 已修复 / 待确认
- 记忆增量或待回写：
- 兼容适配层：未启用 / 已启用
```

回执默认内部完成。用户要求查看、任务涉及正式入库、批量连续生产、质量争议或框架诊断时，再附简版；不得让回执正文挤占创作产物。
