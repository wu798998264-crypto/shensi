# 给 AI 的使用提示

当用户要求“为小说建立资料库”“整理小说结构”“根据正文更新角色/事件/时间线/设定”“维护长篇小说设定”时，按本 skill 执行。

当用户要求生成“全集大纲”“全书大纲”“总纲”“分卷大纲”时，本 skill 只负责确定文件结构、模板和入库位置；正式长篇的全集大纲内容应由规划主笔生成，并写入 `01_剧情控制/全集大纲.md`。

当用户要求生成“细纲”“分集细纲”“章纲”“详细大纲”时，本 Skill 负责确定文件结构、模板和入库位置；Agent 从实时面板选择规划 Skill，并在本轮确需承接时调用 [[神思-记忆检查规则]] 检查既有 canon、人物状态和旧承诺，再写入 `01_剧情控制/章纲/`。小说不再新建或维护 `01_剧情控制/分集细纲/`；所谓“分集细纲”转译为单章章纲或卷纲/阶段规划。

## 必须遵守

- 每部作品一个作品文件夹。
- 正文只放在 `04_正文/` 文件夹。
- 小说正文分卷放入 `04_正文/小说/`；短剧、视频提示词、图片资产提示词和站位线稿图放入 `04_正文/短剧/` 对应子目录。
- 预计外文档不得放在作品根目录；`当前正式可用章节.md`、`当前分卷结构.md` 等创作者查阅型辅助视图放入 `10_其他/`。
- `07_编译报告/` 只维护 `小说自检.md` 和 `剧本自检.md` 两个聚合报告；连续性检查、商业追读评分、短剧逐集自检等写入对应聚合报告，不新建无限细分目录。
- `01_剧情控制/` 保存全集大纲、卷纲、章纲、伏笔管理、信息释放和章节目标队列；不再保存小说分集细纲。
- 事件统一写入 `02_正史设定/事件.md` 的分节；时间线统一写入 `02_正史设定/时间线.md`。
- `01_剧情控制/全集大纲.md`、`01_剧情控制/卷纲/`、`01_剧情控制/章纲/`、`08_资料库/` 默认锁定，除非用户明确要求，不根据正文自动修改。
- `02_正史设定/` 与 `09_索引/` 可根据正文自动追加；正史默认按“分类聚合板 + 实体标题锚点”维护，不得为单个人物、地点、物品、势力、概念、规则或事件建立原子文档，除非用户明确要求且该实体已达到长期独立维护规模。
- 用户只要求读取单个实体时，直接按实体标题、锚点或稳定 ID 截取聚合板分节；禁止把“单实体读取”误判成“必须建立单实体文件”。
- 用户要求完整当前档案时，临时组合“正史分节 + 当前状态块 + 直接相关关系/信息/伏笔/必要记忆”，形成不落盘的虚拟档案；读取清单必须说明实际来源。
- 不确定或冲突的信息写入 `09_索引/待确认事项.md`。
- 所有从正文提取的新事实必须标注来源章节。
- 用户提供的原始详细设定文档保留在 `08_资料库/`，只作为来源和审计底稿，不作为正文写作时的设定入口。
- 如果用户已经提供详细设定文档，聚合板中的实体分节必须优先迁移/整理原文对应段落，不能只保留一句摘要。
- 暂时无法完整迁移原文细节时，在对应实体分节标注“待补全来源段落”，并写入 `09_索引/待确认事项.md`。
- 管理流程只按标题、关键词、来源位置做搬运、归档和链接修复；人物分类、事件分类、复杂归类取舍等价值判断交给规划主笔、原型主笔或类型研究顾问。
- 旧 `分集细纲/` 中仍有价值的单章内容，必须迁入 `01_剧情控制/章纲/` 的单章文件；后续不再维护 `分集细纲/` 作为阶段总控，阶段总控改由卷纲、阶段规划或章纲目录总览承担。
- 细纲入库必须达到“可写正文”的颗粒度：每章明确主任务、叙事模式、关键场景或必要压缩段、因果/关系/信息变化、伏笔状态、结束功能和本章禁区。行动章写清连续动作链；余波、关系、转场和收束章按任务写清有效过程，不强迫统一章尾钩子。只有章节标题、目标和一句结尾提示的内容属于目录级，不得视为合格细纲。
- 分类设定必须优先维护在 `人物设定.md`、`人物关系.md`、`物品设定.md`、`势力设定.md`、`地图设定.md`、`力量体系.md`、`规则设定.md`、`概念设定.md`、`特殊设定.md`、`基础设定.md`、`衍生设定.md`、`事件.md` 等聚合板中，并使用二级标题和稳定 ID 召回。
- 独立建档只用于用户明确要求，或实体已经同时具备独立版本周期、大量专属子结构、聚合板难以稳定维护和长期高频维护需求的情况；独立化后聚合板只保留摘要、链接和迁出理由，不保留重复正文。
- 作品文件夹中不再创建 `02_正史设定/素材库.md`；素材、灵感、参考片段和外部资料优先放入 `08_资料库/`。

## 写作自检选择

每次写作、改稿、审稿前，先判断需求选择自检版本：

- 使用 [[强剧情自检]]：开局、样章、前三章、核心卖点、强商业钩子、需要强反转/强压迫/强追读的章节。
- 使用 [[常规推进自检]]：正式连载中的常规推进、信息沉淀、关系推进、过渡章、后果消化章。

选择规则：

- 用户明确要“强剧情、强钩子、强反转、爆点、追读”，用强剧情版。
- 用户明确要“自然推进、别太用力、稳一点、日常推进、关系推进”，用常规推进版。
- 用户没有指定时，开局和样章默认强剧情版；正式连载中段默认常规推进版。

两个版本都必须检查“下一章期待感”：结尾是否留下新问题、新压力、新选择、新后果、新承诺或新信息缺口。

## 更新正文后需要检查
- 每次正文撰写、续写、改写或批量生成后，必须同步维护随正文保存的后台连续性增量、人物状态、伏笔管理、信息释放表、章节目标队列；未建档作品输出临时结构化更新包。
- 续写前如果没有有效后台连续性增量和状态快照，必须先从最近正文临时提取承接信息，再由运行时编译本轮动态上下文；不得创建上下文包文档。

- 是否出现新角色、别名、身份、关系、目标、状态变化。
- 是否出现新地点、组织、势力、历史、社会规则、技术、魔法或超自然规则。
- 是否出现关键事件、承诺、冲突、死亡、交易、发现、转折，并补入 `02_正史设定/事件.md`。
- 是否出现明确时间、相对时间、期限、年龄、旅行时间，并补入 `02_正史设定/时间线.md`。
- 是否出现术语、物品、能力、制度、禁忌、规则限制。
- 是否出现新伏笔、已回收伏笔、被遗忘伏笔。
- 本章是否使用了正确的自检版本。
- 新增人物、物品、势力、地点、规则、概念、力量体系、特殊机制、基础设定、种族设定、衍生设定、重要事件或时间线记录时，是否已写入对应聚合板的实体分节，并避免创建原子文件。

## 冲突处理

不要直接覆盖旧资料。使用这个格式写入 `09_索引/待确认事项.md`：

```markdown
| 问题 | 来源A | 来源B | 建议处理 |
|---|---|---|---|
| 新正文与旧设定冲突的说明 | `旧资料链接或完整路径别名` | `作品/作品名/04_正文/章节|正文/章节` | 请作者确认以哪个为准 |
```
