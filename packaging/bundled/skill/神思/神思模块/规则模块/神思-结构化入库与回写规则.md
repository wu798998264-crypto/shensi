# 神思-结构化入库与回写规则

状态：正式生效。

用途：规定结构化入库、正文写后回写、设定更新、待确认和三档闭环。

## canon 入库边界

| 内容状态 | 位置 | 是否可当 canon |
|---|---|---|
| 用户确认、已确认正文、明确授权入库 | `01_剧情控制/`、`02_正史设定/`、`03_状态快照/`、正式正文及其后台连续性增量 | 是 |
| 未确认、冲突、试作、理论建议、正文反推核心事实 | `09_索引/待确认事项.md`、临时结构化更新包 | 否 |
| 新项目试作、AI 首轮生成 | 候选稿、临时草案包或 `09_索引/待确认事项.md` | 否；默认不自动落盘。 |
| 用户明确要求长期保留的并行方案 | 按需创建的 `08_资料库/备选方案/` | 否 |
| 废弃方案 | `08_资料库/废弃设定/` | 否 |

## 闭环分档

| 档位 | 适用场景 | 输出 |
|---|---|---|
| 轻量诊断 | 框架审查、质量诊断、临时讨论、非入库改稿 | 诊断结论、风险、待回写清单。 |
| 正式生产 | 正式正文、正式章纲、正式设定、正式剧本、正式提示词 | 结构化更新包和自检结果。 |
| 入库维护 | 用户要求建档、入库、同步、回写、编译报告、批量连续生产 | 完整路径写入、更新日志、待确认事项维护。 |

## 小说正文目录入库

小说正文属于作品表达层主产物，默认写入 `04_正文/小说/`。长篇按卷管理时，卷目录必须位于 `04_正文/小说/` 下，例如 `04_正文/小说/第001卷-卷名/`；不得把正文卷目录直接放在 `04_正文/` 根下。

正文路径调整属于结构化维护，不改变正文 canon。迁移正文目录时必须先按单作品备份规则备份，迁移后在 `09_索引/更新日志.md` 记录来源、目标和 canon 状态。

明确启用 webnovel-writer 兼容适配层时，`04_正文/小说/` 下单章文件是唯一正式正文源。webnovel-writer 的运行目录、审查报告、`.webnovel/`、`.story-system/` 和 `10_其他/webnovel-writer运行记录/` 只作运行记录，不替代正文源；同步按 [[神思-webnovel同步适配规则]] 执行。未启用时，不要求 review、chapter-commit 或 projection。

## 预计外文档入库

运行中产生的新 Markdown 不得自动放在作品根目录。必须先判断职责：

| 文档类型 | 标准位置 | canon 处理 |
|---|---|---|
| 当前正式可用章节、当前分卷结构、创作者阅读清单、辅助汇总视图 | `10_其他/` | 只供查阅，不作为 canon。 |
| 项目规则、更新日志、待确认事项 | `09_索引/` | 项目规则只约束当前作品；更新日志与待确认事项承担维护职责。文档、章节、人物和伏笔导航不落盘为 Markdown。 |
| 当前编译状态 | `07_编译报告/当前编译状态.md` | 软件实时汇总当前完成度，只读派生，不作为 canon 或历史日志。 |
| 人物/关系/势力/地点/物品运行状态 | `03_状态快照/当前状态.md` | 唯一完整当前视图，不按对象拆文件，不替代正史。 |
| 正式大纲、章纲、伏笔和信息释放控制 | `01_剧情控制/` | 需遵守 canon 状态闸门。 |
| 自检、连续性、商业追读、禁用词、信息权限、伏笔风险等报告 | `07_编译报告/小说自检.md` 或 `07_编译报告/剧本自检.md` | 只作报告，不写入正史。 |

如果既有职责目录会被该文件污染，且文件只服务创作者查阅，放入 `10_其他/`。`10_其他/` 不得成为第二个索引、第二个状态快照或第二个资料库。
## 多媒介产物入库

剧本、视频提示词、图片资产提示词和站位线稿图属于作品表达层产物，默认写入 `04_正文/短剧/` 下对应子目录：

| 产物 | 标准位置 | canon 处理 |
|---|---|---|
| 短剧剧本 / 漫剧剧本 / AI 仿真人剧本 | `04_正文/短剧/短剧剧本/` | 剧情事实需用户确认后才能回写正史。 |
| 剧集大纲 / 改编取舍表 | `04_正文/短剧/短剧剧本/` | 可作为改编工作文件，不自动覆盖小说大纲。 |
| 视频提示词 / 分镜提示词 / 漫剧提示词 | `04_正文/短剧/视频提示词/` | 只服务制作，不反向改写 canon。 |
| 图片资产提示词 | `04_正文/短剧/图片资产提示词/` | 只记录可视化资产描述，不新增剧情事实。 |
| 站位线稿图 / 空间调度图 | `04_正文/短剧/站位线稿图/` | 只固定空间调度，不改变人物关系和剧情。 |

多媒介产物入库维护档必须在 `09_索引/更新日志.md` 记录新增、修改、迁移和废弃；涉及剧情事实、人物状态、设定变化或与小说 canon 冲突时，写入 `09_索引/待确认事项.md`，不得直接覆盖正史。

## 编译报告写入

自检和自动审稿结果不得按检查项无限新建目录。统一写入：

- 小说相关：`07_编译报告/小说自检.md`
- 剧本相关：`07_编译报告/剧本自检.md`

写入规则：

- 单项自检：只更新聚合报告中的对应项目。
- 部分章节 / 部分集数：只列已检测对象。
- 全量自检：列出所有项目和所有已检测对象。
- 后续新增单项、章节、集数或全量报告：在原聚合报告基础上增加。
- 文本有新改动后再次自检：覆盖同一对象旧结论，保留最新有效结果。

若启用 webnovel-writer，其原始 review artifact 可以保留在运行记录中；`07_编译报告/小说自检.md` 只作为作者查阅用聚合报告。神思原生双核任务只记录必要的效果结论、硬冲突、记忆增量摘要和待处理返修，不伪造外部运行记录。

## 正文写后更新

正式生产档正文写后至少由记忆核产出结构化更新包。若明确启用 webnovel-writer，必须先确认其适配层要求的提交状态，或标注为待处理草稿；未启用时按双核完成标准判断。结构化更新包列出：

- 章末记忆。
- 人物状态变化。
- 伏笔新增、推进、回收、延后或废弃。
- 信息释放变化。
- 重要信息登场变化。
- 读者当前知识变化。
- 章节目标队列变化。
- 待确认更新。
- 连续性、OOC、伏笔风险和设定冲突。

结构化更新包的来源是正文和已确认资料。创作意图状态可以作为协作参考，但不得写入作品 canon；正例、反例和审美禁区如需长期保存，应放在项目协作说明或资料库，而非正史设定。

入库维护档必须写入对应完整路径文件；轻量诊断只输出待回写清单。

## 索引动态维护

`待确认事项.md` 不是永久堆积清单：

- 已解决冲突应移除并写入更新日志。
- 已揭示模糊事实应转入正式设定或状态文档。
- 已补齐资料缺口应移除。
- 新冲突、新模糊事实、新归类疑问和新补充需求应新增。
- 每次连续生产或阶段复盘后，应检查已解决、已入库、已废弃的待确认事项，避免待确认清单长期堆积为第二资料库。

## 管理边界

管理流程只负责保存、链接、状态、随正文单元保存的后台连续性增量、索引和日志，不主写正文、大纲、设定或剧本内容。动态上下文只在运行时临时编译，不作为回写目标。
