# 神思-正文写作规则

状态：正式生效，小说正文专项入口。

适用：小说正文、续写、扩写、改写、正式样章和正文级草稿。由 Agent 按 [[神思任务路由]] 与实时面板选择具体写作能力。

[[神思-正文高频表达限制与语境裁决规则]] 是正文主笔常驻的轻量硬边界：其中的受控词族、固定模板、开头零容忍和跨章复用门必须在起草时生效，不得以“语言问题留到写后”为由先生成再清洗。[[神思-开场钩子与时间叙述控制规则]] 是开场选型与全文时间节奏的常驻规则：二十四类只作为按情境选择的候选库；时间开场先分为模板报时、叙事性时间锚点和因果性时间锚点，再按删除、换时、承接三项测试裁决。[[神思-正文质量净增益与防退化规则]] 是隐藏常驻裁决层：先识别章节任务、叙事模式和质量保护项，再决定哪些问题必须修、可以优化、应当保留或不宜改动。返修统一执行其三层修改标准：第一层重写叙事结构，第二层恢复具体功能，第三层调整密度；禁止把三层都降格成同义词替换。

## 默认主流程

小说正文由当前面板中适配的写作 Skill 完成；本轮需要长期事实承接时，Agent 按需调用 [[神思-记忆检查规则]] 读取相关资料、检查连续性并提取记忆增量。

```text
理解创作意图和正式交付物
-> Agent 按需读取最小充分资料并选择 Skill
-> 正文起草
-> 与风险相称的效果和连续性复核
-> 必要时做质量净增益对照与定向返修
-> 自动落盘、回读并同步必要记忆
```

`webnovel-write` 继续作为兼容标签，不是默认必须存在的外部命令。未明确启用 [[神思-webnovel-writer运行边界规则]] 时，不要求本章合同、reviewer artifact、chapter-commit 或 projection。

## 写前最小充分上下文

写前只锁定会改变整章方向或连续性的内容：

- 本章目标读者反应与必须发生的变化。
- 前章必须承接的动作、后果、关系和情绪余波。
- 相关人物的欲望、恐惧、误判、底线、知情状态和关系位置。
- 已确认 canon、必要因果、时间地点和现实资源限制。
- 读者已知、可疑、误判和必须继续未知的信息。
- 未兑现承诺、伏笔压力和累积情绪债。
- 用户已确认的正例、反例、禁区与本章特殊取舍。
- 本章主任务、主导叙事模式、类型承诺和必须保护的既有优点。
- 章尾需要完成的具体结束功能；需要追读时再明确读者等待的问题。

胶囊由系统从现有资料自动编译，不要求用户填表。普通细节缺失时采用合理临时倾向；重大分叉才回到 [[创作引导]]。

## 候选竞争强制节点

开篇、前三章、高潮、重大虐点、关键打脸、关系转折、身份揭示、付费节点、结局以及用户反馈“不够刺激”“不自然”“不对味”时，Agent 可在内部比较多种走法；这是质量方法，不是对用户的固定选择门禁。

候选需要同时覆盖人物本能、效果聚焦和意外成立三种方向。先淘汰依赖降智、巧合、强行解释、人物突变、模板复用和提前泄密的方案，再按人物合理性、必然感、类型基调、读者效果、实现目标的最小力度与后续空间选择综合适配度最高者；不得把“最强”误解为“最响”。

## 写中优先级

1. 人物欲望、关系压力和当场选择。
2. 已确认 canon、信息权限和因果边界。
3. 本章目标效果与必须发生的变化。
4. 按叙事模式组合动作、对白、内心、物件、身体反应、说明和后果，不把任何单一载体设为统一答案。
5. 局部兑现、未完成承诺和与章节任务相符的结束功能。
6. 只在能暴露人物、改变选择或增强可信度时使用私心、生活习惯、职业反应、误判和语言毛刺，不按章配额硬塞。

写中不得背完整评分表。比喻密度、商业评分、AI 检测和全量语言问题留到写后或明确触发时处理；但 [[神思-正文高频表达限制与语境裁决规则]] 的受控表达、固定模板与开头硬禁必须随写随判。主笔不能先依赖模板完成初稿，再用同义词做表面清洗。

## 正文效果底线

- 每个场景都要有可说明的贡献：外部状态变化，或情绪余波、关系重定位、认知校准、必要定向、对比蓄力；不为“每场必变”制造虚假翻面。
- 主角能动性可以是判断、试探、选择、行动、拒绝、隐瞒、等待、改变解释或主动承受后果，按章节任务判断，不设机械次数。
- 人物可以犯错，但错误必须来自欲望、偏见、信息差、情绪或现实限制。
- 对话必须包含立场、关系压力或情绪变化，不能只负责解释。
- 强烈情绪必须有具体处境和形成过程，可由外部反应与内心矛盾共同承载；不由标签代替，也不把所有内心机械动作化。
- 爽点必须有阻力、代价、前置压抑或延迟兑现。
- 章尾必须完成与章节任务相符的具体结束功能，可为新压力、选择、后果、关系位移、裂缝、线索、余波、阶段兑现或真正闭合，并避免近期机械同型。强剧情/连载节点需要后续需求，余波章和结局不强制悬念。
- 单章字数是创作合同变量，优先级固定为：用户本轮明确要求 > 项目创作合同 > 单章章纲 > 软件默认值。用户或项目可以指定其他目标或范围，不得被默认规划强行覆盖。
- 未指定时，`2000-2800` 字只作常规连载规划参考，不再作为跨题材硬性发布线。正文应在章节任务、必要场景、因果桥和情绪余波自然完成处结束；不得为达到下限加入无后果细节，也不得为追求紧凑删掉关键过程。明显偏短时先判断是短章选择、任务不足还是未完成，再给结论。

## 开篇句式硬禁

开头硬禁不是只查第一句。必须按 [[神思-正文高频表达限制与语境裁决规则]] 检查前三个完整正文句或前 150 个汉字中覆盖更大的范围；该窗口内受控高频词、既有固定模板和泛化指代开头全部零容忍，不接受语境豁免。

正文不得使用可批量套换人物、地点和时段的模板报时或时间从句骨架，例如“凌晨三点，城市一片寂静”以及只把“时”机械替换成“之际”“的时候”的同构句。具体时刻或时段直接领起场景不再仅凭句法硬禁：若它与独有地点、制度、习俗、物件、声响、自然规律或人物感知形成不可替换的时间—场景组合，或直接改变期限、证词、选择、因果、状态与连续性，则进入语境保留。

开篇必须从本章独有的压力、异常、选择、关系动作、关键物件、感官矛盾或不可替换的时间—场景组合切入，让第一句无法无损搬到另一章。具体钩子按 [[神思-开场钩子与时间叙述控制规则]] 选择一个主钩、必要时最多一个辅钩，不机械追求灾难、死亡或倒计时。时间开场是低频手段而非绝对禁用项，必须通过删除测试、换时测试、随后一至两个叙事节拍的承接测试与跨章频率测试；陌生、古代或专业计时词只能作为风格证据，不能单独豁免通用环境句。必须与此前 30 个同类开头做复用检查。若近期连续或高频使用时间开场，先比较至少一种非时间入口；替代方案不损失必要信息、人物压力和张力时应换用，时间仍具有不可替代功能时可以保留。程序确认属于模板报时或其他固定模板时必须返修；叙事性时间锚点与单纯频率偏高只做语境裁决，不得自动硬阻断。

## 元叙事硬禁

正式正文的角色叙述、对白、心理和旁白中，禁止出现会暴露作者工程结构的表达，例如“第XXX章”“上一章”“下一章”“前文”“后文”“伏笔”“回收伏笔”“读者知道”“爽点在于”。章节标题本身除外。

不得用“他终于明白”“她这才明白”直接替读者总结跨章因果。需要改为人物当前能看到、听到、记住、误判或推断出的证据、动作和具体念头。

## 写后检查

Agent 先检查作品效果：

- 是否存在更强但更符合人物的反应。
- 人物是否过早清醒、突然强硬、突然软化或为剧情降智。
- 最强情绪是否真正落在场面中。
- 本章是否形成不可忽略的变化与局部兑现。
- 用户明确否定的表达和节奏是否重新出现。
- 开头硬禁、受控词逐条功能、词族频率、固定模板及前 20 章段落复用是否全部通过 [[神思-正文高频表达限制与语境裁决规则]]。
- 开场主钩是否由本章任务和人物问题自然产生；时间开场是否具备不可替代功能、信息增量和后续承接，近期是否形成连续或同构惯性；全文非因果性时间锚点是否超过 [[神思-开场钩子与时间叙述控制规则]] 的配额，是否出现连续时间词领段。
- 是否出现精确/近似正文复用、同场景骨架换槽位、固定动作—台词链或内部写作卡污染。
- 所有改动是否通过 [[神思-正文质量净增益与防退化规则]] 的前后对照：目标缺陷改善，质量守恒资产零实质下降。

需要连续承接时再检查：

- canon、时间、地点、资源、伤势、物品和知情状态冲突。
- 因果断裂、越权揭示、关系跳级和旧承诺丢失。
- 本章新增事实、人物状态、关系位置、情绪债、伏笔和读者知识变化。

局部问题采用最小返修；人物驱动或章节功能失败时打回候选方案，不在坏结构上只做语言润色。净收益无法证实时保留原文并说明风险，不为了完成自检项强改。

## 专项检查触发

- 强剧情和高价值节点：追加 [[强剧情自检]]。
- 常规推进失效：追加 [[常规推进自检]]。
- 秘密、误判、身份和终局信息复杂：追加 [[神思-正文信息权限规则]]。
- 满血终稿或可发布争议：追加 [[神思-正文质量规则]] 与 [[神思-正文语言质量规则]]。
- 商业、平台或读者模拟：追加 [[神思-商业判断与自动审稿增强规则]]。
- AI 味与检测风险：追加 [[神思-作者化与AI检测风险控制规则]]。

[[神思-正文高频表达限制与语境裁决规则]] 不属于可选专项；凡正式正文均在主笔和标准写后复核中强制执行。其他专项只追加更深检查。

专项检查只把问题转为返修约束，不把完整报告重新塞进下一轮正文上下文。

## 多章正式正文

多章生产不因数量降级，但允许自动连续执行：

```text
第N章胶囊 -> 第N章正文 -> 效果复核 -> 记忆增量
-> 第N+1章胶囊 -> 第N+1章正文
```

每章必须吸收上一章实际形成的选择、后果、关系、信息和情绪债。不得先按初始大纲一次性写完全部章节，再统一修补连续性。

每章还必须与此前 20 章执行段落精确 / 近似复用检查；同一批次 3 章以上出现同骨架段落时立即停止批量生成，按“模板坍缩”回退到场景因果重新起草。

只有重大 canon、主角命运、核心真相、结局、重大关系转向或用户禁区出现分叉时才暂停询问。

## 落盘与完成

正式结构化小说一章一个 Markdown 文件，标准位置为 `作品/作品名/04_正文/小说/第001卷-卷名/第001章-章名.md`。汇总稿和索引不能替代单章正文源。

标准正式章节完成至少满足：正文真实写入并回读、必要效果复核通过、没有未处理硬冲突，需要后续承接时已生成记忆增量。明确启用外部兼容运行时时，再追加该运行时的真实完成条件。
