# 神思-设定生成规则

本文件是 [[神思]] 的设定生成模块。适用于角色设定、主角设定、金手指设定、世界观设定、地图设定、力量体系、规则设定、势力设定、物品设定、种族设定、事件、时间线、术语和设定补全任务。

## 设定任务定位

设定任务不是简单填表，也不是只写功能摘要。[[神思]] 生成设定时，必须同时解决三件事：

1. 这个设定在作品世界里具体是什么。
2. 这个设定在剧情中如何被使用。
3. 这个设定处于什么 canon 状态，作为正式内容时如何进入 `02_正史设定/`，并与 `01_剧情控制/`、`03_状态快照/`、`04_正文/` 保持一致；属于探讨、未采用方向或明确草案时如何留在对话，或按用户要求保存。

## 设定主笔硬规则

- 从零新项目、新脑洞、新世界观、新人物、原型阶段新设定：Agent 选择适配的设定 Skill，可按需读取 `chinese-novelist-skill`。
- 正式结构化作品的新设定、补设定、事实链整理：Agent 选择实时面板中的设定 Skill；本轮需要时调用 [[神思-记忆检查规则]] 检查事实来源、旧 canon 和待确认边界，本文提供字段、具象度与出场节奏参考。
- [[小说结构化文档管理]] 负责正式内容的建档、拆分、链接、日志和一致性维护，不主写设定。
- 理论顾问只在设定是否能形成核心期待、信息差、剧情循环、出场节奏和追读压力时提供诊断，不得直接写入 canon。
- 原型或规划阶段从零生成主角姓名、新人物姓名时，必须执行 [[神思]] 的角色姓名去污染通用规则：先识别高频命名元素并加入临时冷却池，再按题材、时代、地域、阶层、人物气质和故事功能生成候选并自检；已有资料明确的人物姓名必须承接原资料。

## 默认主流程

设定任务不使用模糊主笔称呼；设定生产由 [[神思-设定生成规则]] 控制字段、具象度和 canon 状态，再按任务阶段调用对应主笔或流程。

| 任务 | 主流程 | 辅助 |
|---|---|---|
| 正式作品补设定 | Agent 按面板选择设定、记忆检查与结构管理能力；用户未要求不落盘时直接入库 | [[神思任务路由]]、[[神思-结构化管理规则]] |
| 原型阶段设定试作 | Agent 选择适配的设定 Skill，可按需使用 `chinese-novelist-skill` | [[神思-结构化管理规则]]、原型初筛 |
| 世界观/地图/规则补全 | Agent 生成候选并按需检查是否影响主线和既有 canon | 类型研究、理论顾问 |
| 设定入库与链接维护 | 管理流程 / [[小说结构化文档管理]] | [[神思-结构化管理规则]] |

其他能力只能提供参考、拆解、类型判断或试作方向，不得直接覆盖已确认 canon。

## canon 状态与输出模式

设定生成服从 [[神思运行规范]]。Agent 根据完整语义区分正式内容与探讨内容，不能因为是新项目、首轮生成或模型生成就默认降级为草案；用户要求正式交付且未明确禁止落盘时，直接写入正确文档。

| 场景 | 输出模式 | canon 状态 | 默认去向 |
|---|---|---|---|
| 新项目、新脑洞、原型阶段设定 | 由用户意图决定：正式交付或明确草案 | 正式版本或草案 | 正式交付写入 `02_正史设定/`；探讨默认留在对话；用户明确要求长期保留多套方案时按需创建 `08_资料库/备选方案/`。 |
| 正式作品补设定 | 正式交付 | 当前 canon | `02_正史设定/`；写入前保存完整历史。 |
| 正文明确产生、用户明确指定或 Agent 为正式任务生成的事实 | 正式交付 | 当前 canon | `02_正史设定/` |
| 与既有 canon 冲突、会改主线或影响核心规则的设定 | 诊断审查或结构草案 | 待确认 / 冲突 | 对应作品完整路径下的 `待确认事项`，不得覆盖正式设定 |

明确草案或待确认内容若按用户要求保存，文件开头应标注其状态并记录来源；不得把正式交付物仅因“尚未二次确认”而降级。

## 设定生成流程

1. 判断设定类型：人物、世界观、地图、规则、力量体系、势力、物品、种族、事件、时间线、术语或特殊设定。
2. 按当前设定与作品阶段读取最小充分事实源；上述结构目录均不是固定必读项。
3. 判断设定状态：已确认、待确认、草案、幕后未揭示、正文已揭示、与 canon 冲突。
4. 生成设定正文：先写具体样貌、运行机制、人物关系、使用场景和限制，再写剧情功能。
5. 标注来源：用户指令、正文章节、大纲、已有设定或待确认事项。
6. 落盘：正式内容进入 `02_正史设定/`；探讨与未采用方案默认留在对话；真正无法裁决的冲突进入 `09_索引/待确认事项.md`；用户要求保存并行方案时按需创建 `08_资料库/备选方案/`。
7. 写后检查：是否有功能摘要化、空泛标签化、提前泄密、与现有 canon 冲突、缺少来源。

## 设定质量硬规则

- 不得只写“它有什么剧情功能”，必须写清“它是什么、长什么样、如何运行、谁会接触、如何改变人物行动”。
- 不得用表格替代设定正文；表格只能用于索引、总览、字段核对和状态记录。
- 不得把明确草案或测试设定冒充正式 canon；也不得把用户要求的正式首轮成果错误降级为草案。保存草案时标注“草案 / 待确认”。
- 不得把幕后设定当成正文已揭示事实。
- 不得为了补设定而反向改写既有正文和既定事实。
- 不得创建或写入旧根目录 `设定/`；正式设定统一进入 `02_正史设定/`。

## 人物设定最低字段

人物设定必须使用人物档案式字段，至少包含：

| 字段 | 要求 |
|---|---|
| 姓名 | 正式姓名、别名或暂用名。 |
| 性别/年龄 | 可写未知，但不能缺项。 |
| 身份 | 公开身份、隐藏身份、阵营位置。 |
| 当前公开认知 | 正文或读者当前知道什么。 |
| 外貌气质 | 可被正文调用的视觉、声音、姿态、衣着和辨识点。 |
| 性格关键词 | 3-5 个稳定关键词。 |
| 核心性格 | 行动方式、价值判断、恐惧、欲望和底层矛盾。 |
| 当前目标 | 当前阶段正在追求什么。 |
| 长期目标 | 长线欲望、终局方向或隐藏目标。 |
| 能力特征 | 能力、技能、资源、身份优势。 |
| 弱点 | 能力限制、心理弱点、关系软肋、风险。 |
| 人物关系 | 与主角、反派、势力、关键人物的关系。 |
| 出场功能 | 在剧情结构中的作用。 |
| 口头禅 | 只记录可反复使用的短句；不得写一次性名台词。 |
| 写作风险 | OOC 风险、脸谱化风险、信息泄露风险。 |
| 背景故事 | 放在档案底部，集中记录身世、过往、秘密和作者层信息。 |

## 主角金手指字段

主角设定必须默认写明金手指信息和应用场景。即使是无系统、现实题材或普通人主角，也必须写明其核心优势、可复用策略或叙事金手指。

| 字段 | 要求 |
|---|---|
| 金手指一句话 | 主角核心优势是什么。 |
| 金手指来源 | 系统、血脉、记忆、身份、知识差、时间循环、特殊规则、人格特质等。 |
| 金手指机制 | 如何运行、触发条件、成长方式、消耗、冷却、限制和反噬。 |
| 金手指应用场景 | 战斗、破案、赚钱、社交、修炼、逃生、经营、解谜、救人、打脸、反转等。 |
| 金手指阶段变化 | 前期、中期、后期、终局的能力边界和升级方向。 |
| 金手指风险 | 滥用代价、暴露风险、误判风险、道德风险、敌人克制方式。 |
| 与主题关系 | 如何服务主角欲望、作品主题、爽点模型和长期主线。 |

## 世界观设定最低字段

世界观设定不得只写一句核心真相或概念摘要，至少包含：

| 字段 | 要求 |
|---|---|
| 世界一句话定位 | 表层类型、底层真相和主要矛盾。 |
| 世界层级结构 | 表层世界、隐藏层、幕后层、世界外层之间的关系。 |
| 历史背景 | 世界如何形成、当前时代如何到来、哪些历史真相尚未揭示。 |
| 社会结构 | 普通人、超凡者、国家、宗门、组织、阶层或文明如何生活和运转。 |
| 日常生活与常识 | 衣食住行、交易、交通、通信、教育、宗教、禁忌等可被正文调用的常识。 |
| 核心矛盾 | 世界当前最大的压迫、错误、危机或不可调和的规则。 |
| 与地图设定的关系 | 哪些地图承载这个世界观，哪些地点能体现世界规则。 |
| 与力量/规则/势力的关系 | 链接对应力量体系、规则设定和势力设定。 |
| 读者信息权限 | 区分读者已知、可疑、未知但作者已知、正式揭示节点。 |
| 写作边界 | 哪些内容可以前期显影，哪些属于中后期或终局真相。 |

## 地图设定最低字段

地图设定不得只写“剧情功能”。每个地点或区域至少包含：

| 字段 | 要求 |
|---|---|
| 地点一句话定位 | 它是什么地方、属于哪个世界层级、承担什么叙事位置。 |
| 具体样貌 | 地貌、建筑、光线、气候、材质、声音、气味、拥挤程度或荒凉程度。 |
| 空间结构 | 入口、中心、边界、禁区、道路、上下层、内外圈和关键节点。 |
| 行动路径 | 角色从哪里进入、如何移动、可能被堵在哪里、如何逃离或抵达。 |
| 控制方与居民 | 谁管理这里、谁生活在这里、普通人如何使用这里。 |
| 与世界观关系 | 如何体现世界底层规则、社会秩序、历史痕迹或隐藏真相。 |
| 与其他地图相对关系 | 地理、层级、交通、剧情顺序或世界结构上的相对关系。 |
| 可发生事件 | 适合发生哪些冲突、揭示、伏笔、战斗、日常或反转。 |
| 出场节奏 | 首次出现、局部揭示、正式揭示和是否存在幕后信息。 |
| 待确认缺口 | 比例、方向、邻近地点、路线、名称等未定项。 |

## 写后自检

设定生成后必须检查：

| 自检项 | 合格标准 |
|---|---|
| 具象度 | 能让作者看见地点、人物、组织或物件，而不只是知道功能。 |
| 运行性 | 能解释它如何运作、谁使用、有什么限制和代价。 |
| 剧情接入 | 能说明它服务哪条主线、哪类冲突、哪个阶段。 |
| 信息权限 | 幕后真相没有被误写成读者已知。 |
| canon 安全 | 没有覆盖既定设定或正文事实。 |
| 来源可追溯 | 有用户指令、正文、大纲、资料库或待确认来源。 |
| 落盘合规 | 正式内容自动进入 `02_正史设定/` 并经过历史保护和回读；探讨默认留在对话；真正冲突内容进入 `09_索引/待确认事项.md`；用户要求保存的并行方案进入按需创建的 `08_资料库/备选方案/`。 |
