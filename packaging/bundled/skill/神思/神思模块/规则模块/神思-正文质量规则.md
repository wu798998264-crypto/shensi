# 神思-正文质量规则

适用：小说正文质量、字数、信息团、商业开局、压缩初稿密度和可发布正文判定。

本文件只规定正文质量标准；所有诊断和返修先受 [[神思-正文质量净增益与防退化规则]] 裁决；正文生产流程读取 [[神思-正文生产流程]]；语言病灶、机械句式、万能章尾和情绪承载读取 [[神思-正文语言质量规则]]；高频表达、固定模板、开头零容忍、语境配额与跨篇复用读取 [[神思-正文高频表达限制与语境裁决规则]]；信息权限和伏笔显影读取 [[神思-正文信息权限规则]]。

## 商业开局自检标准

当任务为长篇小说开局、前三章、样章、强追读正文，或正文承担新书首批读者转化功能时，自检文档必须额外执行以下检查。该标准优先用于 [[强剧情自检]]，常规推进章节若承担开局功能也必须执行。

| 检查项 | 合格标准 | 不合格表现 |
|---|---|---|
| 先立人物再立设定 | 读者先通过场景、关系、选择和反应认识主角，再接触核心设定。 | 开篇直接解释世界观、等级、组织、金手指，人物像设定载体。 |
| 现实抓手 | 超自然、悬疑或强设定事件必须嵌入家庭、学校、朋友、工作、警署、快递、手机、监控等现实链条。 | 异常凭空发生，现实社会没有反应链。 |
| 大纲转场景 | 每个大纲节点都被转化为具体场景、行动、对话、误判和后果。 | 正文像细纲扩写，只交代发生了什么。 |
| 人物行动显智 | 主角的聪明、谨慎、欲望、缺陷通过具体操作体现。 | 旁白说主角聪明，但行动没有判断和取舍。 |
| 合理误判 | 开局阶段的人物判断必须受现有信息限制；需要误判时让其来自欲望、经验或信息差，不按章硬塞错误。 | 主角全知全能，或为了配额每章固定猜错一次。 |
| 信息释放节奏 | 前三章只释放局部异常和局部规则，不提前讲透完整世界观。 | 第一章就解释组织、等级、体系、终局真相。 |
| 人物关系戏 | 开局需要让关键关系在必要场景中显形；行动章可由协作、拒绝、掩护或代价承载，不按章强塞独立关系场。 | 关键人物长期只有任务功能，或闲聊可整段删除。 |
| 异常升级 | 异常需要逐章从物品、事件、失踪、官方介入、规则显露等方向升级。 | 第一章直接把核心秘密说完，后续只剩执行。 |
| 章尾追读 | 承担开局转化的章节应形成明确后续需求，可来自问题扩大、关系变化、选择、代价、阶段兑现或有证据的余波；不限定悬念形式。 | 没有具体结束功能，或临时塞新危险冒充追读。 |
| 长篇展开潜力 | 开局至少留下人物线、事件线、势力线、规则线中的两条可持续线索。 | 章节像短篇完结，没有连续追读承诺。 |

若任一关键项不合格，自检结论不得判为可发布正文，必须把最小返修约束交回 [[神思-创作核运行卡]]；局部问题定向返修，人物驱动或章节结构失败时重新进行候选竞争或打回章纲。

## 商业评分与硬性失败项

商业评分、读者模拟、平台适配、硬性失败项和自动审稿建议的唯一详细规则源是 [[神思-商业判断与自动审稿增强规则]]。

本文只保留触发引用：当任务涉及开局、样章、强追读、商业判断、读者模拟、章节评分、自动审稿或追读复盘时，读取 [[神思-商业判断与自动审稿增强规则]]；否则不把商业评分作为普通正文质量的默认必检项。

执行边界：评分只用于暴露返修优先级，不替代 [[强剧情自检]]、[[常规推进自检]]、正文质量、信息权限、人物一致性和上下文衔接。硬性失败项未清零时，不得判定正文通过。

## 正文语言质量

正文语言清理、机械关联词、重复信息、比喻密度、画面感边界、万能章尾和强情绪承载，统一读取 [[神思-正文语言质量规则]]。高频词族、否定解释句式、固定模板、开头窗口和跨篇重复统一读取 [[神思-正文高频表达限制与语境裁决规则]]，并作为可发布正文的硬闸门。

注意：受控词不是简单黑名单。每处命中必须结合当前场景裁决；只有满足统一规则列出的允许功能、证据、不可替代性与密度要求才可保留。开头窗口、固定模板和条件上限不接受语境豁免。

本文只保留总质量判定；具体语言病灶不再堆叠在本文件内，避免正文质量规则过厚。


## 人味与反工整质量闸门

正式正文不能只满足结构、信息和钩子，还必须保留人物真实感与文本自然波动。本节是通用规则，适用于所有原创小说正文、续写、扩写、改写和正式样章，不针对任何单一作品。

| 检查项 | 合格标准 | 风险表现 |
|---|---|---|
| 人物私心 | 在人物可能被写成功能人时，检查其反应是否来自自身处境、利益、习惯、恐惧、护短、嫌恶或小算盘；无需每章点名出现。 | 人物长期只执行剧情任务，没有自己的麻烦、欲望和偏见。 |
| 生活毛刺 | 生活细节、身体反应、职业习惯、地方口吻或关系小动作只有在暴露人物、改变判断或增强现场可信度时才保留。 | 场景长期只有设定机关；或为“人味”按章硬塞无后果细节。 |
| 对白去规则化 | 对白必须同时承担信息、立场、情绪或关系功能；同一角色口吻应与身份、状态和关系压力一致。 | 所有人都用同一种冷静、漂亮、规则化句式解释世界。 |
| 章尾类型轮换 | 连续章节的章尾应在危险升级、线索兑现、人物选择、关系变化、代价落地、安静余波等类型中轮换。 | 多章连续使用同类冷反转、同类新名词、同类文书显字或同类惊吓钩子。 |
| 结构不露骨 | 章节功能表只能指导正文，不能让正文读起来像逐项完成清单。 | 每段都精准服务设定、伏笔或钩子，缺少自然停顿和人物余味。 |

处理规则：

1. 若人物长期工具化，优先在最能改变选择或关系的现有位置恢复人物动作、职业习惯、关系反应或小私心，不另造无功能毛刺。
2. 若对白过度规则化，抽取足以证明问题的代表句检查“换成其他角色是否仍成立”。若成立，恢复说话目的、口吻、情绪或关系压力；不为完成数量硬改正常台词。
3. 若连续两章以上章尾同型，下一章优先改用人物选择、代价落地、线索兑现或安静余波，不继续堆新反转。
4. 若文本过于工整，允许保留少量不完美但有性格的停顿、误会、岔话、嘴硬、临场改口和生活反应；不得把所有句子都磨成同一种冷硬节奏。
5. 反工整不等于降智、注水、加废话或破坏作品气质；它只要求人物不像被章节功能表直接驱动。

## 正文产出篇幅闸门

默认规则：

- 单章字数按“用户本轮要求 > 项目创作合同 > 单章章纲 > 软件默认值”解析；用户或项目明确指定的其他目标或范围不得被默认值覆盖。
- 未指定时，`2000-2800` 字只作常规连载规划参考，不作为跨题材硬性发布线。正文应在章节任务、必要场景、因果桥和情绪余波完成处自然结束；不得为达到下限填充，也不得为追求紧凑删过程。
- 信息团数量只作组织诊断：应有一个主导读者问题和必要的支持信息，数量由章节复杂度决定。每团必须由场景、行动、对话、感知、心理、规则代价或关系变化中的合适载体承接。
- 章节应完成其主任务并形成相应结束功能。可记忆场面、外显行动、局部兑现和追读钩子按章节任务取舍，不按章固定配齐。
- 禁止用设定说明、剧情概述、节点罗列替代场景推进。

## 压缩初稿信息密度闸门

压缩稿是后续扩写的高密度剧情种子；它必须保留足以恢复正式章节的因果、人物、场景和情绪锚点。未指定篇幅时不以固定字数倒推填充量。

压缩初稿每章至少必须包含：

| 项目 | 最低要求 |
|---|---|
| 核心事件链 | 完整保留触发、行动、阻力、调整、结果与代价；节点数由事件实际需要决定。 |
| 关键场景 | 列出不可压缩的场景及地点、人物目标、冲突焦点、信息释放和结果；不为数量拆场。 |
| 人物变化 | 写清与章节任务有关的判断、选择、情绪余波或关系变化；若本章是铺垫，说明蓄力功能。 |
| 信息释放 | 写清本章明确揭示、局部揭示、继续隐藏和制造误判的信息。 |
| 伏笔状态 | 写清新埋、推进、回收或延后的伏笔，以及当前显影等级。 |
| 局部兑现 | 按章节任务兑现、推进或合理延迟既有承诺；不能长期只抛新悬念。 |
| 结束功能 | 标明新压力、选择、后果、关系位移、余波、阶段兑现或闭合等实际功能。 |
| 扩写锚点 | 列出恢复因果、关系、空间和情绪所必需的场景、对白、动作或细节锚点。 |

如果压缩初稿无法满足上述密度要求，必须判定为目录级草稿，不得写入 `04_正文/` 冒充章节草稿；应保留在候选稿、临时草案包或进入 `01_剧情控制/章纲/`。只有用户明确要求长期保留并行版本时，才可放入按需创建的 `08_资料库/备选方案/`。

## 正文修辞密度闸门

正式正文按叙事模式组合动作、对白、内心、说明、具体物件、身体反应和环境压力；比喻不能替代关键事件推进，但也不能被统一数字抹除。

默认规则：

- 显性比喻标记包括“像、仿佛、好像、如同、好似、宛如、犹如、一般、般、似的、某种”等。写后必须扫描。
- 数量和分布只触发复检，不设跨题材统一的每章硬上限。按视角来源、类型、场景速度、认知增量、聚集程度和是否干扰关键动作裁决。
- 高压动作和对话密集场景优先保证动作、对象、空间和判断清楚；比喻若不打断链条且能增加精度，可以保留。
- 同段或相邻段比喻聚集时，检查是否争抢焦点、重复同一效果或偏离人物经验；存在实际损害才返修。
- 同一信息团内，比喻只能服务一个明确功能；没有功能就删除。
- 禁止用抽象大词和万能比喻补情绪，例如“像命运”“像深渊”“像巨兽”“像潮水”“像某种无形的手”等，除非该意象已是作品内稳定母题。
- 角色处于逃跑、搏斗、谈判、求生、调查等强行动状态时，优先写动作链和判断链。

写后检查：扫描相关显性标记以定位聚集区，逐条判断视角来源、认知增量、类型适配、节奏负担和可替代性。无功能、同效叠加或打断关键过程的项才删除/重构；有独特功能的项明确保留，不执行“超数必删”或“相邻必删”。

## 神思输出的作品应具备什么

- 小说开局有清晰疑问和入局压力。
- 正文既要结构有效，也要让人物私心、生活质感、对白差异和章尾变化在需要处自然显现，避免按章配额制造人工人味。
- 每章都要完成其主任务并留下可追踪的因果、人物或关系结果。行动/压力章通常需要明确目标、阻力和代价；余波、关系、转场和收束章可以用后果消化、认知校准、关系重定位或闭合成立，不机械补齐同一套节点。
- 正式正文达到用户、项目或章纲指定的篇幅；未指定时由章节任务和自然完成度决定，明显偏短时区分短章选择、任务不足与未完成，而非自动注水。
- 压缩初稿必须是可恢复的高密度剧情种子，具备必要因果链、场景锚点、人物变化、信息释放、伏笔状态和结束功能。
- 场景/信息组织服务一个主导问题，数量随复杂度变化，不能只完成细纲打点。
- 强剧情章节形成有效压力、局部兑现和具体后续需求，不拘泥统一起承转合模板。
- 常规推进章节完成关系、后果、信息或蓄力任务；需要追读时形成期待，余波和收束时允许安静闭合。
- 长篇推进不丢设定、不忘伏笔、不漂移人物。
- 重磅设定有出场节奏，不在前半段无铺垫集中倾倒。
- 爽点来自人物欲望、世界规则和事件后果，不靠机械打脸。
- 反转来自误判、隐藏代价、身份错位、规则补全，不靠硬拧。
- 启用商业增强时，章节评分、读者模拟和自动审稿报告只作为加分项；不得把所有作品强行改成同一种商业爽文。
- 所有改写都通过 [[神思-正文质量净增益与防退化规则]]；指标变好但保护资产下降时回退。
