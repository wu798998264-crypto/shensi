# 神思-分级闭环与规则包规则

状态：正式生效。

用途：把 [[神思]] 的任务执行分成轻链、标准链和强闭环，避免所有创作任务都被完整流程拖慢；同时定义规则包、结构化自检协议和上下文预算优先级。

## 一、分级原则

默认先判断任务风险，再决定闭环强度。

| 闭环等级 | 适用任务 | 运行要求 |
|---|---|---|
| 轻链 | 闲聊、解释、局部润色、短片段试写、单次格式转换、低风险快速改句。 | 只读总控与命中专项入口；可省略完整状态机、自检协议和记忆增量。若实际修改叙事文字，仍执行最小质量守恒：保留原意、声音和有效细节。 |
| 标准链 | 正式正文、正式设定、章纲、单集剧本、常规改稿、需要后续承接的产物。 | 执行双核短链：意图、胶囊、主笔、效果复核、记忆检查、质量净增益裁决、必要返修。 |
| 强闭环 | 多章/多集连续生产、顶级/满血/投稿/发布前、重大质量争议、改动 canon、跨媒介生产链、结构化入库。 | 执行阶段状态机、结构化自检协议、合并返修、质量差值再验收和必要的证据记录。 |

禁止把强闭环变成所有任务的默认流程。用户明确要求“快写一版”“先试试看”“只改这几句”时，除非涉及硬冲突或重大 canon，不得升级到强闭环。

## 二、升级触发

命中任一条件时，从轻链升级到标准链：

- 产物会被后续承接。
- 用户要求正式交付、继续写、按当前版本推进。
- 涉及人物关系、信息权限、伏笔、设定或剧情因果。
- 输出不是解释，而是正文、剧本、大纲、设定或正式提示词。

命中任一条件时，从标准链升级到强闭环：

- 多章、多集、批量或跨媒介连续生产。
- 顶级、人类编剧水平、爆款、投流、投稿、发布前、满血终稿。
- 自检发现结构合格但普通、人物成立但效果弱、尾钩无效、剧情链断裂。
- 会改变主角命运、核心真相、结局方向、重大关系转向或已确认 canon。
- 需要落盘、入库、回写、同步状态、生成可追溯修改记录。

## 三、阶段状态机

状态机只在强闭环中强制执行；标准链可以合并相邻阶段；轻链不得被要求补齐全阶段。

### 小说正文强闭环

```text
intent
-> capsule
-> draft
-> effect-check
-> memory-check
-> quality-delta
-> targeted-rewrite
-> final-or-update-package
```

### 原创短剧强闭环

```text
brief
-> story-engine
-> original-audit
-> setting-domain
-> series-outline
-> episode-outline
-> script
-> script-selfcheck
-> rewrite-ladder
-> quality-delta
-> final-or-update-package
```

### 小说改编短剧强闭环

```text
source-ingest
-> plot-particle-protection
-> series-outline
-> episode-outline
-> script
-> script-selfcheck
-> targeted-rewrite
-> quality-delta
-> final-or-update-package
```

### 跨媒介强闭环

```text
source-script
-> production-feasibility-check
-> storyboard-or-video-prompt
-> visual-assets
-> blocking-or-continuity-check
-> delivery-package
```

## 四、结构化自检协议

强闭环中的自检输出必须转成可返修的短协议，而不是把完整检查表塞回起草上下文。

```text
finding：
severity：blocker / major / minor
affected_scope：
evidence：
must_keep：
must_change：
rewrite_instruction：
recheck_criteria：
expected_gain：
protected_assets：
regression_risk：
owner：创作核 / 记忆核 / 专项模块 / 用户拍板
```

规则：

- `blocker` 阻止入库或终稿交付。
- `major` 必须返修后再验收。
- `minor` 可以随本轮润色处理，不得触发全流程重跑。
- `must_keep` 和 `must_change` 必须同时存在，避免返修时破坏已成立部分。
- 多个检查器的 finding 必须先按证据和受影响范围去重、合并，由一个返修责任方执行；禁止检查器依次改写正文。
- `expected_gain` 不能只写“更顺”“更强”或“分数更高”，必须指向人物、因果、关系、情绪、信息、场景、语言或读者体验的具体改善。
- 改后必须比较 `protected_assets` 与 `regression_risk`；净增益不成立则回退，允许以“不修改”完成该 finding。
- 用户审美拍板项不得伪装成系统硬规则。

## 六、上下文预算优先级

规则加载预算不足时，按以下顺序保留：

1. 总控边界与安全边界。
2. 质量守恒、内容唯一性和正式产物隔离硬门。
3. 当前规则包的其他硬规则。
4. 当前阶段工作流。
5. 格式模板或输出模板。
6. 自检表中的关键失败项。
7. 示例、长理论、历史说明。

如果强闭环规则包发生截断，必须在内部标记 `规则预算不足`，优先降级长示例而不是丢失硬规则。轻链和标准链不因未加载强闭环示例而失败。

## 七、质量回归样本

框架大改后至少用以下样本检查路由行为：

- 普通小说局部改句：不得触发强闭环。
- 正式小说章节：应触发标准链和正文主笔。
- 满血小说审稿：应触发强闭环与对应自检。
- 原创短剧第一集：应触发原创短剧标准包。
- 顶级原创短剧：应触发原创短剧强包。
- 小说改编短剧：不得误触发原创短剧专项自检。
- 视频提示词或图片资产：应进入视觉链，不反向新增 canon。

检查重点不是规则文件标题是否出现，而是任务是否被分到正确闭环等级、是否避免普通任务过载、是否能把自检问题转成返修协议。
