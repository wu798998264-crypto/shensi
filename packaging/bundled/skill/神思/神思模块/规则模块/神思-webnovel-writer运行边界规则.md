# 神思-webnovel-writer运行边界规则

状态：兼容适配层，按需启用。

用途：当用户明确要求、作品已经接入或外部 webnovel-writer 运行时真实可用时，规定它与神思双核的职责边界。本文不是神思正式正文的默认入口。

## 启用闸门

满足以下任一条件才启用：

- 用户明确要求使用 webnovel-writer。
- 现有作品依赖其 reviewer、chapter-commit、projection 或断点恢复。
- 当前环境存在可实际调用并验证的原生运行时。

若仅存在历史 skill 资料、概念标签或不可调用路径，不得声称已经启用；直接使用 [[神思-双核运行规则]] 原生完成正文。

## 协作关系

```text
创作引导：确认方向、边界、验收和取舍。
记忆核：编译动态创作胶囊，写后检查冲突与提取增量。
创作核：完成候选竞争，确定本章最优方案与效果标准。
webnovel-writer：在启用时执行其原生起草、reviewer、commit和projection。
结构管理：维护单正文源、canon、章节记忆和索引。
```

动态创作胶囊需要固定字段时，使用 [[神思-本章创作合同模板]] 转换。合同不得取代创作核的候选竞争，也不得形成第二套事实源。

## artifact 边界

神思不得伪造或口头补写 webnovel-writer 的 review_results、write-gate、chapter-commit 或 projection。外部运行时也不得绕过神思的 canon、信息权限、创作意图和单正文源规则。

未启用本文时，上述 artifact 全部不进入神思完成判定。

## 单正文源

正式正文仍只有一个 Obsidian 查阅源：

```text
作品/作品名/04_正文/小说/第001卷-卷名/第001章-章名.md
```

`.webnovel/`、`.story-system/` 和 `10_其他/webnovel-writer运行记录/` 只保存运行、恢复和排错资料，不是正文、正史或章节记忆。

## 检查分层

| 检查层 | 负责方 |
|---|---|
| 外部运行有效性 | webnovel-writer 原生 reviewer、write-gate、commit 和 projection。 |
| 作品效果 | 创作核效果复核；终稿或争议时追加 [[神思-创作效果验收规则]]。 |
| canon、连续性与信息权限 | 记忆核。 |
| 路径、状态和索引 | 结构管理。 |

不得因为已经有外部 reviewer 就跳过记忆核，也不得让神思重复运行一套同级工程 reviewer。

## 完成判定

启用本文时，一章完成需要：

1. 外部运行时自身要求的 commit/projection 状态有效。
2. 正文位于单正文源路径。
3. 创作核效果复核通过，或用户明确接受。
4. 记忆核无未处理硬冲突并已生成记忆增量。

未启用本文时，按 [[神思-双核运行规则]] 的原生完成标准执行。
