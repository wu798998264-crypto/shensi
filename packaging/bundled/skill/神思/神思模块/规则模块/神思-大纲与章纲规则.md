# 神思-大纲与章纲规则

本文件是 [[神思]] 的大纲与章纲执行模块。适用：新项目大纲、正式全集大纲、卷纲、阶段规划、单章章纲、后续章节规划、目录级草稿判定和压缩初稿规划接口。

## 大纲主笔硬规则

- 原型阶段大纲、新项目方向、故事雏形：Agent 选择适配的规划 Skill，可按需读取 `chinese-novelist-skill`。
- 正式全集大纲、卷纲、阶段规划、章纲：Agent 选择实时面板中的规划 Skill；本轮需要时使用 [[神思-记忆检查规则]] 检查 canon、旧承诺和信息释放约束。
- 正文级章节生产不由本模块主写；Agent 应选择实时面板中的正文写作能力。
- 管理流程只负责保存、目录、链接和一致性维护，不生成大纲内容。
- [[神思-长篇结构自检规则]] 负责全集大纲、卷纲、阶段规划、整卷正文和整本小说的结构自检；不替代适配的规划 Skill。
- 规划与返修必须服从 [[神思-正文质量净增益与防退化规则]]：先明确阶段/章节任务、类型承诺和保护资产，不为固定钩子、场景数或字数配额牺牲人物、因果与节奏波形。
- 理论顾问只在核心期待、故事层级、剧情循环、信息团、追读压力等疑难判断原因不清时辅助解释，不替代 Agent 选择的规划能力，也不单独决定最终修改。
- 从零规划主角姓名、主角卡或新增原创人物时，必须执行 [[神思]] 的角色姓名去污染通用规则：不得继承参考资料的高频姓名、姓氏、用字和命名气质，不得形成新的默认命名惯性；已有资料明确的人物姓名必须承接原资料。

## 定位

大纲不是正文附属品，也不是设定摘要。大纲负责把作品方向、阶段目标、剧情因果、人物行动、信息释放和伏笔回收拆成可执行结构。

所需能力按 [[神思任务路由]] 和实时面板执行：

| 场景 | 主笔 / 主流程 | 状态 |
|---|---|---|
| 新项目、新脑洞、原型阶段大纲 | Agent 选择适配的规划 Skill，可按需使用 `chinese-novelist-skill` | 用户要求正式交付时直接成为当前正式版本，否则按明确草案处理。 |
| 原型通过初筛后的正式长篇接入 | Agent 组合规划、记忆检查和结构管理能力 | 可进入正式规划。 |
| 正式全集大纲、卷纲、阶段规划、章纲 | Agent 选择规划 Skill，并按需检查 canon 与信息释放 | 正式规划产物，默认自动落盘。 |
| 章纲入库、目录维护、链接维护 | 管理流程 / [[小说结构化文档管理]] | 只负责保存和一致性维护，不负责主写。 |

## 大纲类型

| 类型 | 作用 | 默认位置 |
|---|---|---|
| 新项目大纲 | 验证核心冲突、主角欲望、类型承诺和长篇潜力。 | 候选稿或临时草案包；用户明确要求长期保留多套方向时按需创建 `08_资料库/备选方案/`。 |
| 全集大纲 | 确定全书方向、主线结构、阶段推进和终局约束。 | `01_剧情控制/全集大纲.md`。 |
| 卷纲 / 阶段规划 | 确定一段连续剧情的目标、压力、局部兑现和阶段终点。 | `01_剧情控制/卷纲/` 或阶段规划目录。 |
| 单章章纲 | 把单章拆到可直接写正文的颗粒度。 | `01_剧情控制/章纲/`。 |
| 目录级草稿 | 只列标题、事件摘要、目标或钩子。 | 候选稿、临时草案包或待确认区；明确要求长期保留的并行目录可进入按需创建的备选方案，不得冒充章纲。 |
| 压缩初稿规划 | 介于章纲和正式正文之间，用于批量章节草稿。 | 按输出模式进入章纲目录、草案区或临时更新包。 |

## 小说分集细纲废止

[[神思]] 不再为小说结构化管理新建或维护 `01_剧情控制/分集细纲/`。小说阶段级约束由 [[小说结构化管理skill/模板/作品模板/01_剧情控制/卷纲/说明|卷纲]]、阶段规划和 `01_剧情控制/章纲/` 中的章节总览表共同承担；具体单章内容只以单章章纲为准。

废止后的处理规则：

- 新建作品模板不创建 `分集细纲/`。
- 新生成小说细纲、详细大纲、章节区间规划时，直接拆为 `01_剧情控制/章纲/` 下的单章章纲；需要阶段总控时写入卷纲、阶段规划或章纲目录内的总览文件。
- 既有作品中的 `分集细纲/` 视为历史材料或待迁移来源，不作为正文生产的当前约束源；其中仍有价值的单章内容应迁入对应单章章纲。
- 正文生产、连续性检查和结构复盘按任务需要读取相关大纲、章纲、信息释放、伏笔或章节记忆，不设置固定必读项。

短剧、漫剧、AI 仿真人剧本里的多集规划统一称为“剧集大纲”，走 [[神思-短剧与视觉资产规则]]、[[小说改编短剧剧本skill]] 和 [[短剧剧本自检]]，不得与已废止的小说分集细纲混用。

## 全集大纲最低要求

全集大纲负责长期结构，不写成流水账。至少包含：

1. 依据说明。
2. 一句话故事。
3. 类型定位与读者承诺。
4. 核心命题与主角欲望。
5. 主线结构。
6. 全书阶段表。
7. 主角成长线。
8. 核心势力推进。
9. 分卷大纲。
10. 关键伏笔与回收。
11. 章节推进方法。
12. 开篇建议。
13. 第一阶段剧情建议。
14. 待确认事项。

## 卷纲与阶段规划要求

卷纲或阶段规划负责一段连续剧情的可执行方向，必须写清：

- 阶段起点和阶段终点。
- 本阶段主角目标。
- 核心阻力和升级方式。
- 局部兑现点。
- 地图、势力、人物关系和资源变化。
- 信息释放顺序。
- 重要信息首次登场、局部揭示、正式揭示和解释完成计划。
- 阶段伏笔、回收和延后揭示。
- 阶段结尾的具体功能：后续需求、阶段兑现、关系/认知变化、余波或闭合；连载节点再明确读者期待。

## 单章章纲要求

章纲默认采用“章节总览表 + 单章纯文本剧情走向”的复合形态：上方用阶段目标和章节总览表做总控，下方按章展开剧情如何发生。

| 字段 | 要求 |
|---|---|
| 本章定位 / 任务 | 本章在阶段剧情中的功能，并标注压力行动、调查揭示、关系推进、后果余波、铺垫转场、高潮兑现或收束结局中的主任务。 |
| 主导叙事模式 | 实时场景、概述压缩、转场定向、反思内心、说明定向、对话关系或蒙太奇余波；可有次模式。 |
| 前章承接 | 承接上一章的事件、情绪、悬念或人物状态。 |
| 本章目标 | 主角本章具体要做什么。 |
| 主导读者问题 | 本章集中推进的主问题；支持问题可列出但不得争抢层级。 |
| 核心阻力 | 谁或什么规则阻止主角。 |
| 代价 | 主角推进本章目标时付出什么。 |
| 局部兑现 | 本章兑现哪一个爽点、悬念、情绪或信息。 |
| 结束功能 | 章尾完成新压力、选择、后果、关系位移、认知翻面、余波、阶段兑现或闭合中的哪一项；承担追读职责时再写具体期待。 |
| 人物变化 | 本章人物认知、关系、资源或状态变化。 |
| 质量保护项 | 本章写作和返修不能丢失的因果桥、人物动机、关系压力、情绪余波、信息梯度、声音、意象或长线空间。 |
| 近期差异 | 与相邻/近期章节相比，本章在目标、阻力、策略、转折、代价、结果和结束功能上有哪些不可替换差异。 |
| 伏笔 / 回收 | 新增、推进、显影或回收哪些伏笔。 |
| 重要信息登场 | 本章涉及哪些 S/A/B/C 级重要信息；分别是不出现、首次登场、推进可疑、维持误判、局部揭示、正式揭示还是解释完成。 |
| 首次登场承载 | 若本章有重要信息首次登场，写清具体承载：物件、异常、行动后果、台词错位、场景规则、人物误判或旁证。 |
| 本章禁区 | 哪些信息不能提前泄露，哪些设定不能改。 |
| 本章篇幅变量 | 记录用户/项目明确目标、允许范围和来源；未指定时由章节任务、必要场景、因果桥和情绪余波的自然完成度规划，`2000-2800` 仅作常规连载参考。 |

硬规则：单章章纲必须有连续剧情动作链，写清人物判断、行动递进、阻力反应、信息释放和场景结果；不能只把表格字段改写成短句。

## 目录级草稿判定

以下输出只能算目录级草稿：

- 只有章节标题。
- 只有事件摘要。
- 只有本章目标和章尾钩子。
- 只有表格，没有逐章展开。
- 没有场景、动作链、阻力反应和人物变化。

目录级草稿可以用于讨论方向，但不得交给正文主笔当作可落盘章纲，也不得冒充压缩初稿。

## 压缩初稿规划接口

当规划主笔需要输出“压缩初稿 / 章节草稿 / 剧情草稿”而非正式正文时，不得降低到目录级章纲。压缩初稿必须比普通章纲更接近正文执行稿，至少额外标注：

- 本章不可压缩且足以恢复正式正文的场景锚点；数量由实际事件决定，不为配额拆场。
- 每个场景的动作链、人物选择、阻力反应、信息释放和场景结果。
- 本章新增或推进的伏笔、显影等级、当前允许写法。
- 本章新增或推进的重要信息登场动作、首次登场承载和当前允许写法。
- 本章保留给正式扩写的对白锚点、物件锚点、身体反应锚点或环境压力锚点。
- 本章扩写时必须补强的关系戏、现实抓手或情绪后果。

硬规则：压缩初稿不得静默冒充正式正文；如果只有目录级信息，必须标注为“目录级草稿”。

## 生成后结构自检

正式全集大纲、卷纲和阶段规划生成后，必须按 [[神思-长篇结构自检规则]] 执行结构自检。

- 全集大纲检查：核心承诺、主角终极欲望、开端与终局呼应、分卷递进、中段动力、反派/阻力线、人物成长线、信息释放线、伏笔总账和主题证明。
- 卷纲检查：本卷承诺、卷内压力、局部兑现、新缺口、中段转折、人物变化、设定负载、伏笔处理和章节功能分布。
- 阶段规划检查：阶段起点、阶段终点、连续动作链、期待循环、信息权限和人物状态。
- 跨章差异检查：目标、阻力、策略、场景骨架、结果、情绪曲线和结束功能是否发生换槽位复用；连续章节是否保有强弱、快慢、兑现/余波的波形。
- 整卷或整本复盘时，读取正文、章节记忆、伏笔管理、信息释放表和人物状态，再输出结构体检报告。

自检结论为“需大修”或“不建议入库”时，不得把大纲、卷纲或复盘结论直接写入正式剧情控制；必须先进入对应作品完整路径下的 `待确认事项` 或 `07_编译报告/`。

## 入库边界

- 只有用户确认、已确认正文反推，或明确授权接入正式长篇的大纲、卷纲、章纲，才可以进入 `01_剧情控制/`。
- 新项目或首轮生成只要属于正式交付，且用户未明确要求不落盘，就写入正确的大纲或章纲文档；探讨和未采用方案默认留在对话，用户要求长期保留并行版本时按需创建 `08_资料库/备选方案/`。
- 会改变 canon 的大纲修改必须进入对应作品完整路径下的 `待确认事项`，不得直接覆盖正式剧情控制。
- 生成后的章纲由 [[小说结构化文档管理]] 负责保存、链接和一致性维护，不由管理流程改写内容。
