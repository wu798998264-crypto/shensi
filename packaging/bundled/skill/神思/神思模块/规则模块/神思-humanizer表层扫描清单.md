# 神思-humanizer表层扫描清单

状态：正式生效，作为 [[神思-作者化与AI检测风险控制规则]] 的附属清单使用。

用途：吸收本机 `humanizer` skill（`C:\Users\Administrator\.codex\skills\humanizer\SKILL.md`）中适合中文小说的表层 AI 写作痕迹检查项。本文只做写后 lint，不接管正文主笔、不替代作者化返修、不覆盖人物口吻、剧情功能、信息权限或 canon 边界。

## 使用边界

- 只在正文基础质量、信息权限和语言清理之后使用。
- 只标出表层 AI 痕迹和局部修法，不整章统一改写。
- 如果目标是实际降低平台 AI 检测风险，仍优先使用 [[神思-作者化与AI检测风险控制规则]] 的“作者主写 + AI 诊断 + 局部候选”模式。
- 如果表层痕迹来自 AI 整章生成的深层结构，不承诺通过任何黑箱检测。
- 本清单必须接收 [[神思-正文高频表达限制与语境裁决规则]] 的扫描结果，并服从 [[神思-正文质量净增益与防退化规则]]；不能只删“AI 高频词”而漏掉开头模板、反应占位、意义封口和跨章同构，也不能为“去 AI 味”抹掉作者签名、内心深度或类型语言。

## 可吸收清单

| humanizer 模式 | 中文正文中的风险表现 | 神思处理方式 |
|---|---|---|
| 意义拔高 / broader trends | 动不动把小动作写成命运、时代、世界格局的象征 | 删掉虚高判断，改回人物当下能感知的利害、恐惧、误判或选择 |
| 宣传腔 / 形容词堆叠 | “恢弘、璀璨、深刻、极致、震撼”等形容词替代具体画面 | 用物件、动作、声音、气味、身体代价承载感受 |
| 表层分析尾巴 | 句尾追加“彰显了、体现了、映照了、标志着”等解释 | 若角色不知道，就删除；若必须说明，拆成角色偏见、误会、威胁或制度话术 |
| 模糊归因 | “有人说、世人皆知、传闻认为、众人都觉得”没有来源 | 改成具体角色、具体场景、具体传言来源，或标为读者未知 |
| AI 高频词 | “关键、重要、复杂、深层、核心、显著、全面、系统性”等空泛词密集 | 保留必要术语，删掉不能改变画面的评价词 |
| 低熵叙事词族 | “没有 / 不是 / 只是、看一眼 / 沉默、立刻 / 慢慢 / 猛地、真正 / 终于明白”等反复替代场景功能 | 不做同义词洗稿；按统一规则逐条判断功能与证据，开头命中或超条件上限直接返修 |
| 跨篇槽位模板 | 多篇只替换人物、地点、怪物或概念名，段落骨架与结论相同 | 与近期成品比较；3 篇以上同构按模板坍缩停止批量处理 |
| 三段式和排比滥用 | 连续把情绪、动作、判断拆成整齐三连 | 只保留真正递进的排比；装饰性三连压成一个具体动作或判断 |
| 同义词轮换 | 主角、少年、青年、他、此人等称呼为避重复频繁切换 | 正式正文优先稳定称呼；只在视角、身份误认或信息权限变化时换称 |
| 被动和无主句过多 | “被发现、被证明、被意识到”导致责任主体消失 | 能明确行动者时改成角色行动；未知主体才保留无主感 |
| 破折号 / 括号 / 加粗 / emoji 等格式痕迹 | 正文像聊天输出或营销文案，格式符号替代叙事 | 小说正文不得保留 chatbot 式加粗、emoji、客套话；破折号按中文文风和节奏判断，不一刀切 |
| 泛泛正向结尾 | 章尾用“新的旅程开始了”“未来仍充满挑战”等空结论 | 章尾落在与章节任务相符的新压力、选择、后果、关系位移、余波、阶段兑现或闭合上，不统一强塞钩子 |
| 金句化短句 | 每段都像结论、格言或短视频文案 | 保留少数关键落点，其余改回现场动作、对白或人物判断 |
| 对话式客套残留 | “当然、希望这有帮助、下面是、让我们”等 AI 回答语气混入正文 | 正式正文、设定和报告中删除；只有角色台词确实需要时保留 |

## 不直接吸收内容

- `humanizer` 的“最终文本不得有破折号”不能直接套用中文小说。中文正文可使用破折号，但必须服务语气中断、解释插入或强制转折；若只是 AI 式夹注，应删改。
- `humanizer` 的英文 Title Case、curly quotes、hyphenated word pair 等规则只适用于英文或双语文档；中文正文不因此改标题风格。
- `humanizer` 鼓励在博客、评论、随笔中加入观点和个性；小说正文不能为了“有人味”插入作者评论，除非作品叙述视角本就允许。
- `humanizer` 的“重写覆盖原段落”方式不适用于低检测风险终稿。若目标是降低平台检测风险，仍优先使用作者主写优先流程。

## 扫描流程

```text
1. 先确认章节功能、人物动机、信息权限和 canon 没问题。
2. 执行高频表达总闸门：开头、固定模板、词族计数、逐条语境和跨篇复用。
3. 再扫描其余 humanizer 型表层 AI 痕迹。
4. 对每一类命中，只标出具体句段和风险原因。
5. 优先给“局部手术式修法”，不整章统一改写。
6. 修改后按质量保护项复查人物、因果、关系、情绪、信息梯度、叙述声音、类型承诺和后续空间；任何实质退化都回退，并再次执行高频表达扫描。
7. 若表层痕迹来自 AI 整章生成的深层结构，不承诺通过检测，只建议切换到作者主写优先流程。
```

## 输出格式

```text
humanizer 表层扫描：

1. 命中的 AI 痕迹类型：
2. 具体句段：
3. 为什么像模型化表达：
4. 神思修法：
5. 是否会影响人物 / canon / 信息权限：
6. 是否需要作者亲自重写：
7. 高频表达总闸门：开头 / 配额 / 逐条语境 / 跨篇复用
8. 明确保留 / 不建议改动：
9. 质量差值：预期收益 / 实际改善 / 保护资产 / 退化检查 / 采用或回退
```
