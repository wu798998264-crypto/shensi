# 神思-商业判断与自动审稿增强规则

状态：正式生效。

用途：把商业判断、章节评分、读者模拟和自动审稿脚本接入 [[神思]]，作为正文、大纲和结构复盘的增强层。它只负责补充判断维度和检查项，不担任主笔，不替代 [[强剧情自检]]、[[常规推进自检]]、[[神思-长篇结构自检规则]]、[[神思-正文质量净增益与防退化规则]]、[[神思-正文质量规则]]、[[神思-正文高频表达限制与语境裁决规则]] 或 [[神思-正文信息权限规则]]。

## 定位边界

本模块吸收外部“小说工业化生产体系”的可执行部分，但必须本土化兼容 [[神思]]：

- 不新增第二套总控入口；入口仍是 [[神思]]。
- 不新增第二套任务路由；能力选择统一按 [[神思任务路由]] 和实时面板执行。
- 不新增第二套 canon 规则；所有建议都受 [[神思-结构化管理规则]] 的 canon 状态闸门约束。
- 不把商业建议直接写入正史、正文或大纲；需要改动作品事实时，先进入对应作品完整路径下的 `09_索引/待确认事项.md`。
- 不默认套用男频爽文标准；只有任务、作品标签或用户目标明确命中男频爽文、男频网文、爽文、男频黄金三章、男频追读等关键词时，才按 [[小说类型理论研究]] 路由进入 [[男频网文创作逻辑研究]]。
- 不以评分代替作者判断；分数只用于暴露风险和返修优先级，作者或用户拥有最终取舍权。
- 不允许商业分数抵消人物、因果、信息权限、内容唯一性、作者声音或类型承诺的退化；所有返修必须通过质量净增益对照。

## 触发条件

出现以下需求时读取本模块：

- 商业判断、读者承诺、追读、爽点密度、章节评分、章节是否能留人。
- 开局、前三章、样章、强类型连载、付费转化、平台气质、市场对标。
- 自动审稿、硬性失败项、重复词、人名污染、信息提前暴露、连续性脚本检查。
- 整卷复盘、整本复盘、章节质量量化、读者模拟反馈。
- 用户要求“吸收外部框架”“优化神思生产体系”“把理论落成流程”。

不触发场景：

- 纯设定命名、单独格式修复、Obsidian 链接修正、短剧格式页、图片资产提示词、站位线稿图等任务，除非用户明确要求商业追读或自动审稿。
- 用户明确要求文学实验、非商业创作、自由发挥或不做评分时，不强行套评分表。

## 项目商业判断总纲

正式长篇项目若追求商业连载，应在 `00_入口/` 或 `01_剧情控制/` 中维护一份商业判断总纲。未结构化作品可在临时上下文包中生成简版。

建议字段：

| 字段 | 用途 |
|---|---|
| 目标平台 / 频道 | 判断读者耐心、爽点密度、解释成本、章节长度和情绪直给程度。 |
| 类型承诺 | 一句话说明读者为什么追这本书。 |
| 主角核心欲望 | 复仇、变强、求生、护人、掌控命运、洗刷污名等。 |
| 情绪主轴 | 压抑后反击、神秘探索、秩序结算、关系拉扯、恐惧掌控等。 |
| 核心爽点模型 | 爽点来自身份反差、规则反杀、公开兑现、资源翻盘、能力升级还是信息优势。 |
| 长线未兑现 | 读者愿意等多久、等什么最终兑现。 |
| 禁区 | 不能提前揭底、不能连续同类打脸、不能主角失去能动性、不能过量解释等。 |
| 对标样本 | 可学习的开篇、节奏、卖点、读者反馈，不作为抄袭来源。 |
| 作者裁决 | 本项目最终审美、价值观和取舍标准。 |
| 平台适配取舍 | 若目标平台不同，写明哪些可以加强、哪些不能牺牲；例如低理解成本、强情绪、规则复杂度、文风质感、爽点频率。 |
| 人味保留策略 | 写明本项目如何在有功能的位置保留人物私心、生活质感、口吻差异和章尾变化，避免按章配额制造另一种工整。 |

商业判断总纲属于项目控制文件，不是正史设定。涉及作品事实、终局秘密、人物核心身份或力量体系底层逻辑时，仍按 canon 状态闸门处理。


## 平台适配与 AI 痕迹风险

商业判断不能只问“分数高不高”，还要判断作品是否符合目标平台的阅读习惯，以及正文是否因为过度工整而呈现机器协作痕迹。本节适用于所有正式长篇项目、样章、投稿稿和追读复盘，不绑定任何单一作品。

| 检查项 | 起点 / 偏核心读者 | 番茄 / 偏大众转化 | 通用风险 |
|---|---|---|---|
| 主角目标 | 可以稍含蓄，但前 3 章必须明确生存、查证、复仇、变强、护人或洗冤方向。 | 必须更直给，读者第一时间知道主角要什么、怕什么、下一步做什么。 | 主角只被事件推着走，缺少欲望和选择。 |
| 设定理解成本 | 可保留复杂规则；当本章引入会影响当前行动的新规则时，应给足可用的局部答案或可感知后果。 | 规则尽量靠事件和后果理解，少用连续术语和制度解释。 | 设定漂亮但读者不知道当前事件为何重要。 |
| 爽点 / 局部兑现 | 可偏规则反杀、信息优势、身份错位、证据推进。 | 需要更高频、更外显、更情绪化的压迫与反击。 | 只抛悬念，不给读者阶段补偿。 |
| 情绪表达 | 可以克制，但必须能看到人物痛点和代价。 | 应更直接，让压迫、委屈、愤怒、护短、反击更可感知。 | 全文冷静精密，人物像设定容器。 |
| 文风质感 | 允许更强风格，但不能牺牲清晰行动链。 | 以清楚、快读、强情绪优先，风格不能妨碍理解。 | 句子漂亮但推进变慢。 |
| AI 痕迹风险 | 主要风险是结构过密、意象过齐、章尾过稳、对白过像规则讲解。 | 主要风险是套路过直、情绪模板化、爽点机械化、反应同质化。 | 所有人物同口吻、同节奏、同功能。 |

AI 痕迹风险不是判定文本是否由 AI 生成的证据，只是审稿时用于降低“过度工整、过度同质、过度功能化”观感的质量指标。不得为了规避风险而故意写错、注水、降智或破坏作品气质。

高风险表现：

- 每章章尾都使用同类新反转、新名词、新文书、新身份或同类惊吓。
- 物件、意象和规则过于整齐，缺少生活边、人物私心和偶发反应。
- 所有角色都能精准说出世界规则，且说话节奏相近。
- 每个场景都像按功能表完成任务，没有无功能但有性格的动作或停顿。
- 情绪只由抽象词和漂亮句子表达，缺少身体、关系、利益和处境承载。
- 章节反复调用否定重定义、视线 / 沉默占位、速度副词和意义封口，或多个章节只替换名词继续使用同一段落骨架。

处理优先级：先保留作品核心气质，再补人物真实感；先改对白口吻和人物反应，再改叙述风格；先轮换章尾类型，再增加新设定或新反转。

## 章节评分表

正式章节、样章、开局前三章和强追读章节在用户/项目明确需要商业量化时可使用 100 分制评分。下表是“商业压力/追读章”的基础画像，不是所有章节的固定权重。关系章、后果章、调查章、结局和文学性章节必须先按章节任务调整权重或停用总分；评分只定位返修优先级，不允许用高分跳过硬性失败项或掩盖质量退化。

| 维度 | 分值 | 检查重点 |
|---|---:|---|
| 开篇吸引力 | 10 | 第一屏是否有问题、压力、异常、欲望或承诺。 |
| 本章冲突强度 | 10 | 是否有明确阻力、升级和代价。 |
| 主角能动性 | 10 | 主角是否以符合章节任务的方式判断、选择、行动、拒绝、隐瞒、等待或承担后果。 |
| 爽点 / 局部兑现有效性 | 15 | 是否有前置压抑、因果铺垫、公开或可感知兑现。 |
| 人物情绪真实度 | 10 | 情绪是否来自处境、关系、欲望和代价。 |
| 信息控制 | 10 | 是否遵守该作品完整路径下的 `信息释放表`、`重要信息登场账本` 和 `读者当前知识库`。 |
| 章末功能 | 15 | 追读章是否留下具体后续需求；余波、关系、阶段收束或结局是否完成相应后果、意义变化或闭合。 |
| 连续性 | 10 | 人物状态、时间、地点、道具、伏笔和知识范围是否连续。 |
| 语言流畅度 | 5 | 是否通过高频表达开头、语境配额、固定模板与跨篇复用闸门；是否干净、少重复、少机械连词、少无功能比喻，同时保留必要的人物口吻差异和自然停顿。 |
| 商业追读感 | 5 | 是否让目标读者愿意继续读下一章，且平台承诺清楚。 |

评分解释：

- 85 分及以上：可进入定稿候选，但仍需硬性失败项为 0。
- 75-84 分：仅表示需要复核；有正文证据时再定向返修，优先检查章节任务、信息控制、结束功能和与任务相符的主角能动性。评分本身不能触发改写。
- 低于 75 分：通常应重修章节功能表或章纲，不能只润色正文。
- 评分与自检冲突时，以硬性失败项和对应自检文档为准。
- 评分上升但质量保护资产下降时，按 [[神思-正文质量净增益与防退化规则]] 回退修改，不能以总分抵消。

## 硬性失败项

以下问题一旦出现，章节不得判为通过，必须返修或降级为草稿：

- 出现未登记且影响主线的核心设定、战力规则、组织、血缘、身份或终局信息。
- 提前明示或半明示 S级 / A级信息，或绕过该作品的 `重要信息登场账本` 讲透重磅信息。
- 主角在需要其作出选择的关键节点失去能动性，只被作者便利推动；拒绝、隐瞒、等待和主动承受后果也计入能动性。
- 结尾没有与章节任务相符的具体结束功能；承担追读职责时无后续需求，承担余波/收束职责时无真实后果或闭合。
- 人物行动、对白或情绪与人物卡、状态快照、已发生事件冲突。
- 爽点没有前置压抑、阻力、代价或因果铺垫，只靠作者宣布胜利。
- 关键选择、主要对抗、证据确认或不可逆代价被解释性旁白全部替代，导致读者无法相信结果。段落数量只能触发复检，不能单独硬判。
- 作品长期只抛悬念而无阶段进展，或本章承诺应兑现却无理由拖延。
- 同类打脸、追杀、解释、梦境、系统弹窗、文书显字、身份反转、规则宣告或冷反转章尾连续重复，且没有升级变量。
- 正式正文低于项目要求字数，且未标注为压缩初稿或剧情草稿。
- 命中 [[神思-正文高频表达限制与语境裁决规则]] 的开头硬禁、固定模板、条件上限、未完成逐条裁决或未登记跨篇复用。
- 命中精确/近似正文复用、同场景骨架换槽位、固定动作—台词链、内部写作卡污染、空壳或完成状态异常。

## 读者模拟反馈

读者模拟属于顾问层，只输出风险和阅读反应，不接管主笔，不直接改 canon。

读者模拟至少回答：

| 问题 | 输出要求 |
|---|---|
| 哪一段最想继续读 | 指出具体期待来源。 |
| 哪一段最想弃读 | 指出拖沓、解释、重复、OOC、结束功能失效或类型承诺未兑现的原因。 |
| 本章读者拿到了什么 | 列出局部兑现、信息、关系变化或情绪补偿。 |
| 下一章读者在等什么 | 必须是具体问题，不是泛泛“继续看后续”。 |
| 目标读者是否匹配 | 说明是否符合当前项目商业判断总纲；不清楚时标注缺少目标读者信息。 |

## 自动审稿脚本建议

脚本检查是编译报告的一部分，不替代人工自检和作者判断。正式项目可在 `scripts/` 中逐步建立以下检查器；报告结果统一写入 `07_编译报告/小说自检.md` 或 `07_编译报告/剧本自检.md`，不得按检查项无限细分报告目录：

当前状态：本节是检查器设计清单，不代表这些脚本已经在 vault 中全部实现。执行任务时，只有明确存在的脚本或报告模板才可称为“已执行自动审稿”；其余情况应标注为“人工按清单复核”或“建议后续实现脚本”。

| 检查器 | 检查对象 | 输出位置 |
|---|---|---|
| 人名污染检查 | 新增姓名、高频姓氏、同名混淆、称谓漂移。 | `07_编译报告/小说自检.md` |
| 重复词检查 | 相邻句、相邻段和单章高频重复词。 | `07_编译报告/小说自检.md` |
| 高频表达与模板复用检查 | 开头窗口、受控词族配额、逐条语境、固定句式、近期精确 / 近似段落复用与批量坍缩。 | `07_编译报告/小说自检.md` / `剧本自检.md` |
| 重复信息检查 | 旁白、台词、回忆、设定解释是否重复表达同一信息。 | `07_编译报告/小说自检.md` |
| 信息提前暴露检查 | S/A/B 信息是否越权进入正文。 | `07_编译报告/小说自检.md` |
| 章尾功能检查 | 结尾是否完成章节任务要求的后续需求、后果、关系位移、阶段兑现、余波或闭合。 | `07_编译报告/小说自检.md` |
| 主角能动性检查 | 关键节点是否缺少符合人物和章节任务的选择、拒绝、隐瞒、行动或承受。 | `07_编译报告/小说自检.md` |
| 内容唯一性与产物污染检查 | 精确/近似正文、槽位换皮、动作—台词链复用以及写作卡/自检/结尾说明混入正式产物。 | `07_编译报告/小说自检.md` / `剧本自检.md` |
| 连续性检查 | 时间、地点、道具、伤势、人物知识范围。 | `07_编译报告/小说自检.md` |
| 伏笔寿命检查 | 伏笔是否长期无推进、无回收计划或重复埋设。 | `07_编译报告/小说自检.md` |

脚本输出只能作为问题清单或辅助评分依据。若脚本结果会改变 canon，必须进入对应作品完整路径下的 `待确认事项`，不得自动覆盖正式设定。

## 结构化落盘建议

商业判断和自动审稿资料建议按以下位置保存：

```text
作品/作品名/
  00_入口/
    商业判断总纲.md

  01_剧情控制/
    爽点账本.md
    情绪账本.md
    章节评分表.md

  07_编译报告/
    小说自检.md
    剧本自检.md

  08_资料库/
    对标拆书/
```

这些文件默认是控制、报告或资料库文件，不是 `02_正史设定/`。对标拆书只能学习结构、节奏、读者承诺和市场信号，不得复制具体表达、桥段排列或角色设定。

商业追读评分、读者模拟反馈和自动审稿清单属于自检报告内容，应写入 `小说自检.md` 对应章节、范围或全量报告条目；不得另建 `商业追读评分/`、`读者模拟反馈/` 或 `自动审稿/` 目录。

## 最终原则

商业增强只解决“更清楚地判断哪里弱、为什么弱、先修哪里”。它不能替代主创审美，不能替代用户确认，不能把所有作品都改造成同一种爽文。对 [[神思]] 来说，它是加分项：强化目标、量化风险、补足读者视角和自动检查，而不是新增一套会互相打架的生产系统。任何商业返修只有在读者收益可说明、质量保护资产零实质下降时才能采用。
