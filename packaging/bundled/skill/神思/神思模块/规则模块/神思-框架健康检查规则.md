# 神思-框架健康检查规则

状态：正式生效，双核版。

用途：每次 [[神思]] 大幅调整后，检查默认运行路径是否短、双核职责是否清楚、创作引导是否可用、兼容适配层是否越权，以及活动规则是否仍可调用、可维护、无备份污染。

## 检查范围

默认只检查活动规则：

- [[神思]]。
- `skill/神思/神思模块/` 下活动模块索引。
- `skill/神思/神思模块/规则模块/` 下活动规则、流程和映射。
- 当前被入口或路由明确调用的 skill 入口。
- 本次调整直接涉及的专项文件。

默认排除 `_备份_不参与规则扫描/`、`原始资料/`、`废弃设定/`、乱码隔离文件和历史备份。

## 一、总入口检查

必须满足：

1. [[神思]] 是唯一总控入口。
2. [[神思-双核运行规则]] 是默认生产编排。
3. [[神思-创作核运行卡]] 和 [[神思-记忆核运行卡]] 各自只有一份活动规则源。
4. [[神思任务路由]] 是唯一的 Agent 路由说明，实时面板拓扑是能力关系依据。
5. [[神思运行规范]] 统一约束执行、历史、落盘和错误回执。
6. [[神思-分级闭环与规则包规则]] 只裁决闭环强度、规则包和预算优先级，不接管主笔、自检或管理职责。
7. 所有新入口都能解析到唯一 UTF-8 Markdown 文件。

## 二、默认路径长度

普通小说正文的默认运行链必须能压缩为：

```text
神思
-> 创作引导意图
-> 记忆核胶囊
-> 创作核生成与效果复核
-> 记忆核冲突检查与增量
-> 交付/回写
```

普通起草前不得强制全文读取：

- 完整自检库。
- 商业评分和类型理论库。
- 语言病灶和 AI 检测规则。
- 结构化执行手册。
- webnovel-writer artifact、commit 或同步规则。
- 本章创作合同。

命中明确专项风险、满血终稿或兼容运行时后，才允许追加对应文件。

分级闭环检查：

- 轻链不得强制状态机、自检协议、记忆增量或证据记录。
- 标准链不得默认加载强闭环规则包。
- 强闭环必须有明确触发原因，例如多章/多集、顶级/满血、重大 canon、质量争议、跨媒介生产链或入库回写。
- 规则包只能约束加载组合和预算优先级，不能建立第二套总控。

## 三、创作核检查

必须满足：

- 高价值节点要求人物心智模拟和至少三种候选竞争。
- 候选覆盖人物本能、效果极值和意外成立。
- 先淘汰降智、巧合、强解释、人物突变和提前泄密方案。
- 创作核只携带动态胶囊与一个命中专项模块进入起草。
- 创作核不擅自写入 canon，不展示冗长内部推演。
- 效果复核关注人物、情绪、场景变化、局部兑现、结尾期待和用户反例。

若创作核开始承担目录、索引、长期状态或 canon 入库，判定职责漂移。

## 四、记忆核检查

必须满足：

- 写前只编译最小充分上下文，不扫描全部资料。
- 动态创作胶囊区分作品事实与创作意图状态。
- 写后检查 canon、知情边界、因果、时间地点、资源和信息权限。
- 每章生成记忆增量，多章之间先增量再进入下一章。
- 硬冲突可以阻断；软风险只提示；普通创作选择不干预。
- 推断必须标注，不把未确认内容覆盖正史。

若记忆核开始重写正文、提供保守剧情方案或把“资料没写过”当作禁止创新，判定职责漂移。

## 五、创作引导检查

必须满足：

- [[创作引导]] 仍可通过“创作引导模式”、空白想法、零散材料和数字选项启动。
- 已确认偏好可以复用，不重复从基础问题开始。
- 引导维护方向、边界、验收、取舍、正例和反例。
- 创作意图状态明确标为非 canon。
- 普通细节由双核自动推进。
- 只有重大 canon、人物命运、核心真相、结局、重大关系或用户禁区分叉才暂停。
- 信息足够时停止追问并进入双核。

若创作引导主写正式产物、维护作品事实或形成长期问卷，判定职责漂移。

## 六、兼容适配检查

[[神思-本章创作合同模板]]、[[神思-webnovel-writer运行边界规则]] 和 [[神思-webnovel同步适配规则]] 必须同时满足：

- 明确标为兼容或按需启用。
- 只有用户明确要求、项目已接入或外部运行时真实可用时才触发。
- 未启用时，不得要求 reviewer artifact、chapter-commit、projection 或同步映射。
- 不得把缺少外部 artifact 判为神思原生双核失败。
- 启用后仍服从创作意图、记忆核硬冲突、canon 和单正文源规则。

在活动规则中发现“正式正文必须启用 webnovel-writer”“每章必须生成本章合同”“无 commit 不算完成”等未加启用条件的表述，判定兼容层越权。

## 七、专项规则检查

检查专项模块是否只在命中时读取：

| 专项 | 允许触发 |
|---|---|
| [[强剧情自检]] | 开局、前三章、高潮、重大虐点、打脸、反转、追读不足。 |
| [[常规推进自检]] | 过渡、关系推进或后果消化失效。 |
| [[神思-长篇结构自检规则]] | 整卷、整本、全集大纲和阶段复盘。 |
| [[神思-商业判断与自动审稿增强规则]] | 用户要求商业、平台、评分、读者模拟或市场判断。 |
| [[神思-作者化与AI检测风险控制规则]] | 用户明确提到 AI 味、检测或作者化。 |
| [[神思-正文语言质量规则]] | 语言质量争议、终稿或专项诊断。 |
| [[神思-结构化管理规则]] 子流程 | 明确建档、迁移、入库、回写或路径维护。 |
| [[神思-分级闭环与规则包规则]] | 框架大改、强闭环任务、规则包或预算策略诊断。 |

普通写作若默认同时加载多个专项自检，判定规则过载。

## 八、canon 与结构检查

必须满足：

- 正文、正史、状态快照、章节记忆和编译报告职责分离。
- 正式小说正文仍一章一个 Markdown 文件，并保持单正文源。
- 创作意图状态不写入正史设定。
- 记忆增量只记录正文明示或强烈成立的事实，推断有标记。
- 同名结构文档使用完整路径加显示别名。
- 管理流程不补写核心创作内容。
- 未确认内容进入候选稿、待确认或临时草案包；只有用户明确要求长期保留并行方向时才进入按需创建的备选方案。

## 九、备份与污染检查

必须满足：

- 大框架调整前已经备份到 `skill/神思/_备份_不参与规则扫描/`。
- 活动入口、路由和搜索默认排除备份、原始资料、废弃设定和乱码文件。
- 备份目录中的旧规则不得被活动 wikilink 或默认扫描误读。
- 新增示例名、占位作品名和模板名不得误建成当前 canon。

## 十、文本扫描建议

框架大改后，在活动文件中搜索：

```text
必须生成本章创作合同
正式正文必须.*webnovel
无.*chapter-commit.*不得
逐章.*等待.*确认
默认读取.*完整自检
创作引导.*不再
```

命中后逐条判断：

- 是否位于兼容适配层且写明启用条件。
- 是否是历史说明、反例或健康检查扫描词。
- 是否仍对默认双核产生强制约束。

不得只按关键词机械删除；要检查语义是否冲突。

## 十一、通过标准

框架健康检查通过，必须同时满足：

1. 默认路径短且唯一。
2. 创作效果、连续性和产能优先级明确。
3. 创作引导可用且不会重复追问。
4. 双核职责无交叉越权。
5. 兼容适配层不再劫持默认生产。
6. 多章之间存在真实记忆增量。
7. canon、单正文源和结构化边界未被削弱。
8. 新增 wikilink 与路径全部有效。
9. 活动规则中没有未处理的旧强制链残留。

任何一项失败，都应输出：问题文件、冲突语句、影响范围、最小修复方案和是否需要再次备份。修复后重新执行本规则，不得只凭“入口已更新”宣布完成。
