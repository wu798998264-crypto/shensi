# 神思-框架健康检查规则

状态：正式生效，Agent 运行版。

用途：在神思框架或能力包调整后，验证实际运行入口、文档事务、白板隔离、Skill 路由、界面回执和发布内容。本文是验收清单，不参与普通创作路由。

## 检查范围

检查当前发布源码、活动能力包、实时 Skill 面板、文档 Agent API、白板/媒体 API、定向测试和最终安装包。排除历史版本、备份、用户作品、测试作品、缓存、日志、依赖和打包产物，防止它们重新成为活动规则源。

## 一、唯一入口与路由

必须同时满足：

1. 文档对话只进入 Conversation Agent；白板和媒体只进入白板/媒体 API，二者没有共享任务编排器。
2. [[神思任务路由]] 与 [[神思运行规范]] 是仅有的内部运行合同；旧路由文件和旧运行卡不在发布能力包中。
3. Agent 依据完整语义、当前阶段、交付物、作品结构和实时 Skill 面板选择能力。
4. 关键词、标签和兼容字段只能用于检索或元数据，不能单独决定任务类型、Skill、资料读取或写入方式。
5. 不存在固定必读清单、统一前置检查链、主笔数量向导或因空文档阻断任务的逻辑。

## 二、Skill 面板与动态路由

- 并行、主次和组织关系以持久化数组的真实顺序为准，拖拽后的角色影响下一轮路由。
- 只允许同容器排序或精确交换，不允许跨模块、跨模组移动；锁定节点不能移动。
- 保存面板后使用当前文字模型生成动态路由候选。
- 候选只有在 revision、topology hash、关系语义、能力覆盖和防退化校验通过后才激活。
- 失败保留上一份有效路由并显示真实原因；恢复面板历史时同步恢复对应路由。

## 三、文档执行与落盘

- 用户手动文档操作全部保留；Agent 在权限范围内可以执行相同操作。
- 当前打开文档只作为可识别上下文，不是默认绑定目标。
- 正式内容在用户未明确要求不写入或不落盘时，自动写入最合适的具体文档。
- 探讨、解释和未采用方案默认留在对话；用户明确要求保存时可以落盘。
- 目标不存在时由 Agent 按结构化规则新建；完整正式文章可以用文章标题替换“未命名”等占位标题。
- 每次写入、覆盖、续写、追加、局部替换、重命名、移动、复制或删除前，保存受影响对象的完整可恢复历史版本。
- 写入后必须回读验证；只有真实工具回执可以声明完成，标题链接必须能打开真实目标。
- 局部修改显示改前和改后对比，确认替换前不改变正文；确认后先保存历史再落盘。
- 自检报告默认写入 `07_编译报告/小说自检.md`、`07_编译报告/剧本自检.md` 或实际适配的具体报告文档；`report-compile` 只汇总，不代替报告正文。

## 四、读取与任务卡证据

- Agent 按任务真实需要决定资料和 Skill，不设置统一必读项。
- 任务卡只显示已经实际取得非空内容的文档和真正加载的 Skill。
- 空文档、预计读取但最终未读的资料、[[神思任务路由]] 和 [[神思运行规范]] 不显示。
- “已读取”位于生成任务卡内部的最下方，默认展示前几项并可展开全部；不再渲染独立、重复的读取板块或“当前状态”文字。
- 目标文档显示具体名称；任务结束时展示与标题一致的可跳转链接。

## 五、对话连续性

- 用户消息先进入对话，再出现选择框；确认按钮位于选项右侧且不与选项过度分离。
- 选择结果等同普通用户指令，必须继续原任务；输入框发送其他想法会跳过当前选择并继续。
- 选项持久有效，不因等待过期；撤回所属指令时同步撤回选择框。
- 编辑历史指令可以发送并建立新分支；多个对话可以并行运行。
- 用户手动新建的对话在重启和更新后仍存在。
- 运行中显示加载、思考、等待或恢复状态；完成、失败、取消、中断、阻断和需重试都必须有明确回执，禁止静默停止。

## 六、白板与媒体冻结边界

- 文档改动不得改变即梦凭证锁、账号隔离、配置切换、提交、轮询、下载、回写、幂等恢复或聚合 API 生图路由。
- 即梦锁只覆盖一次真实任务从准备、生成、有限重试、成功、下载到卡片回写的完整活动链；任务脱离活动状态后立即释放。
- 生成失败必须展示 CLI 或供应商的真实原因，不把已核验账号笼统误报为未核验。
- 待处理项能彻底终止所有仍阻塞的图片、视频和文档发起的媒体任务；终止后不残留锁。
- 对话区成功生成的图片和视频自动备份到全部资产。
- 受保护的跨配置串行生图回归必须通过；真实付费测试只在用户授权的最短视频和单张图片范围内执行。

## 七、界面与发布内容

- `en-US` 下设置、模型、权限、Skill 面板、Skill 广场、路由历史、任务卡、选择框和错误卡没有界面中文残留；用户内容、品牌名和外部模型名除外。
- “发布skill到广场”和“skill广场”等界面文本符合当前命名，按钮文字不溢出。
- Skill 能力分类包含“其他”。
- 安装包不包含开发者个人作品、测试作品、凭证、日志、缓存、依赖目录或运行产物。

## 八、通过标准

框架健康检查只有在源码、定向测试、真实 Electron 界面测试、包内容策略和发布构建全部通过后才能宣布完成。任何失败都要给出问题文件、真实原因、影响域、修复结果和复测证据；不得因为入口文档已经更新就推断运行行为已生效。
