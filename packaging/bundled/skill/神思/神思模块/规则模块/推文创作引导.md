# 推文创作引导

状态：正式生效。

用途：为公众号文章、公众号长文和微信推文建立可执行的创作合同。本文负责逐轮挖掘选题、读者承诺、作者个性、内容证据、阅读节奏和传播包装，不替代 [[公众号模块]]、[[公众号文章创作理论]] 或命中的类型理论。

## 启用边界

- 用户准备创作、构思、续写或重做公众号文章时启用。
- 是否启用由最终产物决定，不受当前工作区、打开文档或目录类型限制。
- 知识问答、资料整理、摘要、校对和普通笔记不启用。
- 只有主题、热点、素材、标题或一个观点时必须启用；这些信息不构成完整创作合同。
- 用户明确说“直接写”“必须直出”“不要追问”“按现有信息写”时，立即停止追问，把已确认信息与专业补全项组成临时合同交给主笔。

## 引导原则

每轮只处理一个决策簇，不把字段表丢给用户填写。每轮必须包含：

1. 说明当前最需要决定的内容及其对成文的影响。
2. 给出 2—3 个差异明显的方向，说明各自适合什么读者体验。
3. 明确推荐一个方向并说明理由；不得只给选择而不提供专业判断。
4. 只问一个可直接回答的问题。
5. 回答后合并创作合同，跳过已经确认或授权系统决定的内容。

用户说“你决定”“按你的推荐”时，将当前决策簇记为授权委托，并采用已说明的推荐，不再反复确认。

## 必需决策簇

| 决策簇 | 必须挖掘的内容 | 对成文的控制作用 |
|---|---|---|
| `audience-purpose` | 目标读者、阅读场景、当前认知或情绪、平台目的、希望读者读后采取的行动。 | 决定解释深度、共情入口和转化方式。 |
| `topic-promise` | 主题与真正选题、核心问题、一句话阅读承诺、读者最终获得什么。 | 防止只有主题没有内容主张。 |
| `type-angle` | 文章类型：观点、故事、经验、案例、方法、科普、争议辨析、人物或混合型；主要切口、立场和尺度。 | 决定信息组织和论证方式。 |
| `voice-difference` | 文字风格、作者人格、情绪温度、用词习惯、个人经验或观察、禁用表达、与同类文章的差异来源。 | 让文章像一个具体的人在写，而不是通用模板。 |
| `evidence-attraction` | 核心看点、案例或事实来源、证据边界、反常识或争议信息是否需要、如何避免标题党和伪科普。 | 同时控制可信度、新鲜感和抓人程度。 |
| `structure-rhythm` | 开头钩子、叙事或论证结构、信息密度、段落节奏、情绪曲线、看点出现顺序和结尾功能。 | 决定读者能否持续读完。 |
| `title-package` | 标题主要机制、关键词、冲突、收益、悬念、身份代入、反常识强度，以及标题承诺如何在正文兑现。 | 提高打开率，同时约束正文不跑题。 |
| `ending-action` | 结尾是总结、回扣、行动建议、价值抬升、问题留白还是互动引导；是否需要关注、评论、转发或私域动作。 | 决定余味和传播后的下一步。 |

## 文章专项深挖

### 选题与承诺

- 把“主题”压缩成“某类读者在某种处境下，为什么必须现在读这篇文章”。
- 区分用户想表达什么与读者愿意点开什么；二者不一致时提出兼容切口。
- 选题必须有明确的旧认知、新认知和读后变化，不能只做资料罗列。

### 标题设计

标题讨论至少覆盖标题的主驱动力：明确收益、冲突对立、身份代入、信息缺口、反常识、时间压力或故事悬念。给出方向时同时说明：

- 哪种标题更容易打开。
- 哪种标题更符合作者人格。
- 标题承诺需要正文在哪一段兑现。
- 是否存在夸张、误导、平台风险或透支信任。

最终主笔应先形成至少 5 个差异化标题，再选出主标题与 1—2 个备选；标题不得只是同一句话替换近义词。

### 作者个性与差异化

优先从真实经验、独特观察、价值判断、惯用比喻、句式节奏、幽默方式和敢于承认的矛盾中寻找作者感。不得把“犀利、温暖、专业、幽默”这类空泛形容词当成完整文风；必须转成可执行表达，例如句长、叙述距离、案例口径、观点锋利度和是否允许自我暴露。

### 反常识与抓眼球

反常识不是必选项。只有它能被事实、经验或严密推理支撑，并能服务核心结论时才采用。可选择：

- 不使用反常识，以强共鸣或实用收益抓人。
- 使用温和认知修正，让读者发现常见做法少了一个条件。
- 使用强反转观点，但必须提前设计证据链和正文兑现位置。

## 自适应回路

```text
识别现有材料已经覆盖的决策簇
-> 选择对阅读承诺影响最大的缺口
-> 提供方向、推荐与一个问题
-> 合并用户答案
-> 基础决策簇完整后提出 1—3 个看点增强建议
-> 让用户选择、拒绝或委托系统决定
-> 展示最终创作合同摘要并确认
-> 交给公众号主笔生成、标题竞争和效果复核
```

用户只给主题时，第一轮必须给出 2—3 个不同“选题承诺”，并让用户选择文章真正要解决的问题；不得直接开始写全文。

## 看点增强回路

基础合同完成后必须进行一次增强讨论。建议从以下方向中选择真正适合本题的 1—3 个，不得机械全加：

- 增加一个真实人物或个人经历作为情绪锚点。
- 增加可验证的反常识结论或认知纠偏。
- 增加具体案例、对照实验、数据或来源。
- 增加一段反方视角，提升可信度和思想张力。
- 增加可立即执行的方法、清单或判断工具。
- 调整看点顺序，让最强承诺在前 20% 得到第一次兑现。

## 停止条件与交接

只有以下条件同时满足时停止追问：

1. 八个必需决策簇均已确认或由用户明确授权系统决定。
2. 看点增强建议已经讨论，用户已选择、拒绝或授权采用推荐。
3. 已向用户展示压缩后的创作合同，用户明确确认可以生成。

内部交接至少包含：文章类型、选题、目标读者、阅读承诺、核心结论、主要切口、作者人格与语言执行规则、差异化来源、证据边界、反常识策略、核心看点、结构与节奏、开头钩子、标题策略、结尾动作、篇幅、禁区、已选增强项。未确认内容标记为临时倾向，不伪装成用户偏好或事实。
