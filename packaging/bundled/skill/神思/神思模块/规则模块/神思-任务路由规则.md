# 神思-任务路由规则

状态：正式生效。

## Agent 报告与引导记录的交付归属

- 用户要求制作自检、质检或审稿报告时，Agent 应按任务语义选取对应自检 Skill，并实际读取所需正文。搜索片段只能支持局部判断，不能声称完成全文自检；未加载的 Skill 不得列为实际采用。
- 报告应保存到编译报告集合（`reports`）中的具体报告文档，标题应说明检查对象和范围。禁止修改被检查正文不等于禁止保存报告；用户明确只在对话交付时不保存。
- `report-compile` 是自动重建的项目总览，不是长篇自检报告正文的写入位置。缺少正文时仅能生成明确标注范围的预审或缺口报告，不冒充完整质检。
- 创作引导文档只追加作者已确认的决策和已采用方向；问题、未采用建议和完整聊天仍留在对话区。已经授权整理引导记录时不重复询问。
- 结束前核对原始要求、实际读取范围、具体交付目标和成功写入回执。模型自称“仅讨论”或“已保存”不能替代该核对；有目标缺失或写入失败时继续处理或如实报告未完成。

适用：判断本轮由哪个专项主笔模式执行、需要什么检查、何时调用顾问、何时交给管理。默认运行编排统一服从 [[神思-双核运行规则]]。

复杂度裁决服从 [[神思-分级闭环与规则包规则]]：先判断轻链、标准链或强闭环，再选择主笔与自检。普通低风险任务不得因为存在完整强闭环能力而被迫走全流程。

## 运行层与职责层

双核是运行层：创作核负责生成与效果，记忆核负责编译上下文、硬冲突和状态增量。凡产物含叙事正文，另由隐藏底层的 [[神思-正文质量净增益与防退化规则]] 承担质量守恒、内容唯一性和修改回退裁决；它不是用户可见模块，也不能被专项 Skill 关闭。

主笔、自检、顾问、管理是职责层：它们定义谁对产物负责，不再要求不同规则之间进行多轮文本交接。

内置能力与用户 Skill 的选择、槽位冲突、缺失能力补位和失败回退服从 [[神思-Skill开放平台规则]]。路由先确定“本轮需要哪些能力”，再为每个槽位选择实现；不得先选 Skill 再让 Skill 反向决定任务类型。

## 爆款拆书双 Skill 路由

命中爆款拆书、拆文、完整作品逆向分析或爆款机制提取时，固定采用互补编排：[[skill/神思/bestseller-book-deconstruction/SKILL|爆款拆书 Skill]] 是唯一主控，负责来源覆盖、证据账本、结论边界、合并报告和改编依据；`01-oh-story-claudecode` 只作为专项拆解器参与。

- 长篇、整本、黄金三章或超过 20000 字的来源，调用 `story-long-analyze` 的长篇分析维度。
- 短篇、盐言、故事会或低于 15000 字的来源，调用 `story-short-analyze` 的短篇分析维度。
- 15000—20000 字先服从用户明确的作品定位；定位不明时根据章节结构和完成形态自适应选择，不用硬门中断。
- 两者必须合成为一份报告；不得把同一来源重复拆成两份互相冲突的结论。
- `01-oh-story-claudecode` 的原宿主命令、外部 Agent、浏览器、安装和固定路径写入不取得软件权限，只吸收分析方法。

## 五道可信运行门

正式创作在现有双核链内固定执行五道门，不新增用户可见板块：

1. **概念绑定门**：关键自造概念先绑定身份、剧情功能、可观察表现、当前解释程度和防普通化禁区。能够从材料确定时自动编译；只有低置信且会改变重大 canon、核心真相、人物命运或结局时才允许询问。
2. **叙事形态锁**：非线性、循环、碎片、不可靠叙事、梦境或象征结构必须锁定真实时序、呈现顺序、视角边界、认知锚点、信息释放顺序和禁止线性化项，并在写后检查是否被普通化。
3. **统一询问门**：只有可信内核可以向用户发出创作决策问题。主笔、顾问、自检和用户 Skill 只能提交缺口建议；缺口必须同时满足“确实缺失、无法合理推断、影响重大方向、尚未回答”才能展示。`直接写`、`必须直出`、`不要追问`使用户可见追问预算归零，但不跳过内部绑定和检查。
4. **文体组合校验门**：每轮冻结最终产物、作品/笔记模式、原创/改编来源、唯一主笔、允许引导、允许顾问、对应自检和禁止能力。同一正式产物不得出现两个主笔、原创与改编并存或异文体主笔串入。
5. **成品隔离门**：正式产物、内部检查、记忆增量、待确认项和返修约束必须分离。写作卡、动态胶囊、候选方案、自检报告、评分表、内部职责、规则名和运行字段不得进入正式成品；污染候选必须阻止落盘并定向返修。

五道门属于可信内核运行约束，用户 Skill 无权关闭、替换或宣告通过。

## 实时插槽拓扑编译规则

任务与资料路由的实时管理属于不可替换的可信内核，不属于任何 Skill 或插槽。软件必须由 `RouteTopologyManager` 在本地把固定插槽组、固定插槽、自定义插槽组、自定义插槽、Skill 绑定、启用状态和固定槽替换编译为带 `routeRevision` 与内容哈希的不可变路由快照。旧 Skill 即使声明 `task_router` 也不得取得任务识别、资料许可或路线更新能力。

固定执行顺序：

```text
读取同一版本的 Skill 注册表
-> 编译当前插槽树、继承边界与组权重
-> 本地匹配受控触发条件
-> 合并本轮 @Skill 与固定槽替换
-> 计算能力槽和资料读取许可
-> 把当次不可变快照交给可替换路由 Skill 作为只读数据
-> 执行能力协商、上下文编译与失败回退
```

硬规则：

1. 新建、替换、改名、移动、启停或删除插槽 / 插槽组后，必须递增 `routeRevision`。下一次任务不得复用旧拓扑；同一次任务内则冻结快照，避免执行中途漂移。
2. 外部任务路由 Skill 只能消费当次快照，不能缓存自己的插槽清单，不能忽略安装后新增的路线，不能自行扫描文件，也不能扩大资料读取范围。即使外部 Skill 没有理解新插槽，可信内核的本地触发匹配仍先于它完成。
3. 固定插槽组和固定插槽不可改名、移动或删除，只能替换其中 Skill 实现。自定义插槽和自定义插槽组可以改名、删除、拖拽移动并递归嵌套；拖入固定组时必须重新校验该组允许能力，并拒绝自身父级、祖先回指和其他循环结构。
4. 自定义组只组织路由，不授予权限。每个插槽必须且只能对应一项能力；Skill 自身可以声明多项能力，但绑定某插槽时只获得该插槽的一项授权。若同一 Skill 的多项能力均需启用，必须分别绑定到多个对应插槽。插槽允许能力由最近的固定祖先组约束；绑定 Skill 和插槽都必须声明目标能力，最终授权取二者交集。
5. 选择优先级固定为：本轮明确 `@Skill` > 命中自定义插槽（触发分数 + 继承组权重）> 固定插槽替换 > 默认 Skill > 开发者补位。显式引用提高选择优先级，不提高资料权威或文件权限。
6. `短视频赛道` 是组织型插槽组：`短视频通用理论` 为上位，账号 / 系列 / 细分类型方法为下位。命中下位时必须共同启用当前上位；上位 Skill 可以被测试通过的自定义 Skill 完整替换，替换后不得再叠加开发者上位。下位只有同时在 Skill 和插槽声明 `short_video_script_writer` 时才能替代短视频主笔，否则只作为理论顾问。
7. `公众号文章理论顾问` 是组织型插槽组：`公众号文章通用理论` 为上位，科普、社会观察、历史人文及后续品类理论为下位。命中下位时共同启用当前上位；替换上位仍保留命中的未替换下位，替换下位则保留当前上位并排除被替换的开发者下位。
8. `短篇小说理论顾问` 是组织型插槽组：`短篇小说通用理论` 为上位，题材、结构和风格等后续理论为下位。当前上位没有开发者 Skill 时必须显示空缺，不得拿创作引导、正文规则或短篇科幻题材理论冒充；绑定自定义上位后，仍可与另一个独立命中的题材理论共同参考。
9. `索引生成`、`资料召回`、`连续性与格式门禁`、`结构与落盘` 只存在于可信内核，不建立替换插槽。`记忆与信息台阶` 为小说和剧本共用规则，用户 Skill 最多提供只读建议，最终状态更新和落盘由内核完成。
10. 迁移旧版扁平自定义插槽时，必须保留 ID、名称、绑定、触发条件、能力边界和启用状态，再按能力归入最接近的固定组；无法安全归类时留在根级，不得删除或静默停用。
11. Skill 设置根页固定按 `固定插槽 -> 固定插槽组 -> 自定义插槽 -> 自定义插槽组` 排列。固定槽使用方形加号打开自定义 Skill 选择器，不使用下拉框；选择器顶部必须提供“新建 Skill”。
12. `拆爆款书` 是初始化自定义插槽，默认绑定开发者 Skill，显示在固定插槽组之后；停用或删除后不得自动触发，显式 `@Skill` 不受影响。
13. 插槽组必须声明为“并行结构”或“组织结构”。并行结构中的同级独占能力按优先级竞争；组织结构保存一个可替换的上位插槽和任意数量下位插槽，下位理论命中时由可信内核自动共同启用当前上位理论。固定组织组的上位插槽必须是组内直接插槽，界面持续显示并允许绑定测试通过的自定义 Skill；替换上位后开发者上位必须退出本轮上下文。组织关系只允许组合当前任务确实需要且已授权的顾问或可叠加能力，不得借机产生多个正文主笔、扩大资料权限或覆盖可信内核。
14. 路由快照缺失、哈希不一致、父子循环、绑定 Skill 不可用或能力越界时，只回退对应槽，不得让路由 Skill自由选择替代权限，也不得跳过可信内核门禁。

固定插槽组至少包括：

- `创作引导`：小说、短剧剧本、短篇小说、公众号文章、短视频剧本、提示词及自定义插槽。
- `主笔`：小说设定规划、小说正文、短剧原创、小说改短剧、短篇小说、公众号文章、短视频剧本、提示词及自定义插槽。
- `题材理论顾问`：小说与剧本共用题材、嵌套的短篇小说理论顾问、嵌套的公众号文章理论顾问、嵌套的短视频赛道及自定义插槽。
- `自检`：小说自检、短剧剧本自检及后续自定义文体自检。

| 职责 | 作用 | 边界 |
|---|---|---|
| 主笔模式 | 在创作核内生成正文、设定、大纲、剧本、提示词或资产。 | 同一正式产物只启用一个专项主笔模式。 |
| 效果检查 | 创作核检查目标情绪、人物、场景、兑现和追读效果。 | 默认一次聚焦复核，不加载全量自检矩阵。 |
| 记忆检查 | 记忆核检查 canon、因果、信息权限、连续性并提取增量。 | 只阻断硬冲突，不接管创作选择。 |
| 顾问 | 解释市场、类型、理论和疑难原因。 | 只在判断模糊或用户明确要求时调用。 |
| 管理 | 落盘、链接、状态、章节记忆、索引和日志。 | 不主写创作内容，只写入已确认事实。 |

## 主笔模式路由

### 自适应路由与运行中改道

任务路由输出的是推荐路线、置信度、允许调用的能力和改道条件，不是限制泛化能力的硬门。Chat 与 Agent 使用同一套任务语义；二者只在执行能力上不同：Chat 主要调用对话与神思能力，Agent 可按任务需要申请读取、命令或修改工具。是否调用工具由任务需要、证据和权限共同决定，不能由“Chat / Agent”标签或“是否启用创作引导”单独决定。

运行中必须根据实际证据复核初始路线：

- 稀疏创作声明优先推荐对应专项引导；若已经实际读取的项目资料足以形成当前产物，可高置信度改道主笔，不为了走完引导流程继续追问。
- 即使已经读取资料，用户若只是询问事实、概念、状态或区别，仍应改道通用回答；资料存在本身不等于创作授权。
- 即使最初被识别为普通问答，后续证据表明用户要求生成、改编、续写、诊断或落盘创作资产时，应改道对应神思能力。
- “项目中存在文件”、文件名、旧提示词或未打开的候选资料不能作为已读证据。改道必须说明来自用户本轮要求或实际读取资料的依据。
- 只有权限、canon 硬冲突、未解决的阻断型资料缺口和不可逆写入属于硬边界；创作引导、主笔、顾问和工具选择都允许在这些边界内动态调整。

### 新作品创作引导启动边界

出现“具体作品类型 + 创作求助意图”时，必须先按最终产物选择对应专项引导，不得归入通用问答，也不得统一套用小说[[创作引导]]。只有最终产物属于小说且创作意图仍不充分，或最终产物尚未明确时，才进入小说通用[[创作引导]]。具体作品类型包括但不限于女频文、女频虐文、女频爽文、男频文、男频爽文，以及玄幻、仙侠、都市、悬疑、科幻、末世、古言、现言、宫斗、宅斗、甜宠、虐恋、追妻火葬场、真假千金等明确题材。创作求助意图包括“我想写”“我要写”“我需要创作”“准备写”“不知道怎么开始”“应该怎么构思”“帮我设计”“有什么创作建议”等表达。

固定边界：

- “我想写个女频虐文”“我要写一本女频复仇爽文”“我需要创作一部长篇悬疑小说”“男频爽文应该怎么构思”属于新作品创作求助，先进入[[创作引导]]并只追问一个最能确定核心看点的问题。
- “我想写公众号推文”“我想做短视频剧本”“我想写短篇小说”“我想做视频提示词”分别进入[[推文创作引导]]、[[短视频创作引导]]、[[短篇小说创作引导]]、[[提示词创作引导]]，不进入小说通用[[创作引导]]。
- 最终产物对应的最小创作合同已经具备时，直接调用对应主笔或写作 Skill，不为了完成引导流程继续追问。公众号、剧情短视频、短篇小说和提示词的“信息充分”必须由专项引导的必需决策簇、看点增强讨论和最终确认共同判定；只有主题、题材、风格词或单个素材点不算充分。
- “我要写”只是创作意图声明，不等于授权立即生成正文；只有“我要你直接写”“直接写”“不要追问”“无需追问”“全自动”等明确执行指令才进入对应创作主笔模式并跳过追问。
- “女频文是什么意思”“女频文和男频文有什么区别”“推荐几部女频虐文”等知识、比较或检索问题属于通用问答，不启动创作引导。
- 不能仅凭“女频”“男频”或题材名称启动创作引导，必须同时存在创作、构思、开始或求助意图，避免知识问答误触发。

### 最终产物专项创作引导

无论当前处于作品模式还是笔记模式，只在用户确实进行对应创作且信息存在关键缺口时，按最终产物启用一个专项引导。当前打开的文档和目录只提供上下文，不得覆盖用户明确指定的最终产物：

| 创作行为 | 引导入口 |
|---|---|
| 公众号文章、公众号长文、推文 | [[推文创作引导]] |
| 单条剧情短视频、剧情号、AI 剧情短片 | [[短视频创作引导]] |
| 短剧、微短剧、竖屏短剧、真人短剧、漫剧剧本及其全集 / 剧集大纲 | [[短剧剧本创作引导]] |
| 短篇小说、短篇故事 | [[短篇小说创作引导]] |
| 视频、分镜、漫剧、图片资产、站位或全景调度提示词 | [[提示词创作引导]] |

普通笔记、知识问答、资料整理、摘要和机械处理不启用任何创作引导。创作引导采用以下固定回路：

```text
识别最高影响缺口
-> 给出 2—3 个可比较方向、成品影响与明确推荐
-> 每轮只问一个决策问题
-> 把回答合并进创作合同状态
-> 重新计算缺失决策簇
-> 基础合同完整后讨论一次看点增强
-> 展示压缩后的最终合同并确认
-> 调用对应主笔、效果检查与必要返修
```

“每轮只问一个”不等于“总共只问一个”。用户回答后仍有必需决策簇缺失时必须继续下一轮，不得把一次回答误判成完整授权；已经确认或明确委托系统决定的内容不得重复追问。用户说“直接写”“必须直出”“直接转换”“不要追问”“按现有信息生成”时跳过用户可见回路，以临时创作合同直接执行，但不跳过后续质量与安全门禁。

[[提示词创作引导]] 同时适用于作品模式：已有剧本且转换要求明确时直接使用专项提示词 Skill，不启动追问；当用户指出转换结果的站位、动作、运镜、景别、光源、质感或整体效果不到位时再启用，引导补齐最关键的视觉控制量。

短剧与漫剧的最终产物优先级高于当前打开文档和来源材料。只要最终交付明确为原创短剧、改编短剧、漫剧剧本、短剧全集大纲、剧集大纲或单集剧本，就必须进入 [[短剧剧本创作引导]] 或对应剧本主笔，不得归入小说创作引导和小说正文主笔。原创 / 改编来源模式必须保存到当前会话目标与剧本文档元数据；后续“继续写”“接着写第一集”等省略表达继承该状态，主笔选择、规则包与自检必须使用同一个来源模式。

创作核是统一生成运行时，不替代专项格式和媒介规则。专项规则只把当前任务需要的领域约束注入动态创作胶囊。

拆书分析模式属于研究资料生产，不属于原创主笔、改编主笔或正史管理。软件必须先建立来源覆盖清单，再按章、集、场或段落分块拆解并综合；未覆盖全部来源时只能交付“样本拆解”。结果可落盘到笔记，或作品 `08_资料库/参考资料/` 作为改编依据，不得直接回写设定、状态、记忆、正文或大纲。

短剧术语与流程补充：原创短剧使用“小说级剧情母本 -> 原创短剧专项自检 -> 原创剧本设定域 -> 全集大纲 -> 详细剧集大纲 -> 单集正式剧本”；小说改编使用“原著剧情颗粒拆解 -> 全集大纲 -> 详细剧集大纲 -> 单集正式剧本”。全集大纲是短剧整季总控；剧集大纲是逐集详细规划，不得与小说章纲混用。试写、样集和指定单集试作可以豁免完整全集大纲，但不能跳过最小剧情母本、本集总控与逐场剧情链。

剧情短视频理论补充：抖音剧情号、单条剧情短视频、连续剧情号和 AI 剧情短片，先由 [[短视频剧本创作理论|短视频剧本类型识别与理论路由]] 判断内容形态；未命中细分方向时加载 [[skill/神思/短视频剧本创作理论/general-short-video-screenwriting/SKILL|短视频剧本通用创作概论 Skill]]，再由独立短视频剧本主笔和短视频效果自检完成。普通单条剧情视频不得默认读取原创短剧 Skill。只有用户明确要求连续微短剧、竖屏短剧、分集剧情、剧集大纲或多集剧本时，才进入或追加原创 / 改编短剧故事引擎。

原创短剧顶级模式补充：当用户要求顶级、人类编剧水平、爆款、投流、投稿、平台重点项目、满血终稿，或自检发现“结构合格但普通”时，原创短剧模式必须追加 [[skill/神思/original-short-drama/references/top-tier-benchmark|顶级短剧样本标尺]] 与 [[skill/神思/original-short-drama/references/rewrite-ladder|短剧四轮重写机制]]。四轮代表四个审阅域，不代表正文必须机械重写四遍；某一轮没有可证明的净增益时允许不改，任一轮损伤人物、因果、信息梯度、声音或关键过程时必须回退。该模式只能称为“冲顶级流程”，不得承诺自动稳定达到顶级人类编剧水平；原创卖点、终局价值选择、核心关系不可逆变化、尺度与制作成本仍需用户或人类总编拍板。

## 默认检查路由

标准正式任务默认只执行：

1. 创作核效果复核。
2. 记忆核硬冲突检查与记忆增量。
3. 只要成品含正式叙事正文，强制执行 [[神思-正文高频表达限制与语境裁决规则]] 的开头、语境配额、固定模板和近期复用闸门；它属于基础门禁，不等待专项或满血触发。
4. 强制执行 [[神思-正文质量净增益与防退化规则]]：先识别章节任务、叙事模式和受保护资产，再检查内容唯一性、关键过程、正式产物纯净度与修改前后质量差；无法证明净增益时保留原文。

专项自检发现问题后，必须按 [[神思-Skill开放平台规则]] 的统一问题协议去重、合并成一张带证据的最小返修单，再由唯一返修责任方交给创作核；不得让多个自检依次重写正文，也不得把完整检查报告塞回起草上下文。用户效果主审可以替换通用创意量表，题材自检可以叠加，但权威连续性、信息权限、基础格式、质量净增益和安全门禁始终由内核执行。

强闭环中的自检问题必须使用 [[神思-分级闭环与规则包规则]] 的结构化自检协议输出；标准链只保留最小返修约束；轻链只给必要修改点。

## 顾问边界

顾问通常不是默认步骤。题材顾问例外：标准创作任务一旦识别出已有理论覆盖的明确题材，就从规划阶段启用；没有任何已接入理论覆盖当前题材，或用户明确要求关闭题材理论时不启用。理论按“通用理论 -> 上位类型 -> 细分类型”组合：细分理论存在时仍参考通用和上位理论；只有上位理论命中时使用通用与上位理论；二者均未命中时不调用题材理论。其他顾问仍只在自检结论模糊、修法存在分歧或用户明确要求时调用。

- `story` 与 [[小说类型理论研究|小说类型识别与理论路由]]：市场、类型承诺和读者期待。
- [[公众号文章创作理论|公众号文章类型识别与理论路由]]：公众号内容方向、读者承诺、证据结构与传播机制；命中明确方向后只加载一个主类型 Skill。
- [[短视频剧本创作理论|短视频剧本类型识别与理论路由]]：剧情短视频的内容形态、观看问题、状态变化、情绪兑现和制作适配；不替代原创 / 改编主笔或剧本自检。
- `theory-advisor`：由 [[skill/神思/小说写作技能skill/04-webnovel-theory-engine/SKILL|网文通用理论顾问]] 解释人物驱动、剧情循环、信息团和结构疑难。
- [[神思-商业判断与自动审稿增强规则]]：评分、硬性失败项和读者模拟。

顾问默认不得担任正式主笔；唯一例外是 `短视频赛道` 组中的账号 / 系列方法同时由 Skill 与插槽声明 `short_video_script_writer`，此时可以替代短视频共性主笔。任何顾问都不得覆盖 canon，最终方案必须回到创作核和记忆核裁决。

## 多章与多集

多章或多集正式生产按顺序运行：每个单元生成、效果复核、记忆增量后，下一单元立即使用更新后的胶囊继续。普通单元不等待用户确认。

只有重大 canon、主角命运、核心真相、结局、重大关系转向或明确禁区出现分叉时，暂停并交给 [[创作引导]]。

## 管理边界

- 已确认事实才能写入正式 `01_剧情控制/`、`02_正史设定/`、`03_状态快照/` 和对应正文单元的后台连续性增量。
- 未确认、冲突、试作和理论建议进入候选稿、待确认或待确认更新；只有用户明确要求长期保留多套并行方向时，才按需创建 `08_资料库/备选方案/`。
- 大框架调整必须按 [[神思-结构化管理规则]] 先备份。
- 具体作品的同名结构文档使用完整路径加显示别名。

## 兼容标签

`chinese-novelist-skill`、`webnovel-plan`、`webnovel-write`、`story` 和 `theory-advisor` 等名称继续保留为历史或兼容标签。默认双核运行不依赖存在同名外部命令；需要实际入口时读取 [[神思-执行入口映射表]]。

若明确启用 webnovel-writer，按 [[神思-webnovel-writer运行边界规则]] 将双核胶囊适配为外部任务输入。未启用时不得要求其 artifact。

## 禁止越权

- 创作核不得改写已确认 canon 或越过信息权限。
- 记忆核不得把保守偏好当硬规则，不得主写正式产物。
- 专项自检不得建立第二套常驻 reviewer。
- 顾问不得覆盖用户审美裁决。
- 管理不得从摘要反推并写入核心事实。
- 多章生产不得跳过单元间记忆增量。
