# 神思-结构化目录模板

状态：正式生效。

用途：保存标准作品目录和多媒介作品目录示例。本文只提供目录模板，不裁决 canon，不负责具体入库。

## 软件展示规则

下列目录树描述的是标准物理落盘结构；软件左侧展示可以按职责压缩一层。固定且只有一份的文档直接显示在所属板块根部，例如 `人物设定.md`、`人物关系.md`、`当前状态.md`、固定聚合报告和 `项目规则.md`。只有实际已有多份合法文档、存在子目录、属于明确可增长资料集合，或单文档超过 60,000 个有效字符时才显示分类文件夹。`版本草案` 与回收站不属于资料库；回收数据保存在内部 `.shensi/recycle-bin/`，只由独立回收站入口访问。

软件左侧顶层只展示“正文、大纲、设定、记忆、作者驾驶舱、资料库”。“作者驾驶舱”在界面层合并原“编译报告”和“索引”的可见内容：项目总览映射 `07_编译报告/当前编译状态.md`，创作合同映射 `09_索引/项目规则.md`，待决策映射 `09_索引/待确认事项.md`，检查与报告集合 `07_编译报告/` 中全部当前有效报告，最近变更映射 `09_索引/更新日志.md`。这是只读投影与原文导航关系，不创建 `作者驾驶舱/` 物理目录，不复制 Markdown，也不改变下列标准落盘结构。

## 其他目录

`10_其他/` 用于保存创作者查阅型、辅助型、索引视图型文件。它不承担 canon、剧情控制、正史设定、状态快照、正文源文件、章/集后台连续性增量、动态上下文、编译报告或资料库职责。

适合放入 `10_其他/` 的文件：

- `当前正式可用章节.md`
- `当前分卷结构.md`
- 临时阅读清单、创作者查阅索引、非 canon 的汇总视图。

硬规则：结构化作品根目录不得自动落盘预计外 Markdown 文件。新增文档必须先判断职责；能归入既有职责目录就归入对应目录，不能归入且只服务创作者查阅时才进入 `10_其他/`。`10_其他/` 中内容不得被当作正史、状态或正文源。

多媒介产物管理规则：

| 产物 | 标准位置 | 说明 |
|---|---|---|
| 小说正文 | `04_正文/小说/` | 长篇正文主产物；分卷目录必须放在此目录下，不得直接挂在 `04_正文/` 根下。 |
| 短剧剧本、漫剧剧本、AI 仿真人剧本 | `04_正文/短剧/短剧剧本/` | 剧集大纲、改编取舍表和分集剧本统一管理。 |

| 视频提示词、分镜提示词、漫剧提示词 | `04_正文/短剧/视频提示词/` | 必要时按集、按场或按镜头拆分。 |

| 创作者查阅型辅助视图 | `10_其他/` | 只作阅读、索引和汇总辅助，不作为 canon 或正文源。 |

## 编译报告聚合规则

`07_编译报告/` 默认保留四个聚合报告：

- `小说自检.md`：小说正文、连续性、商业追读评分、禁用词、信息权限、OOC、伏笔风险等小说相关检查统一写入此文件。
- `剧本自检.md`：短剧剧本、剧集大纲、漫剧前置剧本、AI 仿真人剧本等剧本相关检查统一写入此文件。
- `小说改剧本编译报告.md`：记录小说到剧本的改编范围、具体改动、改编思路、连续性风险和待确认事项。
- `当前编译状态.md`：由软件根据当前已落地项目实时覆盖更新，汇总全集大纲、卷纲、章纲、正文卷数与实质章节数、正史设定分类与条目、连续性资料及剧本推进状态；它不是追加式日志，也不作为 canon。

不得为每个检查项目无限细分目录，例如 `连续性检查/`、`短剧逐集自检/`、`商业追读评分/`、`自动审稿/`、`伏笔风险报告/`。如果只检查某一项，就在聚合报告中记录该单项；如果只检查部分章节或部分集数，就只显示已检测范围；后续新增单项、章节、集数或全量检查时，在同一聚合报告中追加或更新。正文、剧本或规则发生新改动后再次自检，覆盖同一对象的旧结论，保留最新有效报告。

上述四个聚合报告必须全部集合到作者驾驶舱的“检查与报告”区域。作者驾驶舱可以显示运行时状态、风险摘要和导航卡片，但这些都是来源文档的动态投影，不得额外生成重复报告或把展示摘要反向写回 canon。

剧本大纲、剧本设定、剧本连续性、剧本正文和全部提示词资料不得反向污染小说 canon 或小说正文上下文；只有用户确认、已确认正文或明确授权入库的事实，才能同步到 `01_剧情控制/`、`02_正史设定/`、`03_状态快照/` 或对应小说正文单元的后台连续性增量。
