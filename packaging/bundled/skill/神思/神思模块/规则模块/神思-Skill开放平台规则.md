# 神思-Skill开放平台规则

状态：正式生效。

适用：内置 Skill、我的 Skill、Skill 广场、`@Skill`、默认能力配置、能力替换、自检替换、能力缺失补位和失败回退。

## 平台定位

神思是“可信内核固定、创作能力可替换、顾问能力可叠加、结果必须通过硬门禁”的开放创作平台。软件替换的是具名能力槽，不是内部 Markdown 文件。一个能力包可以由多份规则、量表和模板组成，安装、启用、冻结、测试、回退时必须作为整体处理。

## 不可替换的可信内核

- 任务意图、产物类型、阶段、任务路线、资料路线和实时拓扑编译。
- 创作引导的轮次控制、阻断项判断、直出终止和答案保存。
- 上下文读取计划、来源身份、预算、截取、去重和读取清单。
- 当前正文、正史、状态、记忆、草案、参考资料的权威级别。
- 权威连续性门禁、基础格式门禁、输出协议与证据校验。
- 结构化管理、canon 闸门、事务落盘、版本、恢复和安全。
- 状态、章节记忆、伏笔、信息台阶、索引和上下文包回写。

外部 Skill 可以发现疑似连续性问题或增加格式标准，但不能关闭、替换或宣称已经完成上述能力。

## 可替换能力槽

Skill 的“能力板块”是能力声明，可以同时勾选多项，表示该 Skill 在不同职责上都可接受独立测试和授权。插槽是单一职责授权：每个固定插槽或自定义插槽必须且只能对应一项能力，不存在复合型插槽。同一个多能力 Skill 若在多项能力上都通过测试，可以分别绑定到多个单能力插槽；每次运行只按当前命中插槽裁剪授权，不能因为 Skill 自身声明了其他能力而一并获得。

| 槽位 | 能力声明 | 组合规则 |
|---|---|---|
| 创作引导内容 | `creative_guidance` | 每种产物一个主引导；内核继续控制追问边界。 |
| 故事与大纲规划 | `story_planner` | 一个主规划；缺失时内置规划补位。 |
| 设定规划 | `setting_planner` | 一个主规划；不能直接写正史。 |
| 正文或分类主笔 | 对应 `*_writer` | 每项正式产物只能有一个主笔。 |
| 创意效果主审 | `effect_reviewer` | 一个主审；替换通用审美量表，不替换硬门禁。 |
| 题材附加自检 | `genre_reviewer` | 可以叠加，不能取消通用效果验收。 |
| 连续性顾问 | `continuity_advisor` | 只能提出疑似冲突，由内核裁决。 |
| 返修主笔 | `repair_writer` | 消费结构化问题清单，执行最小范围返修。 |
| 附加格式标准 | `format_extension` | 可以增加要求，不能关闭基础格式校验。 |
| 理论、风格、知识顾问 | 顾问类能力 | 可以叠加，不取得主笔权和 canon 权。 |

## 能力协商与回退

1. 先由内核根据模式、产物、阶段和当前任务计算所需能力。
2. 用户本轮明确 `@Skill` 高于命中的自定义插槽；自定义插槽高于作品或分类默认；都未命中时使用内置能力。
3. 同一独占槽只选择一个能力包；题材审查、格式扩展和顾问允许叠加。
4. 外部 Skill 缺少规划、自检、返修或其他所需能力时，由内置能力逐槽补位，不允许把缺失能力交给模型自由发挥。
5. 外部 Skill 声明未授权能力、测试失败、版本不兼容、输出协议无效或运行结果不可解析时，屏蔽对应能力并回退内置能力。
6. `@Skill` 只影响本轮获准槽位，不改变可信内核、其他槽位和长期默认配置。
7. 多能力 Skill 被绑定到某个插槽时，只授权该插槽的一项能力；需要承担另一项能力时，必须再次绑定到另一个对应插槽并独立参与该槽竞争。

## 用户自定义插槽

用户 Skill 可以在设置中开启“自定义插槽”，使其不经本轮 `@Skill` 也能在满足声明条件时自动参与能力协商。

设置界面分为固定插槽、固定插槽组、自定义插槽和自定义插槽组。固定项由开发者维护，不可改名、移动或删除；固定槽通过方形加号打开自定义 Skill 选择器，选择器顶部允许新建 Skill。自定义插槽可以拖入能力兼容的固定组或自定义组，移动后必须重新编译路由。`拆爆款书` 是默认创建的自定义插槽，不是固定槽；任务与资料路由不显示为任何插槽。

自定义插槽只能选择一项能力。多能力 Skill 不允许通过“设为自定义插槽”自动合并成复合插槽；用户应按实际需要创建一个或多个单能力插槽，并在每个插槽中分别绑定该 Skill。旧版复合插槽升级时按原能力逐项拆分，保留原 Skill 绑定、触发条件、使用模式、组位置和启用状态。

自定义插槽组创建时必须选择组属性：

- 并行结构：同级插槽相互独立；独占能力按优先级只选一个，可叠加能力按原协议组合。
- 组织结构：设置一个上位插槽，下面允许无限增加下位插槽或子组。任一下位理论命中时，可信内核自动带上该上位理论；提示上下文按上位在前、细分在后排列。没有下位命中时，上位插槽仍按自己的触发条件决定是否启用。

组织关系不增加任何权限。上位和下位 Skill 必须分别通过能力声明、触发条件、工作区和当前任务所需能力校验；正文主笔、规划主笔等独占能力仍只能选择一个，组织结构不能制造“领导主笔 + 员工主笔”的多主笔冲突。

1. 自定义插槽只是一种受控启用方式，不是新的权限类型。自动命中的 Skill 仍只能进入自身声明且被当前任务需要的能力槽。
2. 开启前必须满足：Skill 已启用、测试通过，并在当前活动版本的 frontmatter 中声明至少一项 `trigger_keywords` 或 `trigger_conditions`。
3. 自动匹配必须发生在正式任务分类和能力分配之前，但不能替代任务路由。路由仍由可信内核根据用户最终交付物裁决。
4. 触发关键词采用不区分大小写的完整子串匹配；存在多个关键词时命中任意一个即可。关键词不得短于两个字符。
5. 触发条件只允许声明式字段，不接受正则、脚本、模型自由判断或文件探测。支持：`workspace`、`module`、`domain`、`deliverable`、`document_prefix`、`text_all`、`text_any`。
6. 同一 Skill 同时声明关键词和条件时，必须满足“至少命中一个关键词，并且全部条件成立”。多条普通条件之间为 AND。
7. 多个自动 Skill 命中同一独占槽时，按触发具体度、本地评分和安装时间稳定排序，只选一个；题材审查、格式扩展和顾问仍可叠加。
8. 同一 Skill 同时被 `@Skill`、默认配置和自动条件命中时只加载一次，并保留最高优先级来源。
9. 匹配但能力不适用于当前任务的 Skill 进入未激活集合，不读取正文，也不作为辅助提示注入模型上下文。
10. Skill 更新版本、测试失败或被停用后，不得继续自动运行；新版本需要重新测试并重新开启自定义插槽。

示例：

```yaml
trigger_keywords:
  - 民俗悬疑
  - 规则怪谈
trigger_conditions:
  - workspace:project
  - module:manuscript
  - domain:novel
```

## 自检统一协议

创意自检必须返回：通过状态、覆盖清单和结构化问题。每个问题至少包含稳定代码、严重度、检查维度、原文证据或明确位置、诊断、最小返修要求。资料缺失、截断或未读取必须写入覆盖清单，不得伪造完成度。

```yaml
pass: false
coverage:
  read: [当前章纲, 上一章, 当前状态]
  missing: []
  truncated: []
findings:
  - code: PACING_STALL
    severity: major
    dimension: 节奏
    evidence: 原文或明确位置
    diagnosis: 冲突启动后没有产生局势变化
    repairInstruction: 压缩说明并提前关键阻碍
```

硬格式、正史、信息权限、记忆证据、文件权限和安全结果不进入可替换创意量表，始终由可信内核独立验证。

## 版本与测试

新版能力包使用 `schema_version: 2`；旧版 `schema_version: 1` 继续兼容为传统主笔或顾问。设为默认前必须通过元数据、权限、输出合同、虚构材料沙箱和失败回退测试。每轮冻结实际使用的 Skill 版本和哈希；任务中途升级不得改变本轮行为。

第一版只允许 Markdown 指令型 Skill，不允许脚本、程序、任意网络或文件访问。Skill 只能读取内核为当前阶段编译的上下文，不能自行扫描作品目录。
