# 神思-Skill开放平台规则

状态：正式生效。

## 定位

Skill 面板描述 Agent 当前可以调用的能力、能力之间的关系和可用边界。面板不预先决定任务类型或固定执行流程；Agent 按 [[神思任务路由]] 理解完整意图后，从实时面板选择本轮真正需要的 Skill。

用户导入、创建、启用、停用、拖拽、替换和恢复 Skill 的手动功能全部保留。Agent 也可以在权限范围内调用相同管理能力，但不能跳过安装验证、面板历史和真实回执。

## 面板层级

- 面板：当前唯一生效的能力版图。
- 模组：组织一类作品或一组相关模块。
- 模块：组织一组 Skill 插槽及其关系。
- 插槽：保存完整 Skill 绑定及其能力、适用范围和身份。

同一模块内部只允许插槽互换、排序；同一模组或面板内部只允许成员互换、排序。不得把成员拖入另一个模块或模组。交换整个插槽或节点对象，不只交换 `skillId`，避免能力约束、身份和配置分离。

## 三种关系

- 并行：成员同级，可独立调用或按任务需要协作。
- 主次：第一位是主要成员，其余是次要成员；Agent 通常优先主要成员，但完整任务语义明确需要其他能力时可以选择次要成员。
- 组织：第一位是上位成员，其余是下位成员；调用下位成员时，上位成员负责组织本轮协作。

关系角色来自真实数组顺序，不来自 DOM 顺序或颜色。拖拽交换和排序后统一重算角色并验证结构，下一轮路由立即使用新角色。内置锁定节点继续禁止移动。

## 能力与路由

- Skill 只能使用自身登记且验证通过的能力；多能力 Skill 在每个插槽中仍按该插槽的实际能力边界运行。
- `@Skill` 表示用户本轮明确指定，Agent 应在适用边界内优先考虑，但它不改变文件权限、作品隔离或事务规则。
- 名称、题材词、`trigger_keywords` 和标签只用于检索、兼容导入和帮助 Agent 理解，不得单独决定任务类型、Skill 选择、资料读取或写入方式。
- `trigger_conditions` 可以描述工作区、交付物和适用范围，Agent 必须结合完整上下文判断，不能把声明式字段当成机械门禁。
- Skill 不适配、不可用或测试失败时，Agent 选择其他真实可用能力或明确报告缺口，不伪造调用成功，也不因空插槽阻断无关任务。
- 需要多个候选时用文字描述数量和差异，保留多候选；不询问主笔身份或主笔数量。

## 保存、历史与防退化

保存面板时先验证拓扑、关系、插槽身份和可调用性，再生成完整面板历史版本。随后使用用户当前文字模型生成简短动态路由候选，候选必须同时满足：

1. route revision 与保存后的面板一致。
2. topology hash 精确一致。
3. 正确表达面板中的并行、主次和组织关系。
4. 不包含旧路由文件名、关键词裁决、必读清单、固定流程或主笔数量向导。
5. 不修改可信面板拓扑，不把模型输出当成面板事实。

校验全部通过后才激活动态路由，并把模型、正文哈希、revision、topology hash 和审计结论绑定到任务路由历史。失败时保留上一个有效路由并向用户显示具体原因。恢复历史面板时同步恢复对应动态路由；历史版本没有正文时回退静态 [[神思任务路由]]。

## Skill 包与自检

Skill 包安装前检查元数据、路径、内容边界和危险行为；安装后必须通过当前版本验证才可参与路由。开发者个人作品、测试作品、凭证、日志、缓存和运行产物不得进入应用能力包。

自检 Skill 应给出实际检查范围、真实读取资料、结论和可执行问题。资料未读、为空或范围不足时如实说明，不把预计读取冒充实际读取，不把普通局部检查冒充全文通过。报告落盘遵循 [[神思运行规范]] 和结构化管理规则。
