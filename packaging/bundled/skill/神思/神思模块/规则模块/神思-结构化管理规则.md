# 神思-结构化管理规则

状态：正式生效。

适用：作品建档、结构化入库、路径规范、链接消歧、设定更新、索引维护、状态快照、章/集后台连续性增量、动态上下文和编译报告。

本文件是结构化管理总则，只保留职责、canon 边界和三档闭环。具体目录模板、链接写法、入库回写和执行手册分别读取对应子文档。

## 核心原则

- [[神思]] 是创作决策系统，默认按 [[神思-双核运行规则]] 编排。
- 创作核负责产物效果，记忆核负责最小上下文、连续性和状态增量。
- 正史设定是长期事实库。
- 状态快照是当前运行内存。
- 章/集后台连续性增量是随对应正文单元保存的历史提交摘要。
- 动态创作胶囊是每轮临时编译的最小充分输入，不落盘，不是第二套事实源。
- 编译报告是自动测试结果。
- 作者拥有最终 canon 裁决权。

## 职责边界

| 职责 | 主要内容 | 是否能改 canon |

| 创作核 | 候选竞争、生成正式产物和效果复核。 | 只能提出内容，不能越过 canon 闸门。 |
| 记忆核 | 编译动态创作胶囊、检查硬冲突、提取记忆增量。 | 只能整理已确认事实和标注待确认，不主写 canon。 |
| 主笔 | 生成正文、设定、大纲、剧本、提示词或资产。 | 只能提出内容，不能越过 canon 闸门。 |
| 自检 | 检查追读、节奏、OOC、设定冲突、信息权限和文本问题。 | 否 |
| 顾问 | 提供市场、类型、理论、原因解释和诊断依据。 | 否 |
| 管理流程 | 入库、链接、状态维护、章/集后台增量、待确认事项和更新日志。 | 只能写入已确认事实。 |

管理流程不得补写核心创作内容；需要补写时必须路由回对应主笔或规则。

## canon 入库边界

| 内容状态 | 默认位置 | 规则 |
|---|---|---|
| 已确认事实 | `01_剧情控制/`、`02_正史设定/`、`03_状态快照/`、正式正文及其后台连续性增量 | 来自用户确认、已确认正文或明确授权入库。 |
| 待确认事实 | `09_索引/待确认事项.md`、临时结构化更新包 | 可供后续参考，不得覆盖正史。 |
| 草案 | 候选稿、临时草案包、`09_索引/待确认事项.md`，或按需创建的 `08_资料库/备选方案/` | 新项目试作和 AI 首轮生成默认不落盘；只有用户明确要求长期保留多套并行方案时才创建备选方案。 |
| 拆书与对标研究 | `08_资料库/参考资料/《作品名》爆款拆书报告.md` | 非 canon 研究资料；允许按被拆作品建立完整报告，改编时可引用但必须回查原作。 |
| 废弃/冲突 | `08_资料库/废弃设定/` 或 `09_索引/待确认事项.md` | 保留来源和废弃/冲突原因。 |
| 不涉及 canon | 诊断报告、格式检查、任务分工查询 | 不产生作品事实。 |

硬规则：未确认内容不得伪装成正式正史；如果为测试临时放入正式目录，文件开头必须标注“草案 / 待确认”，并记录到待确认或更新日志。

## 标准结构

正式长篇作品使用 [[神思-结构化目录模板]]。旧根目录 `剧情控制/`、`设定/`、`正文/`、`资料库/`、`索引/` 不得再作为新建、补档、测试或临时输出位置。

正史设定默认采用分类聚合板与标题锚点，不采用“分类文件夹 + 每实体一个文件”的原子化结构。单个人物、地点、物品、势力、概念、规则、事件只有在用户明确要求，或内容已经形成独立版本周期、复杂子结构和长期高频维护需求时才能独立成文；不得以“检索更方便”为由拆分，因为运行时已经支持标题、稳定 ID 和段落级召回。

### 软件目录展示层级

软件左侧目录树不必逐层复刻 Markdown 的物理目录。一个分类当前只有一份文档时，直接在当前板块根部显示该文档，不再因为未来可能增加内容而预先套一层同名文件夹。只有已经存在多份合法文档、已经存在子文件夹、属于明确可增长的资料集合，或单份聚合文档超过 60,000 个有效字符时，才显示分类文件夹并进入结构化拆分评估。

`人物设定.md` 与 `人物关系.md` 是两个相互独立的根级聚合文档，不得再放入共同的“人物设定”文件夹。其他固定聚合板、`当前状态.md`、四份固定聚合报告和 `项目规则.md` 同样直接显示；剧情控制账本、项目维护，以及卷、章、分集、提示词和参考资料等实际多项或可增长集合继续使用文件夹。显示层扁平化不得复制正文或 canon，也不得改变运行时读取和落盘裁决；达到 60,000 字符阈值只触发分类管理与拆分评估，真正拆分时仍必须按稳定实体边界事务式迁移，禁止机械截断。

### 作者驾驶舱展示契约

软件界面不再把“编译报告”和“索引”作为两个并列的顶层板块；二者在展示层合并为唯一的“作者驾驶舱”。作者驾驶舱是动态投影视图，不是新的 Markdown 目录、文档或事实源。物理落盘仍保持 `07_编译报告/` 与 `09_索引/` 两套职责目录，稳定文档 ID、完整路径、版本历史、canon 权限和运行时读取规则均不得因界面合并而改变。

作者驾驶舱至少汇总：项目总览、创作合同、待决策、风险与连续性、检查与报告、最近变更。映射关系固定如下：

- “项目总览”读取派生文档 `07_编译报告/当前编译状态.md` 与运行时完成度指标。
- “创作合同”是 `09_索引/项目规则.md` 的项目资产视图，不得再生成第二份合同文档；其中“项目禁用词”和“特别注意事项”的既有确定性作用保持不变。
- “待决策”读取 `09_索引/待确认事项.md`，只有作者确认后才能进入正式 canon 或来源文档。
- “风险与连续性”由当前结构缺口、连续性覆盖、记忆证据和待处理报告动态计算，不落盘为新的风险汇总文档。
- “检查与报告”必须集合 `07_编译报告/` 中全部当前可见聚合报告；不得在驾驶舱外再保留另一个可见报告入口，也不得复制报告正文。
- “最近变更”读取 `09_索引/更新日志.md`。

左侧作品模块因此只展示“正文、大纲、设定、记忆、作者驾驶舱、资料库”六个顶层入口。内部能力注册表仍可保留 `reports` 与 `index` 两个职责域，以保证任务路由、权限、落盘和历史恢复精确；界面合并不得把索引维护能力授权给报告模块，也不得把报告结论当作项目规则。

资料库只承载当前有效的外部资料、拆书报告、对标研究，以及明确隔离的废弃设定。`版本草案` 不属于资料库；旧工程中的 `library-drafts` 在移出活动结构前保存一份作品历史快照，之后不得进入目录树、全文召回或上下文编译。回收站是文件恢复机制，不是资料分类；界面只保留独立回收站入口，物理数据保存在 `.shensi/recycle-bin/`，不得在 `08_资料库/` 中建立回收站文档、索引或文件夹。

### 单实体读取与虚拟档案契约

“禁止短原子文件”只约束物理存储，不限制逻辑上的单实体读取。用户要求读取、分析、续写或检查某一个人物、物品、地点、势力、概念、规则、事件或伏笔时，必须执行以下顺序：

1. 在对应分类聚合板中定位实体标题、标题锚点或稳定 ID，只召回该实体分节至下一个同级标题之前，不把整份聚合板无差别注入模型。
2. 如果任务只需要稳定设定，到此结束；不得为了本轮读取临时创建实体文件。
3. 如果任务需要“完整当前档案”，运行时动态拼装虚拟档案：实体正史分节 + 对应 `[STATE:id]` 当前状态 + 直接相关的关系、信息权限、伏笔和最近必要记忆。
4. 虚拟档案只存在于本轮读取计划和动态创作胶囊中，必须在读取清单中列明来源、命中分节和截取状态；任务结束后不保存为第二套 canon，不反向覆盖来源文档。
5. 某来源没有该实体相关内容时应省略，不得用无关人物、整张大表或整份长文档填充上下文。

这套关系统一表述为：**物理存储采用分类聚合板，逻辑读取采用单实体分节，跨职责资料采用运行时虚拟档案。**

独立建档不是检索手段。只有用户明确要求，或该实体同时具备内容已无法在聚合板中稳定维护、拥有独立版本周期、包含大量专属子结构且需要长期高频维护等条件时，才允许迁为独立文档。迁出后聚合板保留摘要、稳定 ID、正式链接和迁出理由，禁止保留两份并行正文。

结构健康硬线：同一设定分类内若超过半数文档不足500字，或连续出现5份以上只描述单一实体的短文档，必须判定为过度原子化并收拢；空壳索引、只转链不承载职责的中间文档、迁移备份和已被新版报告覆盖的旧诊断不得留在活动扫描范围。

多媒介作品仍以单个作品目录为主，不另建作品外的全局剧本库。小说正文和短剧链路同属该作品的表达层产物，但必须分层管理：小说正文统一归入 `作品/作品名/04_正文/小说/`；短剧剧本、视频提示词、图片资产提示词和站位线稿图统一归入 `作品/作品名/04_正文/短剧/` 下的对应子目录；跨媒介索引、更新日志和待确认事项仍归 `09_索引/` 管理。

小说正文分卷需要进入专门的小说文件夹，标准位置是 `作品/作品名/04_正文/小说/第001卷-卷名/`；不得把小说分卷目录直接挂在 `04_正文/` 根下。短剧剧本也需要专门文件夹，但该文件夹应位于具体作品内部，标准位置是 `作品/作品名/04_正文/短剧/短剧剧本/`。只有跨作品模板、理论和通用 skill 才留在 `skill/神思/`，不得把不同作品的正式剧本混放到作品外公共剧本目录。
正文源文件粒度硬规则：小说正式正文必须按章落盘，一章一个 Markdown 文档，标准位置为 `作品/作品名/04_正文/小说/第001卷-卷名/第001章-章名.md`。短剧正式剧本必须按集落盘，一集一个 Markdown 文档，标准位置为 `作品/作品名/04_正文/短剧/短剧剧本/第001集-集名.md`。多章 / 多集汇总文件只能作为索引、总控、大纲或临时编译视图，不得作为长期正文源；后续返修、自检、上下文抽取、分镜和资产拆分均以单章 / 单集文档为准。

明确启用 webnovel-writer 兼容适配层时，正文仍以 `04_正文/小说/` 下单章文件为唯一 Obsidian 查阅源。`.webnovel/`、`.story-system/`、`10_其他/webnovel-writer运行记录/` 只保存运行记录、审查 artifact、commit 和恢复信息，不得成为第二正文源。未启用时不创建或要求这些 artifact；启用后的同步闸门按 [[神思-webnovel同步适配规则]] 执行。

预计外文档归位规则：结构化作品根目录只允许承载目录和少量入口约定，不得把运行中临时产生的 Markdown 自动放在作品文件夹最外层。新增文档必须先按职责归位；例如 `当前正式可用章节.md`、`当前分卷结构.md` 这类创作者查阅型辅助视图，应放入 `10_其他/`，不得放在作品根目录，也不得污染 `01_剧情控制/`、`03_状态快照/` 或 `09_索引/` 的固定职责。

`10_其他/` 只保存创作者查阅、辅助汇总和非 canon 索引视图。该目录内容不得作为正史、状态快照、正文源、章/集后台增量、编译报告或资料库来源；如果某文件开始承担正式职责，必须迁入对应标准目录。

## 编译报告聚合规则

`07_编译报告/` 不按检查项目无限细分目录。默认只维护：

- `小说自检.md`：承接小说正文自检、连续性检查、商业追读评分、禁用词、信息权限、人物一致性、伏笔风险等小说相关报告。
- `剧本自检.md`：承接短剧剧本、剧集大纲、漫剧前置剧本、AI 仿真人剧本等剧本相关报告。

单项自检只写入聚合报告中的单项条目；部分章节或部分集数只显示当前已检测对象；后续新增单项、多项、更多章节或全量检查时，在原报告基础上追加或更新。正文或剧本有新改动后再次自检，覆盖同一对象旧结论，保留最新有效报告。不得新建 `连续性检查/`、`短剧逐集自检/`、`商业追读评分/`、`自动审稿/`、`伏笔风险报告/` 等无限细分报告目录。

## 链接消歧

具体作品内同名结构文档必须按 [[神思-结构文档链接规则]] 使用完整路径 + 显示别名。尤其是 `伏笔总表`、`信息释放表`、`读者当前知识库`、`待确认事项`、`更新日志`、`世界观`、`术语表` 等通用名。

## 结构化闭环分档

| 档位 | 适用场景 | 必做 | 可豁免 |
|---|---|---|---|
| 轻量诊断 | 框架审查、章节质量诊断、命名讨论、结构风险判断、临时创作讨论、用户只要求建议不落盘。 | 说明判断依据、列出风险和建议；涉及作品事实时标明是否需要确认。 | 不强制更新后台连续性增量、人物状态、伏笔管理、信息释放表、读者当前知识库、章节目标队列和更新日志。 |
| 正式生产 | 正式正文、正式章纲、正式设定、正式剧本、正式提示词、准备后续承接的改稿。 | 读取必要上下文，执行对应自检，产出可承接的结构化更新包。 | 用户未授权入库或作品未建档时，可暂不写入正式目录，但必须保留待回写清单。 |
| 入库维护 | 用户明确要求建档、入库、同步、回写、编译报告、批量连续生产、长篇正式连载维护。 | 执行完整路径别名、canon 状态、章/集后台连续性增量、人物状态、伏笔、信息释放、重要信息登场、读者知识、待确认事项和更新日志。 | 不可豁免全量回写；缺文件时先补建或输出迁移包。 |

轻量豁免不等于跳过安全判断。只要涉及具体作品事实，仍需标明 canon 状态；只要发现会影响后续承接的变化，必须输出待回写清单。

## 每章结构化闭环

正式长篇每章默认执行：

```text
创作意图状态
-> 记忆核编译动态创作胶囊
-> 创作核候选竞争与正文生产
-> 创作核效果复核
-> 记忆核硬冲突检查与记忆增量
-> 必要时定向返修
-> 按授权回写章/集后台连续性增量、状态、伏笔、信息与待确认
```

动态创作胶囊只包含本轮最小充分上下文：当前阶段目标、最近必要章末记忆、相关人物欲望与状态、关系位置、相关伏笔、必须遵守的 canon、本章目标与禁区、读者信息状态、未兑现承诺、情绪债和相关创作意图。无关资料不得扫描式注入。

多章连续生产时，每章先完成记忆增量，再编译下一章胶囊；普通章节不等待用户逐章确认。明确启用 webnovel-writer 时，才在双核链中插入 [[神思-本章创作合同模板]]、外部 commit/projection 和 [[神思-webnovel同步适配规则]]。

正文写后按 [[神思-结构化入库与回写规则]] 处理；需要具体字段时读取 [[正文写后同步流程]] 和 [[章节记忆与状态模板]]。

## 设定与出场节奏

- 已确认设定写入 `02_正史设定/`。
- 人物、势力、关系、地点、物品等运行态写入 `03_状态快照/`。
- 事件和时间线作为正文推进记录，分别按稳定事件 ID 和时间节点分节写入 `02_正史设定/事件.md` 与 `02_正史设定/时间线.md`，不得再为单一事件新建短文件。
- 伏笔正文和当前状态统一写入 `01_剧情控制/伏笔管理/伏笔总表.md`；作品入口直接链接正式伏笔表，不再创建保存重复状态的 `09_索引/伏笔总表.md`。
- 重要信息首次登场、读者状态、局部揭示、正式揭示和解释完成节点写入 `01_剧情控制/重要信息登场账本.md`。

设定拆分、字段和出场记录按 [[设定拆分与入库流程]] 执行。

## 备份策略

备份先按修改粒度裁决，不得把单文档或少量文档更新升级成整包快照。只有目录结构、跨模块职责、主笔路由、canon 闸门、自检闭环、生产流程、命名规则、结构化落盘规则等“会改变一组文件如何共同运行”的改动，才属于整体备份场景。

备份不得作为后续事实源或规则源读取。备份命名必须尽量说明“修改前文本的特点”，而不是只写日期；例如 `银环设定纠偏前`、`短剧多媒介目录收拢前`、`备份策略优化前`。

### 历史版本作用域

创作工具中的历史版本按四级归属，必须保存到发生变化的最低充分层级：

1. 单文档历史：只修改一篇正文、一个章纲、一份设定或一个记忆文档时，只备份该文档。
2. 分类历史：同一分类内有多个文档或目录结构联动变化时，备份该分类。例如小说连续性与剧本连续性分别维护独立历史，正文目录、剧本目录、提示词目录、小说大纲、剧本大纲、正史设定和剧本设定同理。
3. 板块整体历史：同一板块下两个或更多分类同步变化，或分类之间的结构关系发生整体调整时，才备份正文、大纲、设定或记忆板块。单一分类变化不得进入板块整体历史。
4. 作品历史：跨板块同步更新、作品整体结构变化或对话退回影响整个作品状态时，才进入作品历史。

恢复、删除和设为当前必须在原作用域执行。历史版本保持隔离，不得作为神思创作上下文或 canon 来源读取。

## 备份粒度裁决

| 修改粒度 | 是否备份 | 备份对象 | 存放方式 |
|---|---|---|---|
| 错别字、单条链接、标点、局部措辞、不改变判断规则的说明补充 | 可不备份 | 无 | 直接修改，并在必要时记录更新日志。 |
| 单个文档局部微调 | 通常备份 | 只备份该文档修改前全文 | 不单独创建新文件夹；优先放在对应 `_备份_不参与规则扫描/` 根下，或放入近期同主题备份文件夹。 |
| 单个文档大幅改写、重排章节、替换核心段落 | 必须备份 | 只备份该文档修改前全文 | 可单独创建主题文件夹；文件夹名写明改动主题和日期。 |
| 少量文档联动更新，但不改变目录结构和跨模块职责 | 必须备份 | 只备份实际会修改的几个文档 | 可放入一个同主题文件夹；不得备份未改动目录。 |
| 单作品多文件批量修订、正文大段返修、设定批量回写 | 必须备份 | 只备份受影响文件或受影响子目录 | 放入 `作品/作品名/_备份_不参与规则扫描/主题-日期/`。 |
| 单作品目录迁移、结构重排、正文源路径调整 | 必须整体备份受影响结构 | 备份迁移前的相关目录和入口文件 | 放入 `作品/作品名/_备份_不参与规则扫描/主题-日期/`。 |
| 跨作品批量迁移、作品总目录调整、同时影响多个作品的操作 | 必须整体备份受影响范围 | 备份操作前的跨作品范围 | 放入 `作品/_备份_不参与规则扫描/主题-日期/`。 |
| [[神思]] 框架级目录、主路由、跨模块职责或模板体系重排 | 必须整体备份受影响结构 | 备份实际受影响的框架文件、模块、模板或流程 | 放入 `skill/神思/_备份_不参与规则扫描/主题-日期/`。 |

## 备份位置裁决

| 备份对象 | 标准位置 | 说明 |
|---|---|---|
| [[神思]] 单个规则、单个模块、单个 skill 文件 | `skill/神思/_备份_不参与规则扫描/` | 单文件微调可直接放根下；大改才建主题文件夹。 |
| [[神思]] 多文件同主题更新 | `skill/神思/_备份_不参与规则扫描/主题-日期/` | 只放本次会修改的文件，不复制整个神思目录。 |
| [[神思]] 框架级目录或模板体系重排 | `skill/神思/_备份_不参与规则扫描/主题-日期/` | 只在结构或职责整体改变时备份受影响结构。 |
| 单一作品的单文档修改 | `作品/作品名/_备份_不参与规则扫描/` | 单文件微调可不建文件夹；文件名写清修改前特点。 |
| 单一作品的多文件批量修订、整体重写或目录迁移 | `作品/作品名/_备份_不参与规则扫描/主题-日期/` | 单作品备份首选位置。 |
| 跨作品批量迁移、作品总目录调整、同时影响多个作品的操作 | `作品/_备份_不参与规则扫描/主题-日期/` | 作品总目录级备份，只用于跨作品或作品总目录级操作。 |
| 用户明确要求长期保留的替代方案或并行设定 | 按需创建的 `作品/作品名/08_资料库/备选方案/` | 方案工作区，不等同于修改前备份；普通 AI 首轮生成和一次性试作不得自动落入此处。 |
| 已废弃但需保留来源的方案或冲突内容 | `作品/作品名/08_资料库/废弃设定/` 或 `作品/作品名/09_索引/待确认事项.md` | 必须记录来源、废弃原因和处理状态。 |

路径裁决硬规则：单作品操作不得默认放入 `作品/_备份_不参与规则扫描/`；单文档或少量文档操作不得默认复制整个作品、整个 `skill/神思/` 或整个结构。只有结构被改动，才备份结构；只有文本被改动，才备份文本。

版本与方案边界：历史版本只回答“当前文档以前是什么样”，保持隔离且不进入创作上下文；备选方案只回答“另一套仍可能采用的方向是什么”，是用户明确要求后才创建的可见、可编辑工作文档。不得用备选方案代替历史快照，也不得把普通候选稿自动复制为备选方案。

相近版本归并规则：同一主题在短时间内连续局部微调时，优先复用最近同主题备份文件夹或直接追加同主题单文件备份；只有修改幅度扩大到核心段落替换、多文件联动或目录/职责变化时，才新建独立主题文件夹。

## 运行时读取与派生缓存边界

结构化文档只有进入本轮读取计划并实际编译内容才产生运行价值。软件版统一遵循 [[神思-记忆核运行卡]] 的读取契约：硬依赖先预留预算，长文档按标题/段落/稳定 ID 召回，输出读取清单，显式暴露缺失、截取和过期状态。

自动路由、当前绑定文档、用户本轮 `@文档`、附件、段落召回和 Skill 输入要求必须先进入同一个上下文来源注册表。相同稳定文档 ID 与版本、相同规范化路径或完整内容指纹相同的来源只编译一次；读取原因合并显示。用户 `@` 只把文档提升为本轮硬依赖和显式关注，不提高其 canon 权威，也不制造第二份上下文。当前版与历史版、同名不同内容或相同实体的冲突副本不得静默去重，必须标明版本和冲突。

`03_状态快照/当前状态.md` 是覆盖式当前视图；每章、每集的后台连续性增量随对应正文单元保存；动态上下文由运行时每轮重建且不落盘。三者不得互换职责。状态快照和后台增量不得覆盖正文或正式 canon；正文人工修改后必须标记连续性增量过期，直到完成新一轮有正文证据的同步。

正文承接优先读取当前章纲、上一单元正文、必要正史与当前状态。上一单元正文缺失或需要压缩承接时，读取附着于该正文单元的后台连续性增量。动态上下文始终由这些资料临时编译，不得持久化为与正文、正史或状态并列的事实源。

文档、章节、人物和伏笔导航只存在于软件内部目录树、稳定 ID 映射、标题锚点和全文检索中，不落盘为 Markdown，也不进入模型上下文。旧的自动索引、人物索引、章节索引、伏笔索引和文档索引不得留在活动结构，迁移后必须删除；`01_剧情控制/伏笔管理/伏笔总表.md` 是正式剧情控制账本，必须保留，不得误当成导航索引删除。

`07_编译报告/当前编译状态.md` 是面向作者的实时完成度视图，由软件根据当前大纲、分卷、章纲、正文、设定和连续性资料整体重建。它只总结当前推进状态，不保存历次编译流水，不参与 canon 裁决，也不得反向覆盖来源文档。

`07_编译报告/` 中所有当前有效报告统一通过作者驾驶舱的“检查与报告”集合展示。驾驶舱只读取和导航原报告，不复制报告内容、不改变报告落盘路径，也不把已被新版结论覆盖的旧报告重新暴露到活动视图。

`09_索引/项目规则.md` 保存只对当前作品生效的创作约束，至少包含“项目禁用词”和“特别注意事项”两个分节。确定性禁用词检查只读取“项目禁用词”分节；整份项目规则可以进入本项目创作上下文，但不得跨作品继承。

## 最终边界

创作核可以发明、安排和呈现。记忆核可以编译、检查和提取。自检文档可以诊断。管理流程只能入库已确认事实。顾问只能提供参考。[[创作引导]] 负责让作者的方向、边界、验收和取舍持续生效；作者拥有最终 canon 与审美裁决权。
