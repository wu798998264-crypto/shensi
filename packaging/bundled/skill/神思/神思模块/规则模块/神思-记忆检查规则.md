# 神思-记忆检查规则

状态：正式生效，记忆与连续性能力。

## 定位

记忆检查是 Skill 面板中的可调用能力，不是所有任务的固定前置门禁。Agent 仅在本轮需要承接作品事实、人物状态、时间线、关系、伏笔、信息权限或长期创作意图时调用；普通问答和无关任务不因记忆文档存在而被迫读取。

## 两类记忆

| 类型 | 内容 | 事实地位 |
|---|---|---|
| 作品记忆 | 已采用正文、已确认设定、人物状态、事件、时间线、关系、伏笔和信息释放。 | 按正文与 canon 来源裁决。 |
| 创作意图 | 用户确认的方向、边界、验收标准、取舍、正例与反例。 | 约束协作和审美，不自动成为故事事实。 |

不得把临时口味写成永久 canon，也不得把模型推断冒充已确认事实。

## 读取原则

Agent 根据具体任务动态选择最小充分资料，不设置固定必读列表。通常优先考虑用户本轮明确引用、直接承接的正文、相关人物当前状态、必须遵守的 canon，以及与本轮直接相关的伏笔和信息权限；是否实际读取由当下语义决定。

- 文档只有真实读取到非空内容后才显示在任务卡“已读取”中。
- 空文档、预计读取但最终未读的资料、过期派生内容不显示为已读取，也不构成默认阻断。
- 用户明确点名的文档或实体必须按真实目标读取；聚合文档可按标题或稳定 ID 聚焦。
- 需要跨职责事实时可以临时拼装本轮上下文，但不落盘为第二事实源。
- 当前正文高于派生快照和摘要；正文被人工修改后，旧派生结论不得反向覆盖正文。

## 连续性检查

按任务需要检查：

- 是否违反已确认 canon。
- 人物是否使用不可能知道的信息。
- 时间、地点、年龄、伤势、物品、资源和行动路径是否冲突。
- 行动是否缺少必要前因，结果是否忽略已发生代价。
- 是否提前揭示受限信息。
- 关系和情绪变化是否缺少足以支撑的过程。
- 本轮结果是否破坏仍需兑现的承诺。

发现问题时提供位置、事实来源、冲突类型、必须保留项和最小修正范围。记忆检查不直接替代正文写作 Skill，也不因软风险机械否决成立的创作突破。

## 写回

正式正文采用后，Agent 可按实际变化更新章节连续性摘要、当前状态、关系、伏笔、信息释放和待确认事项。写回遵循 [[神思-结构化管理规则]] 与 [[神思运行规范]]：先保存完整历史，使用真实文档事务，写后回读验证。

只记录正文中明示或有充分证据成立的事实。可能改变核心设定、终局或重大关系但尚未确认的推断进入待确认，不覆盖正式 canon。连续多章或多集任务在每个单元完成后按需更新记忆，再承接下一单元；普通状态变化不要求用户逐项确认。
