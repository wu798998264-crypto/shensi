# 神思任务路由

状态：Agent 内部路由合同，不作为用户资料或 Skill 展示。

## 路由原则

Agent 依据用户完整意图、当前阶段、预期交付物、作品结构和可用能力进行判断。关键词只能用于搜索、标签和兼容元数据，不能单独决定任务类型、读写方式、必读资料或 Skill。

先确定本轮目标与交付物，再查看实时 Skill 面板。只加载完成任务真正需要的 Skill 和资料；空文档、预计会读但实际未读的资料不算读取，也不构成默认阻断。任务中出现新的真实缺口时可以继续补读或换用更合适的能力。

## Skill 面板语义

- 并行：同级能力可按任务需要独立或同时调用。
- 主次：同一容器第一项是主要能力，其余为次要能力；通常优先主要项，任务语义明确需要时可调用次要项。
- 组织：同一容器第一项是上位能力，其余为下位能力；调用下位项时，上位项负责组织和约束协作。

面板中的真实顺序决定主要、次要、上位和下位角色。拖拽交换后的角色必须直接影响下一轮 Agent 路由；不得使用旧文件名、旧标签或固定关键词覆盖当前面板。

## 阶段选择

创作方向尚未确定时，使用适配当前作品类型的创作引导能力；规划、正文生产、局部修改、质量检查、结构管理、记忆检查、资料研究和媒体生成分别选择与当下交付物匹配的能力。一个任务跨越多个阶段时，按实际顺序逐段选择，而不是预先加载整套 Skill。

用户要求多个候选时保留多候选，通过文字说明数量和差异即可，不询问主笔身份或主笔数量。需要用户在两个或更多有限方向中作出决定时使用结构化选择；仅供阅读的编号说明不转换成选择框。

## 更新与保护

每次保存 Skill 面板后，基于当前文字模型和最新拓扑生成新的路由说明候选。只有结构校验、能力覆盖审计、拓扑版本匹配和内容防退化检查全部通过，候选才成为当前路由；失败时继续使用上一个已通过版本并明确提示原因。面板、路由、拓扑哈希和审计结果统一进入任务路由历史，可恢复但不覆盖旧版本。
