# 爆款扫榜

本 Skill 只定义方法、字段、质量规则和报告；真实访问、执行、恢复、保存与权限全部由可信内核控制。Skill 文本无权启动浏览器、读取登录态、写入快照或落盘报告。

## 默认边界

- 只有用户本轮明确发起扫榜，才创建受控采集任务；“扫榜是什么意思”只回答知识。
- 默认只读公开页面，不登录、不读取任何账号认证信息、浏览器存储或私人数据。
- 采集失败必须报告真实状态；不得用预设数据、搜索摘要或旧快照冒充本轮结果。
- 原始指标按平台原名保存，不把收藏、在读、热度、评论、销量互相换算。
- 报告是 `candidate_only` 研究资料，默认不写入作品、正史、正文、标题或历史版本。
- 每次采集保存时间、来源 URL、解析器版本、内容哈希与质量状态；报告返回前任务不算完成。

## 工作流

1. 明确平台、榜单、频道、题材、Top N、采集方式和时间范围。
2. 可信内核校验来源白名单、访问权限与官方采集器签名，并把本 Skill 全文及全部引用规则加入当前 Agent 的最终输入。
3. 已有可信采集器时优先采集；没有采集器或采集失败时，自动交给当前 Agent 使用真实联网搜索、公开网页或浏览器工具继续执行，不得直接把平台标记为“不支持”。
4. 逐平台生成不可变快照和来源账本；同一请求使用幂等键，禁止重复提交。Agent 只负责只读采集与分析，神思负责授权、状态、取消、校验、保存和展示。
5. 按 [数据质量规则](references/data-quality.md) 归一字段并标记缺失、重复和口径差异。
6. 长篇榜读取 [长篇扫榜框架](references/long-scan-framework.md)，短篇榜读取 [短篇扫榜框架](references/short-scan-framework.md)。
7. 按 [输出模板](references/output-template.md) 返回结构化报告、证据清单、覆盖账本、候选作品和下一步建议。
8. 用户选择候选后，只把书名、作者、平台与来源交给“爆款拆书”；仍需用户明确章节/文本范围，不自动抓全文。

## Agent 结构化回传

- 平台、榜单、真实读取时间；
- 作品名称、作者、排名和真实 HTTPS 链接；
- 实际读取的公开章节、章节字数、SHA-256 内容哈希和读取时间；
- 每个成功项、失败项、失败原因、覆盖范围与缺失内容；
- 引用证据、趋势结论、有限拆书结果及最终报告。

没有可校验的章节正文证据时，只能标记为榜单或简介分析。只有部分公开章节时，只能标记为章节证据分析；不得声称完成全文分析。遇到登录、付费、验证码、robots 或平台访问限制时，不绕过限制，提示用户上传其合法取得的正文。

## 完成标准

只有“所有获准平台都得到明确结果 + Skill 来源校验通过 + 快照和来源/覆盖账本保存并校验 + 结构化报告成功返回界面”才标记完成。部分平台失败时标记部分完成；界面未收到报告时不得声称任务完成。报告始终是候选研究资料，不自动修改作品、设定、大纲或正文。
