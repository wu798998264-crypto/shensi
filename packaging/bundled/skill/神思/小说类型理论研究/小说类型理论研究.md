# 小说类型理论研究

显示名称：小说类型识别与理论路由

## 定位

[[小说类型理论研究]] 是类型研究顾问的能力索引，不是具体类型理论本体，也不是 Agent 的前置门禁。

它帮助 Agent 根据完整任务意图、作品语境、目标平台和当前问题找到合适的具体理论。表中的题材表达只用于说明语义范围和资料搜索，单个词不得直接触发读取、决定任务类型或阻断执行；Agent 已从实时 Skill 面板确定明确能力时，可以直接读取对应 Skill。

## 总原则

1. 是否启用题材顾问由 Agent 结合完整意图、当前阶段和交付物判断，不设置强制前置识别，也不按任务长短机械排除。
2. 类型研究顾问只解释类型规律、读者期待和结构依据，不担任正文主笔、大纲主笔、设定主笔或最终自检裁决者。
3. 类型理论不得覆盖 canon，不得把理论建议直接写入正史设定或剧情控制。
4. 当前任务只需要上位理论时读取上位理论；需要细分机制时再补读对应细分理论。没有合适理论时不强行套用。女频任务的上位类型是女频通用理论，不是女频爽文理论。
5. 一个任务可以同时具有多种类型特征，Agent 依据核心承诺、主要冲突和预期读者体验判断主次；无法可靠判断时保持开放，不强行套用已有男频爽文理论。
6. 细分母题确实影响本轮交付物时，可按需组合细分、上位与通用理论。例如作品的核心机制确属真假千金身份错位与家庭亏欠时，可组合读取 [[真假千金剧情创作概论]]、[[女频小说通用理论]] 与网文通用理论；不因文本偶然出现“豪门”或“认亲”等单词自动加载。
7. 没有独立实际 Skill 的女频类型只读取 [[女频小说通用理论]]，不得为了填满下位插槽而套用女频爽文。只有任务明确出现“女频爽文、先虐后爽、虐转爽、后期转爽”等爽文或转爽意图时，才读取 [[女频爽文创作概论]]。
8. 任务明确同时要求商业长篇追读、主角持续成长与传统科幻深度时，优先读取 [[skill/神思/小说类型理论研究/hybrid-science-fiction/SKILL|融合型科幻创作理论 skill]]；由该 skill 再按需追加网文科幻或传统科幻来源，不得默认同时加载三份完整理论。
9. 交付物是以压缩思想实验为核心的短篇科幻时，优先读取 [[skill/神思/小说类型理论研究/short-science-fiction/SKILL|短篇科幻创作理论 skill]]；不得只因出现科技术语就套用，也不得直接套用长篇传统科幻或网文科幻框架。

## 待扩展板块

后续可按同一格式接入其他细分类型，例如女频复仇、追妻火葬场、无限流、规则怪谈、悬疑破案、民俗诡案、玄幻升级、都市异能、末世、高武、权谋、群像史诗等。

新增板块必须满足：

1. 有独立理论文档。
2. 有清晰的语义适用范围和可检索题材表达，但不把表达列表作为自动触发器。
3. 有适用范围和禁止套用范围。
4. 在实时 Skill 面板登记并通过验证后才可由 Agent 调用。

## 调用流程

1. Agent 先依据用户完整意图、当前作品语境、阶段和交付物判断是否需要类型理论。
2. 查看实时 Skill 面板与本索引；只读取真正支持本轮判断或创作的具体理论，不设置必经索引门禁。
3. 多种理论都可能相关时，依据核心承诺和问题主次按需组合，并说明各自承担的作用。
4. 类型理论只提供原因解释、类型风险和修改依据，不替代正文生产或最终自检能力。
5. 最终修改由当前任务实际选用的生产或自检 Skill 完成；未发现适配理论不阻断任务。

## 上位类型回退

- 玄幻、仙侠、修仙、都市异能、悬疑推理、末世、高武、无限流、规则怪谈、系统流和升级流等尚无独立细分理论时，仅在其商业长篇机制确实适配时参考 [[男频网文创作逻辑研究]] 与网文通用理论。
- 古言、现言、宫斗、宅斗、甜宠、女性成长等没有下位专精时，可参考 [[女频小说通用理论]] 与网文通用理论，不默认进入爽文。
- 女频虐文、纯虐文、虐恋、虐心、BE 结局和追妻火葬场目前可参考 [[女频小说通用理论]]；待存在经过验证的独立理论 Skill 后再增加下位插槽。只有作品明确采用先虐后爽、虐转爽或后期转爽的核心承诺时，才使用 [[女频爽文创作概论]]。
- 已有细分理论时仍组合对应上位理论，不再采用“细分覆盖后完全让上位退出”的方式。
- 完整语义无法可靠归入任何已接入上位类型时停止理论召回，不为了填满流程强行套用男频或女频理论。

## 未命中处理

如果任务没有明确属于已接入类型：

- 不得在没有男频题材证据时默认读取 [[男频网文创作逻辑研究]]。
- 不得把民俗诡案、悬疑、女频、短剧、权谋、现实题材等强行套入男频爽文标准。
- 可以说明“当前没有对应类型理论板块”，并仅按通用正文、大纲、自检和信息权限规则处理。
- 如果用户要求新增该类型理论，应先建立对应理论文档与 Skill，再登记到实时面板。
