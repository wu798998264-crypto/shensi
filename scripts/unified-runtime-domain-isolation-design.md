# 神思统一源码与文档/白板物理隔离设计

## 唯一基线

- 唯一集成分支：`codex/v606-reliability-integration`。
- 本地基线标签：`baseline-unified-v606-before-domain-isolation`，指向 `28458ae`。
- `shensi-source` 的未提交修改只做逐项审计；确认被基线覆盖的内容不重复迁移，独有且符合最新需求的内容以独立提交迁入。
- 不修改、迁移或覆盖用户现有供应商配置、端点、模型、凭证、作品和历史版本。

## 领域边界

文档 Agent 与白板媒体是两个独立执行域。文档域只负责对话、选择、资料读取、Skill 路由、文档事务、历史版本、跳转回执和局部修改。白板域只负责卡片、图片/视频/音频任务、供应商提交、轮询、下载、回填、即梦凭证锁和待确认任务。

两个领域只能共享只读配置快照、统一错误信封、任务身份和通用持久化原语。文档代码不得判断或改变即梦锁；白板代码不得推断文档落盘、选择框或正式内容。前端从 `app.js` 抽离两个控制器，服务端从 `server.mjs` 抽离两个 API 路由器，并增加领域导入检查和变更范围检查。

## 白板黄金基线

即梦锁只在生成准备、提交、有限连接重试、生成、下载、验收和卡片成功回写链路中占用。明确失败、用户终止、有限核对到期、回填明确失败均释放逻辑锁。彻底终止永久抑制迟到结果，并保留进程和物理凭证槽诊断。

任何即梦或 LibTV 失败都必须保存并展示配置身份、神思任务号、厂商任务号、供应商错误码、真实原始错误、归因和可执行处理建议。只有明确的账号认证错误才允许要求核验账号。待确认页面只显示真实阻塞且未完成的任务，提供一个核验入口和一键彻底终止。

黄金回归包括状态表、进程终止、重启恢复、错误管道、Electron 卡片交互、聚合 API/即梦跨配置串行生图保护，以及用户授权的一张图片和一个最短视频真实验收。黄金基线封存后，文档阶段不得修改白板领域文件。

## 文档域

任意指令发送后先持久化用户消息和任务卡，再启动 Agent；选择答案等同新的用户指令并继续原任务。撤回同步取消运行和选择框，选择长期有效。任务卡只保留一份“已读取”，置于卡内最底部，展示前三项并可展开全部；空文档、预计读取、任务路由和运行规范不显示。卡片下方只保留 Agent 正在处理状态。

Agent 判断为正式成果且用户没有明确禁止落盘时直接写入；讨论不自动落盘，用户明确要求时仍可写入。所有覆盖、续写、追加、局部替换、重命名和删除前继续使用既有完整历史保护。局部修改必须显示前后差异，确认后才替换并回读验证。写入链接只能由真实写入回执生成，标题与目标文档一致且可点击跳转。

## 路由、旧代码和界面

内部规则收束为“神思任务路由”和“神思运行规范”两个短文档，均不显示在 Skill 面板或任务卡读取证据中。保存 Skill 面板后，使用当前文字模型提出路由更新候选；候选必须经过结构校验、能力覆盖审计、历史保存和失败回退后才能激活，不能无限自改。

关键词可以作为搜索、标签和兼容导入元数据保存，但不得拥有任务类型、写入方式、资料必读或 Skill 路由裁决权。最后删除被新语义 Agent 路径覆盖的旧执行代码，再单独完成 Skill 广场文字、能力分类“其他”和英语界面全量检查。

## 发布门禁

每项需求分别记录代码提交、定向测试、真实 Electron 操作和安装包构建身份。任一真实界面测试因能力包缺失而未运行时，不得表述为完整通过。发布包必须同时显示版本号、Git 提交和构建时间；只从唯一集成分支生成，不上传远端，除非用户再次明确要求。
